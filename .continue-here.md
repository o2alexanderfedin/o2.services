## Three loose threads, each its own session

1. **The funnel silently drops reports on a plain relay.** *"The relay is the collector"* is
   true of the deployed Cloudflare Worker and **false of any self-hosted seed**, which serves
   libp2p WebSocket on that port and answers **400**. Immediate, so nothing hangs — but the
   funnel looks configured and collects nothing. The fix that fits the existing scope fence is
   **probe before targeting**: derive the origin as now, install the send port only once
   `/funnel` has answered, which fails closed to exactly the old inert behaviour.
2. **`packages/node/src/funnel-attribution.e2e.test.ts:135` leaks processes.** `newArm()`
   spawns `npx wrangler dev` and stops it with `worker.kill('SIGTERM')`, which signals only the
   `npm exec` process — the `wrangler dev → cli.js → workerd` chain survives and holds its port.
3. **A second concurrency hazard survives the Vite-cache fix.** With two e2e lanes running,
   `demo-pi` fails 5/10 with **zero** `504`s, on the mDNS candidate class already documented in
   `packages/node/src/e2e-browser-launch.ts`. It was previously masked because the
   optimiser-race loser died before it ever dialled.
