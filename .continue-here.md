## THE THING THAT DECIDES WHETHER TURN HELPS ANYONE — an owner decision, not a task

**The TURN gate admits a caller by certificate. A visitor to the published page holds none.**
Every step of this was measured on 2026-09-09 against the live deployment and the live page, not
reasoned from the code:

- `https://o2alexanderfedin.github.io/o2.services/bootstrap.json` carries `relayAddrs`,
  `seedPeerId`, `peerAddrs` — and **no `enrollmentProvider`**.
- So `enrolmentOffer()` reports nothing offered, no visitor enrols, `resolveCertificate` answers
  `null`, and the tab posts `certificate: null`.
- Posting exactly that body to the live route answers **`400 malformed-request`**.
- `O2_TRUSTED_ISSUERS` is set nowhere either — not a secret (`wrangler secret list` returns only
  `O2_ADMISSION_KEY` and `O2_IDENTITY_SECRET`) and not a var (`wrangler.jsonc` declares only
  `ANNOUNCE_MULTIADDRS`). The pinned set is empty, which refuses every certificate anyway.
- The two are one problem: **the hosted Cloudflare object issues no certificates.**
  `hosted-libp2p.ts` constructs no `EnrollmentAuthority` — that lives in `packages/net/src/agent.ts`
  on the Node tier — so there is no provider for a production visitor to enrol with, and no issuer
  key that pinning could name.

**Stated at full size, because it is a tension between two requirements rather than a defect.**
`NET-12` criterion 1 asks that *a request from outside the fabric is refused*. On the published
page **every visitor is outside the fabric by that definition**. TURN as specified serves enrolled
nodes; Phase 39's cohort is unenrolled. Who the rung is for is the owner's call — an agent must
not close it by loosening a gate that exists on purpose.

Until it is settled, the office guest-wi-fi pair that started all this still has no data path.

## What landed on this branch

- **The credential model, confirmed and then contradicted.** Cloudflare answered `201` with an
  `iceServers` **array** whose credentialed entry carries a 64-character opaque `username` with
  no `expiry:` prefix — not RFC 5766. There is no shared secret to HMAC over. The API credential
  under the old `O2_TURN_SECRET` name would have minted a well-formed credential every Cloudflare
  TURN server answers `401` to, reaching a tab as a **network fault** and walking straight past
  the `turn-not-configured` refusal written to stop exactly that.
  `cloudflareTurnMinter` therefore **asks** rather than mints.
- **The shipped adapter was then run once against the live endpoint** — a different claim from the
  probe. It answered `ok`: five URLs, `turns:…:443` among them, and the credential-less STUN entry
  correctly skipped on a real response rather than only on a fixture. No test lane repeats that
  call.
- **A configuration trap, closed.** `turnUrlsFor` collapsed *declared with no URLs* into
  *undeclared*, so a deployment holding only the API key pair would have refused **every** mint as
  `unknown-region`. The plant reproduced the exact text: *"bootstrap-us" is not a region this
  deployment declares*.
- **Nobody had ever asked for a credential.** The rung was reachable only through `?turn=`, which
  is not in the circulated link. `demo/main.ts` now derives the endpoint from the relay the tab
  already dials, as the kill switch's is. That is the fourth `wired is not used` this repository
  has caught.
- **A node-lane spec that dialled Cloudflare on every run**, caught in review the same day. It was
  outcome-stable — a real `401` and an offline refusal both map to `provider-refused` — so it
  would never have reddened. Measured before and after: **348 ms → 3 ms**.
- **Secrets renamed to make the collision impossible**: `.secrets/O2_TURN_API_SECRET` (was
  `O2_TURN_SECRET`), both copies round-tripped, keychain moved under the new account name.

Verified: typecheck clean, node lane **260/260 files, 3752 tests**, four plants watched red and
restored by surgical inverse with `cmp` clean. **The e2e lane was still running when this was
written — check it before merging.**
