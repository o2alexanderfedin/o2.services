## Start here: TURN, and a model mismatch I found and did NOT fix

The owner created the Cloudflare TURN app **`round-band-959b`** on 2026-09-09. Credentials are
banked in `.secrets/` (0600, gitignored) and in the macOS login keychain under
`o2.services/cloudflare/o2-bootstrap`:

| item | file |
|---|---|
| Turn key id (not secret) | `.secrets/O2_TURN_KEY_ID` |
| API credential (secret) | `.secrets/O2_TURN_SECRET` |

**The minter is built for the wrong credential model, and this is measured rather than
suspected.**

- **This tree** (`packages/cloudflare/src/turn-credential.ts:193-200`) mints RFC 5766 long-term
  credentials: `HMAC-SHA-1` over the username with a **shared secret the TURN server also
  holds**.
- **Cloudflare does not work that way.** Their instructions are to call
  `https://rtc.live.cloudflare.com/v1/turn/keys/<key id>/credentials/generate-ice-servers` with
  `Authorization: Bearer <the API credential>` and receive ready `username` / `credential` / `urls`.

Putting their credential into `O2_TURN_SECRET` as an HMAC key **will not work**: their TURN server
verifies its own credentials, not ours. The failure would be a `401` that reads like a network
fault — exactly what `.planning/OWNER-ACTIONS.md` row 3 warns about.

**FIRST ACTION ON RESUME — verify the claim above before building on it.** One live call:

```
curl -s -H "Authorization: Bearer $(cat .secrets/O2_TURN_SECRET)" \
  -H "Content-Type: application/json" -d '{"ttl": 3600}' \
  "https://rtc.live.cloudflare.com/v1/turn/keys/$(cat .secrets/O2_TURN_KEY_ID)/credentials/generate-ice-servers"
```

If that returns `iceServers`, the model is confirmed and the work is: keep the certificate gate,
the region sharding and the short lifetime exactly as they are, and **replace the minting step
with a call to their API**, the worker holding the credential. `mintTurnCredential`'s callers, its
refusal vocabulary and `turn-regions.ts` should all survive.

**The API credential was pasted into the session transcript.** After TURN works end to end, delete the
`round-band-959b` app in the dashboard, create a fresh one, and write the new value straight into
`.secrets/O2_TURN_SECRET` without sending it through a chat.

## Why TURN is now the thing that decides the run

Observed in the field on 2026-09-09: the owner ran Colouring on a laptop with a phone listening,
**both on the same office guest wi-fi**, and nothing executed on the phone.

That is correct behaviour, not a defect — `demo/main.ts` states it: *"A control-only pair is not
a peer this visitor can compute with"*, because the only path was a relayed circuit budgeted at
64 KiB each way. **Why the pair had no direct path is the finding.** STUN is configured (three
servers, `packages/browser/src/ice-configuration.ts`), so this is not the missing-STUN case:

- a guest network isolates its clients, so both peers' **host** candidates are unusable;
- both sit behind one NAT with the **same** reflexive address, so the STUN candidates would need
  hairpinning the access point does not do.

No candidate pair can work. Only a relay outside that network can. The live funnel agrees on the
whole population: **`direct: 15` against `control-only: 7` — 32 % of sessions get no data path.**
Guest wi-fi is offices, cafés, hotels and universities; it is not an edge case for this cohort.

Recorded in `39-GO-NO-GO.md`'s Phase 34 row at `72f2224`.

## What landed this session

- **The kill switch exists.** The deployed object had `region: null` **and** no operator key
  since its first deploy, on a node that had already relayed 143 connections for real people.
  Both secrets set, `GET /self` carries `killSwitch: { operable, reason }`, and the switch was
  thrown and thrown back against production — halt 200, unhalt 200, wrong region 409, wrong key
  401. `deploy-hosted.sh` now derives the region from `SERVED_BY`, requires both secrets before
  spending a request, and reads the verdict back.
- **A returning visitor is told WHAT changed.** `CONSENT_VERSION_NOTE` had existed since
  disclosure version 3 and nothing rendered it.
- **A nostr bootstrap fallback**, read only when the origin has none and no `?relay=` was given.

## Standing constraints that cost something to relearn

- **`.secrets/` holds four values** — admission key, identity secret, nostr key, TURN pair. It is
  gitignored, and it was ignored **before** anything was written into it, which is the only safe
  order.
- Commit with explicit paths (`git commit -m "…" -- <path>`); branches need a git-flow prefix
  (`feature|release|hotfix|bugfix|support|fix|chore|docs|test`) — `research/` is refused.
- Read `EXIT=$?` on the line **immediately** after the command, never after a pipe. This session
  broke that rule once and reported `tail`'s status as a push's.
- Run vitest by project; read the `[host conditions]` banner before quoting any duration.
- Attribute a failure by measurement. A control lane with the nostr publisher pinned to
  `NOT_PUBLISHED` is what settled which spec my change had broken.
