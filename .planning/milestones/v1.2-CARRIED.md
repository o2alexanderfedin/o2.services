# What v1.1 did not close, and what it would take to close it

**Written 2026-08-24, when v1.1 shipped at 15/15 phases and 50/50 milestone requirements.**

`v1.1-SHIPPED.md` says of its carried criteria that *"the originals stay live until a v1.2
roadmap replaces them"*. There is no v1.2 roadmap, and until this file there was no register
naming what would go into one: **none of the four items below appeared in `OPEN-ITEMS.md`,
in `DEFICIENCIES.md`, or in any milestone document.** They were visible only by reading 95
rows of `REQUIREMENTS.md` and noticing which four did not say `Done`.

**This file does not declare a milestone.** Scope is the owner's call and `/gsd-new-milestone`
is where it is taken. What this does is make sure nothing has to be rediscovered when it is.

**The reliable test is the word the status cell BEGINS with**, not a substring search. A row
that begins `Done` is done however much history follows it.

## The four, grouped by what actually blocks them

### Group A — needs an address or a machine this host does not have (3)

These three share one shape: the mechanism is built and, in two cases, measured. What is
missing is a *place to run it*.

| Id | Phase | Built and measured | What is missing |
|---|---|---|---|
| **NET-03** | 3 — Browser Tier & Backbone Relay | AutoTLS orders, receives, installs and re-uses a certificate with none configured, and a TLS handshake validates the chain — measured 2026-08-17 against `local-acme.ts`, a loopback RFC 8555 authority with a real UDP DNS zone | A **public** authority and a **publicly reachable** interface. This host has none that is not RFC 1918 or a ULA, so the dialable address is declared through `appendAnnounce` rather than bound |
| **BENCH-06** | 8 — Benchmark Harness | The same-machine half became falsifiable 2026-08-14: each spawned agent announces its own host on the handshake and `announcedMachine` is read off that line, never off the parent | A benchmark run across **distinct machines** |
| **AOT-03** | 10 — elfconv AOT Native→WASM | Repeated lifts in separate spawned toolchain processes are byte-identical on one host | The same comparison across **two hosts**. `CROSS_MACHINE_BLIND_SPOT` stays on every artifact until then |

**"Descoped" is not "unobtainable", and the distinction matters for two of these three.**
`BENCH-06` and `AOT-03` were descoped on 2026-07-28 and have carried that word ever since,
which reads like a hardware wall. It is not one: this project has already produced a
cross-machine result — NET-01 closed with **an iPhone running Safari and a laptop running
Chromium, on genuinely different machines**, over direct WebRTC. So the second machine exists
and has been used. What these two are waiting on is somebody running them, not a machine
nobody has.

`NET-03` is the one with a genuine external dependency, and even there the blocker was
misstated for weeks: the note *"AutoTLS needs a publicly reachable host"* was a fact about
**Let's Encrypt** restated as a fact about the mechanism. The mechanism is proven. What is
unpaid is a hosting decision — and this project's own constraint makes that decision
non-trivial rather than merely unmade: **public hosting is public disclosure**, and the EPO
and China have no patent grace period.

### Group B — needs a build nobody has paid (1)

| Id | Phase | State | What is missing |
|---|---|---|---|
| **AOTW-06** | 26 — elfconv Compiled to Wasm | **Measured negative.** `26-GATE.md` returned **NO-GO**: 21 of 27 non-test translation units do not compile for `wasm32-wasi` | A `wasm32-wasi` LLVM built from source, and a `__wasi__` branch in glog |

Two facts make this the only one of the four that is pure local engineering, and also the
largest:

- **glog has no `__wasi__` branch at all.** It branches on Windows, Cygwin, Linux, Android,
  macOS, the BSDs and Emscripten. The `wasm32-wasi-threads` arm only moves the refusal from
  `glog/logging.h:51` to `glog/platform.h:58` — it removes nothing.
- **Precondition 3 of `26-CONTEXT.md`**: the only cross-compiled LLVM on this host targets
  Emscripten and cannot be guest code under this project's preview1 sandbox. So the LLVM
  build comes *before* the deliverable is reachable at all.

The symbol half of that gate is separately **an upper bound, conclusive in neither
direction** — `wasm-ld` pulls only the members it needs, and the process and signal residue
lives in six LLVMSupport objects (`Program`, `Signals`, `CrashRecoveryContext`, `Process`,
`LockFileManager`, `Watchdog`). A future pass must not read it as a verdict.

## What a v1.2 would have to decide

Three questions, and none is answerable from the tree:

1. **Is the relay hosted publicly?** This is `NET-03`, and it is a disclosure decision before
   it is a hosting one. Deployment is deliberately a separate gate in this project, not an
   automatic consequence of a phase completing.
2. **Is a second machine put in the loop for measurement?** This is `BENCH-06` and `AOT-03`
   together — one arrangement closes both, since both want the same thing: the same run on
   two hosts. They are the cheapest pair here and the only two that close together.
3. **Is the wasm32-wasi LLVM built?** This is `AOTW-06` alone, and it is a multi-day
   toolchain job whose first deliverable is a compiler, not a feature.

**Ordering, if all three are taken:** question 2 first — it is the least expensive, it closes
two ids, and it needs no decision beyond scheduling. Question 3 next, because it is long and
independent of everything else. Question 1 last, because it is irreversible in a way the
other two are not: public hosting forfeits EPO and China patent rights permanently.
