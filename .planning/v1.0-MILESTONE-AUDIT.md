# Milestone v1.0 — Audit

**Status: gaps_found**, and not for the reason the ledger suggested.

The requirement ledger says 68 of 72. The four it marks open are all blocked on
hardware, hosting, or a measured negative — none is unwritten code, and that part of
the ledger is accurate.

**The integration check found something larger.** Of the 68 marked Done, **35 have no
production call path.** Phases 4, 5, 6 and 7 built sovereignty, tree-reduce, discovery,
enrollment, quorum composition, capability chains and the whole churn coordinator —
each one genuinely implemented and genuinely tested — and nothing a person can run
calls any of it. The mechanisms are exported from the barrels and exercised by their
own specs; the five production entry points reach none of them.

This is the project's own recorded anti-pattern at milestone scale: *whenever a comment
states a guarantee, grep for the mechanism*. The mechanisms exist. What is missing is
the wire.

## The four open requirements

| Requirement | Phase | What it needs |
|---|---|---|
| NET-03 — real AutoTLS | 3 | A publicly reachable host |
| BENCH-06 — distinct-machine benchmarks | 8 | A second machine |
| AOT-03 — cross-machine reproducible CID | 10 | **The same second machine** |

BENCH-06 and AOT-03 are one blocker wearing two numbers. One second machine closes
both, and it would also turn Phase 8's "no parallel speedup is measurable" from a
caveat into a measurement.

AOT-05 is a different kind of entry. It is not waiting on anything — the experiment
ran, with two controls, and the answer was no. It is recorded as unsatisfied rather
than reworded into something that could be ticked, because a criterion that can only be
reported as met is not a measurement.

## Gaps in the record, as distinct from gaps in the work

These are the audit's own findings about its evidence base, and they are worth stating
plainly rather than passing over because the code is green.

**Phase 1 has no phase artifacts at all.** No directory, no SUMMARY, no VERIFICATION. It
is checked complete on the strength of a roadmap checkbox, and ten requirements —
DET-05, DET-06, DET-07, VER-01, VER-02, VER-05, VER-06, DATA-01, MR-01, SCHED-04 — are
attributed to it. The work is not in doubt: `packages/core` contains canonical DAG-CBOR
encoding, the blockstore, the Worker executor, `submitJob`, quorum and verification, and
the governor, all with tests, and DET-07's three-target claim is structurally verifiable
in `vitest.config.ts` — the `node` and `browser` projects include the same
`packages/*/src/**/*.test.ts` glob, so the portable specs genuinely run in both. But an
audit that accepts a checkbox as evidence for ten requirements is not auditing.

**Eight of ten phases have no VERIFICATION.md.** Only Phases 9 and 10 have one. The
other eight carry criterion-by-criterion tables inside their SUMMARY.md, which is real
evidence in a non-standard place — so the three-source cross-reference this audit is
supposed to perform runs on two sources for nine phases and one for Phase 1. Recorded as
a shape gap, not as an absence of work.

**Two SUMMARY headers understate their own tables.** Phase 4 says "5 of 6 criteria met"
above a table marking all six met; Phase 8 says "4 of 5" above a table marking all five.
The error is in the conservative direction, which is the harmless one, but the header
and the table should not disagree.

## Cross-phase integration — the finding that dominates this audit

**Phases 4, 5, 6 and 7 are a well-built, well-tested library that no runnable entry
point calls.**

Five production entry points exist: `packages/node/src/bin/agent.ts`, `bin/seed.ts`,
`bin/bench.ts`, `tools/aot/cli.ts`, and `packages/browser/demo/index.html` →
`demo/main.ts`. Everything reachable from those is a real path; everything else is
reachable only from a test.

The job path is genuinely wired — `submitJob` → `executeVerified` → the `Executor`
port → RPC → `serveAgent` — and that covers Phases 1, 2, 3, 9 and the demo half of 10.
The mechanisms built in Phases 4–7 sit beside it, not on it.

**Independently verified before being recorded.** Each of the following appears in the
repository *only* as its own definition, a barrel re-export, or a prose comment — zero
call sites outside `*.test.ts`:

`runResilient` · `EgressGuard` · `translationCid` · `composeQuorum` ·
`discoverExecutors` · `executeReduce` · `deriveReduceTree` · `requestEnrollment` ·
`signName` · `verifyChain` · `DutyCycleGovernor` · `recoverCheckpoint`

### The structural cause

`packages/net/src/agent.ts:65-120` declares six optional hooks on `serveAgent`, each
with a silent-default fallback. Production supplies almost none of them:

| Hook | Default | Effect on a running node |
|---|---|---|
| `authorize` | `undefined` → execute | every dispatched task runs unauthorized |
| `index` | `?? []` | no node ever serves a capability record |
| `capacity` | `undefined` → `accepted: true` | no node can refuse an offer |
| `ledger` | `ledger?.record(...)` | reported outcomes are discarded |
| `reservations` | `?? []` | fabric rendezvous always returns nobody |

`ledger` is supplied nowhere at all — not in production, not in one test.
`fabric-node.ts:327` passes `{ rpc, executor, blockstore }` and nothing else.

### Three specific breaks, each confirmed by reading the line

1. **`RemoteExecutor` never sends a capability chain.** `remote-executor.ts:39` sends
   `{kind:'exec', task}`. The protocol carries the field, the parser validates it, the
   agent forwards it, `verifyChain` exists — and no submitter attaches one while no
   node checks one. **AUTH-03.**
2. **`submitJob` has no placement.** `submit.ts:82-92` is unconditional round-robin
   over `spec.executors`. There is no owner label in `JobSpec` or `Task`. The
   sovereignty gate is reachable only through `runResilient`, which nothing calls — so
   "the placer cannot relocate a sovereign task" is true of a placer no job runs
   through. **DATA-03, DATA-04, DATA-09, SCHED-02, SCHED-05.**
3. **`EgressGuard` wraps no production transport.** Both nodes pass the raw
   `Libp2pTransport` to `RpcEndpoint` (`fabric-node.ts:311`, `browser-node.ts:181`).
   The decorator designed to make the manifest "complete by construction" decorates
   nothing outside a test. **DATA-05, DATA-06.**

### Static-host peer rendezvous is dead, and fails silently

`findReservedPeers` (`rendezvous.ts:70-81`) is documented at `demo/main.ts:386` as *the
only route on a static host*. The responder never answers: `fabric-node.ts:327` supplies
no `reservations` thunk, so the agent replies `peerIds: []`. `FabricNode.reservedPeerIds`
(`fabric-node.ts:419-423`) holds exactly the right data and is never handed over.

The LAN path works only because `SeedServer` reads that property **in-process**
(`seed-server.ts:240-242`), bypassing the protocol.

The failure signature is the one this code was written to prevent: the seed answers, so
`asked` becomes true, and the result is `{asked: true, dialed: [], failed: []}` —
nothing attempted, nothing failed, no error. That is the same signature as the two-device
defect found on hardware last session, relocated one tier down. **One line fixes it:**
`reservations: () => node.reservedPeerIds`, the same constructor-ordering shape
`browser-node.ts:208-217` already solves.

### Flows still asserted in one direction

The recorded anti-pattern is **partially** fixed. `seed-discovery.e2e.test.ts:251-330`
genuinely self-organises — explicitly no `window.o2.dial` anywhere. But
`two-tabs.e2e.test.ts:156`, `colouring-demo.e2e.test.ts:115` and
`background-tab.e2e.test.ts:173` still dial from the harness, and **no test puts two
tabs on a static bundle and asks whether they find each other** — which is precisely
the route §above shows is broken.

`sovereign-execution.test.ts` builds its own fabric end to end: hand-built authority,
hand-built index, hand-wrapped `EgressGuard`, hand-called `serveAgent`. It proves the
pieces compose when someone composes them, which is not the claim, because nothing does.

### Explicitly clean

Stated because a finding list without them reads as worse than the truth:

- **The `Executor` port is honoured by every implementation** — `WasmExecutor`,
  `WasiExecutor`, `WorkerExecutor`, `GovernedExecutor`, `RemoteExecutor` — and
  `submitJob` has no branch on kind.
- **The demo job really does flow through the net agent path**, proved across two real
  tabs.
- **The benchmark measures the real `submitJob` path**, not a parallel one.
- **Package layering holds**, no cycles, and `purity.node.test.ts` enforces it against
  real files.
- **No dead re-exports** — every barrel symbol resolves.
