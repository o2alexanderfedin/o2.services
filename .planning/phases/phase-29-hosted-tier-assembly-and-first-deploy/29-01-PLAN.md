## Step 1 — the billing alert. BEFORE anything is deployed.

**The ordering is the entire control.** There is no hard ceiling behind the alert: Cloudflare's
own wording is that its budget alerts are *"informational only. It does not cap your usage."* So
what the criterion can actually assert is not "spending was capped" but "the owner was watching
before the first object existed", and that is only assertable if the timestamps prove it.

1. Configure a budget alert on the account at the stated **$15/month** threshold.
   `wrangler` has no surface for this — established from the CLI's own help output, not from
   documentation — so this is the dashboard or the Notifications API.
2. **Capture timestamp A**: the alert's creation time. A screenshot or the API response.
   Save it into `29-EVIDENCE.md`.
3. **Do not proceed until A is saved.** A deploy performed first cannot be undone into
   compliance — the object exists from its first `get()` and its location is permanent.

**Expected cost, so the alert has a number to be judged against.** One always-on object at a
128 MB allocation is 0.128 GB·s per active second ⇒ 2,592,000 s/month × 0.128 = **331,776 GB-s**
against **400,000 included** ⇒ **≈$5/month**, with the over-rate at $12.50 per million GB-s.
Well inside $15.

**On the runaway-cost figure, if it comes up.** It is one Hacker News self-report
(`thewillmoss`, 2026-04-16, 31 points, 4 comments, no billing response), it was ~930 billion row
reads per day rather than alarm invocations, and it was multiplied by 60+ preview deployments.
It carries those qualifiers or it is not cited. The *structural* half of it — the preview
multiplier — is already closed by criterion 5's guard.

## Step 2 — the one deploy.

1. From `packages/cloudflare/`, run the real deploy. This is the owner's act and is outside
   what this session may run: every wrangler invocation in this repository is
   `deploy --dry-run --outdir=<scratch>` with `WRANGLER_SEND_METRICS=false`, which needs no
   authentication and exits 0 with no credential configured.
2. **Capture timestamp B**: the Version ID and the deployment's own timestamp.
3. **Check A < B before treating criterion 1 as satisfied.** This is the refutation the
   criterion names, and it is checked once, here.
4. Note the resulting host: `<name>.<subdomain>.workers.dev`.

**ONE deploy, not two.** An earlier reading in this project held that a first deploy was needed
to learn the host name and a second to bake it in. Both halves were measured false: the
workers.dev subdomain is an **account** property (`/accounts/{account_id}/workers/subdomain`),
and libp2p appends `/p2p/<peerId>` itself (`address-manager/index.js:252`, strips at `:89`).
The correction is dated in `packages/cloudflare/wrangler.jsonc`.

## Step 3 — criterion 2's evidence: four readings, one PeerId.

The cheap route exists and is deliberate — `worker.ts:232-247`, `GET /self` and nothing else,
because *"every route is a surface, and this tier's surfaces are not"*. It returns the PeerId
**from the seed in the object's storage**, so the answer is the store's and not the isolate's.
That difference is the entire reason this is a Durable Object: a plain Worker returned **three
different PeerIds to three consecutive requests**, each landing in a fresh isolate.

| # | Reading | How |
|---|---|---|
| 1 | fresh, cheap | `curl https://<host>/self` → record `{ peerId, nodeKey }` |
| 2 | fresh, real | from an outside machine, dial `/dns4/<host>/tcp/443/tls/ws/p2p/<peerId>`, complete identify, record the resolved remote peer |
| 3 | after an **eviction** | repeat 1 and 2 |
| 4 | after a **redeploy** | repeat 1 and 2 |

**Criterion 2 is satisfied only if all four return the identical PeerId.** A run that mints a
new identity on any later reading fails it, and the place to look is `hosted-identity.ts`'s
seed-persistence path.

**Reading 2 is the one that carries the criterion.** Reading 1 alone would prove the storage
survives and prove nothing about being dialable — the criterion says *dials, completes identify,
and gets the same PeerId*, three things. Do not report criterion 2 on `/self` alone.

**How an eviction is forced is UNVERIFIED** and is named as unverified rather than guessed. The
honest fallback is to wait, and to record the wall-clock gap beside the reading — a reading
taken after an interval nobody measured is still a reading, provided the interval is stated.
