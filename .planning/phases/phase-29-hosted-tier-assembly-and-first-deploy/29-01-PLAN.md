# Phase 29, Plan 1 — the two owner acts

**Every task below is performed by the owner.** That is the ruling of 2026-08-25 —
*autonomous execution stops at the Cloudflare boundary, and criteria 1 and 2 stay open until
the owner performs them* — and a phase report that ticks either on locally-done work has

## Revision 2026-08-27 — what an independent plan check changed

The first draft of this plan was checked and returned **FAIL**. Four findings, all confirmed
against the source before acting on them, and the first is the one that mattered:

1. **The evidence could not distinguish "survived an eviction" from "was never evicted."** Two
   readings of a live object give the same PeerId trivially. And the default made that the
   *likely* outcome, not an unlucky one: `hibernatable-socket.ts:17-22` records that
   `@chainsafe/libp2p-yamux@8.0.1` defaults `keepAliveInterval: 30_000`, so a held connection
   wakes the object every thirty seconds and **an object under a live connection does not
   hibernate at all** — the "hold a connection and wait" procedure was the one guaranteed not
   to evict. **Closed by `adc9336`**: `GET /self` now returns `instance`, fixed at construction,
   so a construction boundary is visible in the readings themselves. Four cases, watched red
   first.
2. **No `<task>` elements** — `gsd-sdk query verify.plan-structure` reported `task_count: 0`,
   against two `autonomous: false` precedents that wrap every owner step in a blocking
   checkpoint. **Closed below.**
3. **`files_modified: []` was not honest** — filling the evidence flips requirement rows and
   writes a summary. **Closed in the frontmatter.**
4. **No precondition that the namespace is empty.** Criterion 1 is about the *first* object;
   if one already exists the criterion is permanently unsatisfiable however carefully the
   ordering is executed. **Closed as Task 1.**
