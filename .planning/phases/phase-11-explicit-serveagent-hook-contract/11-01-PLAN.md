<objective>
Make `serveAgent`'s six hooks — `authorize`, `index`, `capacity`, `ledger`, `reservations`,
`onDispatch` — required, each typed as its real implementation type unioned with a named
sentinel string literal that reproduces exactly what silently omitting it did before. Sweep
every call site — 4 production, 6 net-package tests directly, 2 node-package tests
transitively — so nothing compiles with a hook left out. Build the two proofs the phase's
own success criteria demand: a compile-failure fixture (criterion 1) and a sentinel-count
guard (criterion 2), each mutation-tested so neither is a guard that only agrees with itself.

This is a signature change plus a mechanical sweep, not a feature. No hook gets a real
implementation in this phase — `authorize`, `index`, `capacity`, and `ledger` keep exactly
today's behaviour, expressed as a named value instead of an absent key. Real implementations
are Phases 12–21, one per capability.

Purpose: turn "a hook nobody supplied" from an invisible default into a compile error naming
the hook, and a fact recorded at the call site — the structural fix the other 35 unwired
v1.1 requirements depend on, per the v1.0 milestone audit.

Output: `packages/net/src/agent.ts` with a required six-hook `AgentOptions`; four production
call sites and six net-package test files updated to state all six explicitly; two new guard
files proving the two compile-time/count-time claims the phase's success criteria make.

**Sequencing note (binding):** the type change and the call-site sweep cannot land as
separate waves — the tree would not compile in between, and a checker resuming from a
half-applied state would see false failures unrelated to this plan's actual defects. All
three tasks below execute inside this one plan, in order, so the working tree is only ever
inspected in a state where either nothing has changed yet or everything has. Because of this,
Task 3 in particular runs larger than the usual ~10-30% per-task budget — that is intentional,
not a sizing miss.
</objective>
