## Phase Goal

**As a** browser visitor arriving from a Telegram message, **I want to** land somewhere that
works, with the copy that brought me there promising exactly what the licensing ruling will
still support a year later, **so that** what I was promised is what I actually get — with the
contribution posture written down before the first outside pull request arrives.

<objective>
Give the owner's two phones something to read back.

Purpose: criterion 2 asks what the embedded browser *does to a running node* — *"whether JS is
suspended on backgrounding, and whether IndexedDB or WebRTC diverge"*. The observations already
taken (`38-DEVICE-OBSERVATIONS.md`) say in their own words why the current screen cannot
answer the first half: *"the observable is identical either way — the indicator says
disconnected because the connection is gone, and nothing on the page distinguishes the engine
stopped from the network went away."* This plan builds the thing that distinguishes them, and
makes it survive the moment the visitor taps *continue here anyway* — because that is when the
observation is taken.

Output: one instrument that compares wall-clock elapsed against timer ticks across a hide, four
words-only verdicts, and a diagnostics mode so a device where the detector fires nothing still
produces a reading rather than a shrug.
</objective>

  <action>
    Create `packages/browser/src/hidden-gap.ts`.

    `classifyHiddenGap({ wallMs, ticks, intervalMs })` computes `due = wallMs / intervalMs` and
    returns:

    - `not-yet` when `wallMs` is 0 — no hidden span has been observed at all.
    - `stopped` when `ticks === 0` and `due` is at least some small integer floor (state the
      floor as a named constant with its reason beside it: a hidden span shorter than one
      interval legitimately fires nothing, and calling that *stopped* would be a false reading).
    - `throttled` when `ticks > 0` and `ticks` is far below `due` — the ratio, not a
      millisecond count.
    - `kept-running` when `ticks` is close to `due`.

    Every boundary is a named constant with a sentence saying what it is sited against. Do not
    tune a boundary to make a case pass.

    `HIDDEN_GAP_SENTENCES` maps each verdict to one words-only sentence a volunteer can read
    back over a phone call, for example: *"this page has not been hidden yet, so there is
    nothing to report"*, *"the script kept running while this page was hidden"*, *"the script
    was slowed down while this page was hidden"*, *"the script was stopped while this page was
    hidden"*. No digit in any of them.

    `HiddenGapWatcher` takes an injected `VisibilitySource`, an injected `now: () => number`
    and an injected timer pair, so the spec drives it with no tab and no real clock. On the
    transition to hidden it stamps `now()` and starts counting interval callbacks; on the
    transition to visible it stamps again, classifies, and keeps the **most recent** verdict
    available from `verdict()`.

    `packages/browser/src/hidden-gap.test.ts` drives all four verdicts through
    `classifyHiddenGap` directly, and drives at least one full hide/show cycle through
    `HiddenGapWatcher` with an injected clock. Add a floor case:
    `Object.keys(HIDDEN_GAP_SENTENCES).length === 4` and every sentence matches no digit —
    reuse `DIGIT` from `packages/browser/src/demo-regions.ts` so *digit on screen* has one
    definition in this repository.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host application → page lifecycle | The embedding application decides when the page is hidden, throttled or suspended; the page only observes the consequences |
| URL search parameter → page state | `entry-diagnostics=on` is attacker-controllable in the sense that any link can carry it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-38-06 | Information disclosure | `#entry-notice-liveness` | mitigate | The verdict is one of four fixed sentences from `HIDDEN_GAP_SENTENCES`. No timing number, no interval count and no clock value is ever rendered — a millisecond figure on a photographed screen is a fingerprint of the device, and it would also put a digit in a section this phase keeps digit-free |
| T-38-07 | Tampering | `entry-diagnostics=on` | accept | A crafted link can force the readout to show. It reveals only which of five declared candidate signals fired in the visitor's own browser, which the visitor's own browser already knows. No state changes, nothing is stored, nothing is sent |
| T-38-08 | Denial of service | `HiddenGapWatcher`'s interval | mitigate | One interval at a coarse period, started once at page start and stopped on `pagehide`. It must not be per-notice or per-visibility-change, or a page cycled between foreground and background accumulates timers. Assert a single watcher instance |
| T-38-09 | Repudiation | the recorded verdict | accept | The reading is the owner's observation on his own device, transcribed by hand in Plan 38-04. `38-DEVICE-OBSERVATIONS.md` already states this class of evidence for what it is — weaker than a spec, stronger than an emulator — and this plan does not upgrade the claim |
</threat_model>
