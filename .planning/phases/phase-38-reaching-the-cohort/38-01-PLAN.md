## Phase Goal

**As a** browser visitor arriving from a Telegram message, **I want to** land somewhere that
works, with the copy that brought me there promising exactly what the licensing ruling will
still support a year later, **so that** what I was promised is what I actually get — with the
contribution posture written down before the first outside pull request arrives.

<objective>
Detect that the page is running inside a host application's embedded browser, and offer the
visitor an "open in your own browser" notice.

Purpose: this is criterion 1's **agent half**. Criterion 1's own words refuse a green obtained
from a spoofed user-agent string — *"the point of the check is the engine, not the string"* —
so this plan builds a detector whose firing condition can be satisfied by a **host-injected
object with no user-agent change at all**, and whose verdict records, per signal, whether the
evidence was an engine/host observable or only a string. The automated spec proves the
detector is not a string check by driving it in the direction a string check cannot pass. It
does **not** claim criterion 1; that claim is the owner's two real devices in Plan 38-04.

Output: one pure module, one unit spec that runs in the `node` project and in all three browser
engines, one e2e spec, and a notice section on the demo page.
</objective>

export type SignalClass = 'host-object' | 'host-shape' | 'user-agent'

export interface CandidateSignal {
  readonly name: string        // rendered on screen — MUST contain no digit
  readonly klass: SignalClass
  readonly confidence: 'measured' | 'candidate'
  readonly why: string
}

export interface EmbeddedWebViewProbe {
  readonly bridgeObjects: readonly string[]   // names of injected host objects found
  readonly standaloneAbsent: boolean          // navigator.standalone is undefined
  readonly userAgent: string
}

export interface EmbeddedWebViewVerdict {
  readonly embedded: boolean
  readonly fired: readonly CandidateSignal[]
  readonly engineCorroborated: boolean   // true iff some fired signal is NOT 'user-agent'
}

export const CANDIDATE_SIGNALS: readonly CandidateSignal[]
export function readEmbeddedWebViewProbe(scope: unknown): EmbeddedWebViewProbe
export function detectEmbeddedWebView(probe: EmbeddedWebViewProbe): EmbeddedWebViewVerdict

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host application → page globals | An embedding application injects objects into the page's global scope before any of this project's code runs |
| page → visitor's clipboard | `navigator.clipboard.writeText(location.href)` on an explicit tap |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-38-01 | Spoofing | `detectEmbeddedWebView` | accept | Any page can define `window.TelegramWebviewProxy` on itself, and a hostile embedder can too. The worst outcome is a visitor shown an unnecessary "open in your own browser" notice with a dismiss button beside it. There is nothing to gain and no state to corrupt; the verdict grants no capability |
| T-38-02 | Information disclosure | `#entry-notice-signals` | mitigate | Render signal **names** from the declared `CANDIDATE_SIGNALS` table only. Never render `navigator.userAgent`, never render `location.href` — both put host-identifying strings on a screen a volunteer may photograph, and the URL also puts digits inside a section this plan keeps digit-free |
| T-38-03 | Information disclosure | detection at page start | mitigate | `readEmbeddedWebViewProbe` reads in-page globals only and issues no request. `built-bundle.e2e.test.ts` P10 (every request before consent is same-origin) stays green, and task 1 case C asserts it for this path specifically |
| T-38-04 | Tampering | `window.__o2EntryVerdict` | accept | A read-only diagnostic handle for the e2e harness, mirroring `ATTESTATION_HOOK`'s existing precedent. Overwriting it changes what a test reads and nothing a visitor gets |
| T-38-05 | Denial of service | the notice blocking entry | mitigate | The notice never disables `#allow` and never blocks `#gate`; task 2's action states this and the ordering specs (`disclosure-before-optin.e2e.test.ts`) are re-run as an acceptance criterion |
