# Phase 20 · Plan 09 — The speculation tax stops being a constant

**Closes:** criterion 3 — *a straggler task is duplicated speculatively during a live run, the
first correct result wins, and the job's reported cost accounting includes the speculation
multiplier.*

<objective>
The surface criterion 3 asks for already exists and is publishing constants.
`packages/node/src/bin/bench.ts` returns `speculationMultiplier: 1` and `redispatches: 0` with a
comment saying why — *"submitJob does not speculate or re-dispatch; those paths belong to
runResilient and are not exercised by this workload. Reported as the identity rather than as a
measured zero."* `packages/bench/src/perf-workload.ts` does the same. `packages/bench/src/harness.ts`
averages both into `speculationTax` and `churnTax`, and `packages/bench/src/report.ts` prints two
columns of them.

**Those comments were honest and are now false.** 20-01 and 20-07 gave `submitJob` both. This plan
replaces the constants with the job's own figures and takes the live reading.

**The reading is comparative, and that is not a stylistic preference here.** A speculation
multiplier is a ratio of dispatches, which depends on how slow the straggler was, which depends on
the host. An absolute threshold would encode this machine's I/O weather and fail elsewhere for
reasons unrelated to the code — `CLAUDE.md` § Measurement, and this repository has two recorded
instances of a wall-clock bound inside an otherwise deterministic test reading contention as a
defect. **The reading is the same fabric, the same job, with speculation on and off, in one run.**
</objective>

  be re-measuring criterion 2.

  which it is — the same care the original comment took in the other direction.
- **The egress wrapper is measured, not assumed.** A benchmark printing `1.00` proves nothing about
  whether the field survived.
- **If no CLI rung can straggle, that is reported as a limit**, not worked around.
