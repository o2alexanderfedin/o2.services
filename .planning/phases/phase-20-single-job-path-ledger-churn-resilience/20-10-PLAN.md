# Phase 20 · Plan 10 — The partial aggregate says it is partial

**Closes:** criterion 4 — *a cross-owner job run with some owners' nodes offline returns a coverage
report (`covered: X/Y`) alongside its result, rather than presenting a silently partial aggregate
as complete.*

<objective>
20-08 put owner coverage on `JobResult`. This plan reads it where it matters: over real
`bin/agent.ts` processes, with an owner's node genuinely stopped, and rendered where an operator
can see it.

**The load-bearing word is *silently*.** A partial aggregate is not a defect — an owner may
legitimately be offline and the answer over the rest may be exactly what the caller wants. What
must not happen is that the caller cannot tell. So the reading is not "the job failed"; it is "the
job returned an answer **and** the number of owners behind it."

**The entry-point substitution applies again**, and is stated in the file: `bin/agent.ts` submits
no job, so this is a job run **across** those processes.

**And there is a second claim in the neighbourhood that this file must not accidentally make.**
Sovereignty is `sovereignty-placement.node.test.ts`'s and Phase 12's; this file's business is the
denominator. But a cross-owner fixture with a node stopped is exactly the shape in which a
sovereignty leak would be invisible, so **assert the negative once** — the stopped owner's data is
not on anybody else's node — and say that the assertion is a guard rather than this criterion's
content.
</objective>
