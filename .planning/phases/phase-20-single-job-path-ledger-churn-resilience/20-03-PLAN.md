# Phase 20 · Plan 03 — A recovered node's combine result arrives late and costs nothing

**Closes:** criterion 6, carried here from Phase 16's criterion 3 by owner ruling 2026-07-31 —
*a combine result arriving from a recovered node after `executeReduce` has already collected its
`wanted` replicas is received and discarded harmlessly, an unsolicited late duplicate rather than
one the test asked for.*

<objective>
Phase 16 measured the dedupe across nine real `bin/agent.ts` processes and then said, against its
own interest, that *"arriving late"* was staged by the test. Its reason, in
`tree-reduce-agents.node.test.ts`'s own header: *"`executeReduce` has **no late-arrival channel** —
it walks the ranking, stops at `wanted` replicas, and there is no production path on which a
result arriving after that can be received at all."*

**That is true of `executeReduce` and false of the endpoint underneath it.** `packages/net/src/rpc.ts`
already holds the channel — search `late or duplicate reply`:

```
if (entry === undefined) return // late or duplicate reply
```

A reply whose pending entry the timeout deleted **is received, decoded, and dropped there**. So
criterion 6 was never "build a late-arrival handler". It is "produce a genuinely late arrival and
read what happens to it", and Phase 16 could not produce one because it had no recovery path.

**This plan produces one.** SIGSTOP the process holding rank 0 of a combine's rendezvous ranking;
let the requestor's `rpcTimeoutMs` elapse; let `executeReduce` walk on and take `wanted` replicas
from later-ranked agents; SIGCONT. The reply arrives at a requestor that has stopped waiting.

**The hard part is proving it ARRIVED.** Every harmlessness assertion — same root CID, same replica
count, no error — is trivially green if the frame never comes. **The reading that carries this
criterion is the arrival reading, and it must be the one that can fail.**
</objective>

From `packages/core/src/reduce.ts` — `executeReduce` walks `rendezvousRank(node.id, executors)`
**sequentially**, awaiting each `dispatch`, breaking once `produced.length >= wanted`, and counting
a `null` product as one `attempt`. `rendezvousRank` is exported and pure, so **the test can compute
which executor is rank 0 for a given tree node id before it stops anything** — that is what makes
the pause deterministic rather than a race.

From `packages/net/src/rpc.ts` — `request` registers a pending entry keyed on `peer\u0000id`, arms
a `setTimeout` that **deletes the entry** and rejects with `RpcFailure{kind:'timeout'}`, and
`#receive` drops any `res` frame whose key is absent. `RpcEndpointOptions.timeoutMs` defaults to
`DEFAULT_RPC_TIMEOUT_MS` (30 000).

From `packages/node/src/tree-reduce-agents.node.test.ts` — the fixture to reuse:
`standUp(8)` spawning eight `bin/agent.ts` processes plus an in-process submitter at
`rpcTimeoutMs: 10_000`; `spawnAgent`; `stopAgent` (SIGTERM — a *leave*, the process closes its
connections); `killAgent` (SIGKILL — a *vanish*); `runMap`. Its criterion-2 case stages a mid-flight
kill **by wrapping the production dispatch one layer down** rather than by reaching into the
library — copy that seam. Each `Agent` holds its `child`, so `child.kill('SIGSTOP')` and
`child.kill('SIGCONT')` are available; **no spec in this repository uses either yet**, so their
behaviour against a live libp2p stream is unverified here.

From `packages/net/src/combine.ts` — `remoteCombineDispatch(options): CombineDispatch`, the
production dispatch, returning `CombineProduct | null`.
