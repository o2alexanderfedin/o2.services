# Phase 20 · Plan 06 — A tab shows counts it could not have produced

**Closes:** criterion 5 — *the browser demo's peer activity ledger, viewed across two or more
connected tabs, shows merged counts contributed by every connected peer — not zero — because every
node now supplies `serveAgent`'s `ledger` hook and reported outcomes are recorded rather than
discarded.*

<objective>
20-02 gave every node a real ledger holding its own row. This plan is where a visitor sees the
consequence.

**The reading that carries this criterion is a foreign browser family, not a count.** A chromium
tab whose merged report contains a `firefox` row cannot have produced that row: there is no
expression in the page that would. A count above 1, by contrast, is satisfiable by an accident, a
double-record, or a fixture that opened the same page twice. Assert the family.

**The demo removed a true-looking sentence for a good reason and this plan restores it for a better
one.** `index.html`'s `refreshReport` comment records that a peer count used to sit beside the
report and read as a tally of contributors — *"`no start outcomes reported` directly above `peers
answering: 2 of 2 asked`"* — and that the lie was the juxtaposition, not the fields. It is no longer
a lie: the peers now contribute. **Quote that comment when replacing it**, and say what changed,
so the next reader does not re-derive the removal.

**And the same comment's deferral is now spent.** It defers the serve-side ledger *"behind the
magnitude bound and the label whitelist"*. 20-02 re-measured both and proved both falsifiable.
Replace the deferral rather than leaving it standing beside the thing it deferred.
</objective>

From `packages/browser/demo/main.ts` — `startReport()` on the tab API. Two arms: with no node
running it builds a local `StartOutcomeLedger`, records `lastOutcome`, and returns
`{reached: 0, asked: 0, text, reported, failed}`; with a node running it calls
`publishStartOutcome({rpc, peers, outcome: allowed ? outcome : null, declinedLocally})` and returns
the same shape with the real `reached`/`asked`. **`lastOutcome.browser` is `currentBrowserLabel()`**
(search `currentBrowserLabel` in that file).

Note the opt-out's exact semantics, which this plan must not change: *"Declining to report is not
declining to see: a visitor who opted out still asks, they simply tell nothing."* The declining tab
sends `outcome: null` and still merges what it is told.

From `packages/browser/src/tab-api.ts` — `TabStartReport` carries `reached`, `asked`, `text`,
`reported`, `failed`. **It carries no structured counts**, so a spec can only regex the rendered
text unless this plan widens it. Widening it is the honest move for a *foreign family* assertion,
which should not depend on prose formatting; decide and say which.

From `packages/browser/demo/index.html` — `refreshReport` calls `window.o2.startReport()` and
renders through `showReportOnly(report.text)`. `describeStartReport` (in
`packages/core/src/start-outcome.ts`) is what produces that text: one summary line, one line per
browser tally, and one line per blind spot. The blind spots are **inside** the string deliberately,
so they survive being copied.

From `packages/node/src/static-rendezvous.e2e.test.ts` — the fixture shape to copy: three engines
(`chromium`, `firefox`, `webkit`), each its own `browserType.launch()` and therefore its own
storage; the bundle **built in the fixture** so the spec fails when sources break the bundle; a
deliberately dumb 404-ing file server over `dist/`; `/bootstrap.json` asserted 404; `?relay=` as
the only address supplied and **no `window.o2.dial` anywhere**; sequential discovery rounds with
`asked: true` and `attempted === undiscovered` asserted as an exact anti-vacuity reading; an engine
that could not take part published with its reason and failing the first case rather than vanishing.

**Three engines is what makes this criterion measurable at all**: three tabs of one engine share a
family label, and `mergeOverlapping` takes the maximum per `(browser, result)` key, so a
single-engine fixture cannot distinguish a merged report from a local one. Say that in the file.
