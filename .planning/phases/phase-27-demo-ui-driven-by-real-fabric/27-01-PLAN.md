<objective>
Fix the measured activity-bar overflow and land the regression spec that stops it
recurring. Measured 2026-08-08 at a 393px iPhone viewport: `#bar` is 500px wide,
`#bar-what` and `#bar-stats` are non-wrapping flex children, and `#stop` sits past
x=482 — off screen. Stop is the control the consent gate promises in writing.

`index.html` already carries a comment about an earlier `#bar` defect — *"Reported from
an iPhone; not caught here, because the tests asserted the `hidden` attribute rather
than whether anything was on screen."* This is the same blind spot one property over:
**nothing asserts the bar fits.** The spec is the deliverable; the CSS fix is small.

This plan is first in the phase because the defect is live on a promised control and
because the spec must exist before the page is restructured — a geometry assertion
written after the redesign is a description of the redesign, not a guard on it.

Purpose: close a live mobile defect on the one control the disclosure promises, and
leave behind an instrument that reddens if the fix is undone or re-broken by the
redesign that follows in Plan 27-02.
Output: `packages/node/src/demo-viewport.e2e.test.ts` holding B1-B7 of UI-SPEC section
6.3, and `#bar`'s grid contract from section 6.2 in `index.html`.
</objective>
