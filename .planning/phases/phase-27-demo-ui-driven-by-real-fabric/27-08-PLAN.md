<objective>
Wire the fabric-state surface — UI-SPEC section 4.6's twenty-one regions. It is the
surface with no workload of its own: it renders the cross-cutting readings `TabApi`
already returns and that no screen has ever shown.

Its one structural rule is the one UI-SPEC states for every surface and that bites
hardest here: **most readings throw `node not started` when there is no node.** `peers`,
`heldPeers`, `computePeers`, `governor`, `capacity`, `addresses`, `storedBlocks` all do.
So the page calls a reading only when `activity() !== null` and renders the stopped
absence otherwise — and when a call throws anyway, the region renders **the thrown
message** as its named reason. Never a number, never a blank, never a retained previous
value. `isolation()`, `startReport()`, `consentState()`, `disclosure()`, `activity()` and
`verifyAnswer()` are the six that are safe with no node, and they are the only ones called
unconditionally.

Two existing elements move onto this surface and must keep working exactly as they do:
`#report` and `#refresh-report`, reached by `peer-ledger.e2e.test.ts` and
`two-tabs.e2e.test.ts` through `getElementById(...).click()` and `textContent`, both of
which work on a hidden panel. Plan 27-02 moved them; this plan must not disturb them, and
**`#report`'s initial literal stays `not asked yet`** — see Plan 27-02's correction to
UI-SPEC's F18 row.

The surface has **no primary run control**. UI-SPEC section 11: *Fabric state — none; the
surface reads, it does not run.* `#refresh-report` and the duty-cycle slider are controls
and neither is a `.btn-primary`, so `demo-liveness.e2e.test.ts` skips this surface by
name, which is what it should do and what it must say it did.

Purpose: make the fabric's own state legible — including the two conditions nobody can
act on unless they are reported: the start-outcome cliff, and a peer that is connected
and cannot carry a job.
Output: `surfaces/fabric.ts`, twenty-one declared regions, `WIRED_SURFACES` gaining
`'fabric'`, and `demo-fabric.e2e.test.ts`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| peer -> `byBrowser` rows, peer ids, addresses | Peer-authored values rendered into a visitor-facing table |
| peer -> `startReport()` merged tallies | Bounded at the wire by `parseCounts` (`MAX_REPORTED_COUNT`, `isStartBrowserLabel`); the row *count* is unbounded and this surface renders it |
| visitor -> `setDutyCycle` | The page's own control; there is deliberately no wire frame that does the same thing |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-27-29 | Tampering / Elevation | Peer ids, addresses and browser labels reaching the DOM as markup | mitigate | `textContent` only, enforced by the grep gate over the surface modules (Task 1) |
| T-27-30 | Denial of Service | An unbounded `byBrowser` row count rendered into a table — measured at 43.90 bytes a row against NET-08's 8 MiB inbound ceiling, a crossover at 191 099 rows, so that ceiling does not meaningfully bound it | accept | The bound is a wire-level decision nobody has taken and this phase does not take it. The surface renders what `parseCounts` admitted. Recorded here so the exposure is visible rather than implied, and carried into `27-OPEN-ITEMS.md` by Plan 27-10 |
| T-27-31 | Repudiation | A reading that throws rendered as a blank or a stale value | mitigate | Per-reading `try`/`catch` rendering the thrown message verbatim, with a plant proving one throw does not blank the surface (Tasks 2, 3) |
| T-27-32 | Repudiation | The start-outcome cliff shown as a zero | mitigate | F18 names it: `Asked, and no peer answered.` (Tasks 1, 3) |
</threat_model>
