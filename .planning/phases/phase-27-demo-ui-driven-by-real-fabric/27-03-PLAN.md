<objective>
Land the anti-placeholder guard **before the screens**. Written after them it would be
written to fit them, and *"the mockup is now wired"* would be satisfiable by CSS.

Three artifacts, in this order: the complete region catalogue as committed data; the
writer that paints an absence or a reading and nothing else; and the guard that
enumerates the page against the catalogue. The session header is wired through the
writer in the same plan — it is the one place readings already exist, so the mechanism
is proved against real data before any new surface depends on it.

**Two corrections to UI-SPEC, both load-bearing, both stated here rather than
discovered later:**

1. **The catalogue lives at `packages/browser/src/demo-regions.ts`, not
   `packages/browser/demo/regions.ts`.** `tab-api.ts` states the rule in its own opening
   docblock — it lives in `src/` rather than `demo/` *"so the page that implements it and
   the harness that calls it type-check against one definition"*, because a mismatch
   otherwise surfaces only as a timeout inside `page.evaluate`. That argument is exactly
   this file's argument.
2. **The guard's expected strings come from the catalogue, never from the element's own
   `data-absence` attribute.** UI-SPEC section 9's P3 reads *"every region's trimmed text
   equals its `data-absence`"*. If the writer sets `textContent` and `data-absence`
   together — which it must, since a region has three different absence sentences for
   three different states — then that comparison is true by construction and P3 can never
   fail. The catalogue holds the three sentences; the element holds the current one; the
   guard compares the element against the catalogue. That is the only arrangement in
   which P3 is a measurement.

**P5 is deliberately not in this plan.** It is the liveness property — *after a real
two-tab run the colouring regions no longer equal their absence text* — and it is the
one property that cannot be green before a screen exists. It lands in Plan 27-04, in a
form that quantifies over *every surface that has a primary run control*, so that π and
bring-your-own inherit it unwritten. UI-SPEC says why it matters: **P2, P3 and P4 are all
satisfiable by a page that renders nothing.**

Purpose: make *"every figure comes from a `TabApi` reading, or is a named absence"*
mechanically checkable before there is anything to check it against.
Output: `demo-regions.ts`, `render.ts`, the session header wired, and
`demo-regions.e2e.test.ts`.
</objective>

```typescript
export type RegionKind = 'reading' | 'constant' | 'cited' | 'control' | 'text-view' | 'prose'

export type SurfaceId =
  | 'session' | 'bar' | 'colouring' | 'primes' | 'pi' | 'byo' | 'fabric' | 'bench'

export interface RegionAbsence {
  /** On screen with a running node and nothing dispatched. Contains no digit. */
  readonly initial: string
  /** On screen when `activity() === null`. Contains no digit. */
  readonly stopped: string
  /** The legitimate-absence arm, when UI-SPEC section 4 names one. Contains no digit. */
  readonly unavailable?: string
}

export interface Region {
  /** `<surface>/<field>`, unique. The catalogue key and the `data-region` value. */
  readonly id: string
  readonly surface: SurfaceId
  readonly kind: RegionKind
  /**
   * `reading`  -> `TabApi.<method>().<field>`, exactly
   * `constant` -> the exported symbol, e.g. `@o2/demo.MAX_N`
   * `cited`    -> the document path and section
   * others     -> what the element is
   */
  readonly source: string
  /** Required for `reading`. Absent for every other kind. */
  readonly absence?: RegionAbsence
  /**
   * The bar's three regions only. `activity() === null` removes the element entirely —
   * UI-SPEC section 4.1: the element's existence IS the reading, and a bar reading `idle`
   * while offering to stop a node that does not exist is a defect this page already fixed
   * once. P1b skips these when `#bar` is absent.
   */
  readonly absenceMode?: 'element-removed'
  /**
   * This reading has **no dispatch path from a tab**, permanently, and renders its
   * `absence.unavailable` sentence in every state. The Primes surface's readings, and
   * `primes/per-shard` and pi's shard-partials row, which name a field no reading carries.
   *
   * Two guard consequences, and they are the point of the flag rather than side effects:
   *
   * - **P3** expects `absence.unavailable` for these, not `absence.stopped`.
   * - **P4 inverts for these.** For an ordinary reading, the method named in `source` MUST
   *   be a key of `window.o2`. For one of these, it must **NOT** be — which turns *this
   *   surface cannot run* into a positive, checkable claim. The day somebody adds
   *   `TabApi.runPrimes`, P4 reddens and the Primes surface is forced back onto the board
   *   instead of quietly staying absent.
   */
  readonly permanentlyUnavailable?: { readonly reason: string }
}

export const REGIONS: readonly Region[]

/**
 * The surfaces whose regions must all be on screen. One line per surface, appended by the
 * plan that lands it — a greppable admission that a surface has arrived, and the switch
 * that turns P1's second half on for all of that surface's regions at once. Starts as
 * `['session']`; the phase is complete when it holds all eight.
 */
export const WIRED_SURFACES: readonly SurfaceId[]
```
