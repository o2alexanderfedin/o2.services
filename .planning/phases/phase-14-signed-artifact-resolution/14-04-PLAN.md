# Phase 14 — Signed Artifact Resolution · Plan 04

**Closes (in part):** DET-03, DATA-08 — the browser tier's half
**Wave:** 4 · **Depends on:** 14-03 · **Autonomous:** yes

> **Numbers in this plan are configuration choices, not derived claims. Any quantity
> describing runtime behaviour must be measured before it is written down anywhere,
> including in a source comment.**

The tier 14-CONTEXT.md Risk 1 says cannot be waved through. `runColouring` is the
visitor-facing demo — Phase 9's "a real job someone cares about" — and DET-03's
criterion 1 carries no label qualifier, so the public path is in scope exactly as the
sovereign one is. A phase that wired the Node tier and left the demo resolving a bare
CID would be the shape of gap the v1.0 audit exists to catch.

The production call site added: `packages/browser/src/browser-node.ts`, inside
`BrowserNode.start`'s single executor composition. The test that fails if that call
site is deleted: `packages/node/src/two-tabs.e2e.test.ts`'s new refusal case, which
requires a job dispatched between two real browser contexts to fail when its record is
signed by an unpinned key.

**Where this tier's evidence comes from, stated before any claim rests on it.**
`BrowserNode.start` builds a real libp2p node and dials a relay; there is no unit test
of it in the repository and this plan does not invent one, because a test that
reproduced the composition rather than calling it would prove that the copy is right.
So the browser tier's wiring is proved end to end, in the e2e project, between two
genuinely separate browser contexts — the same evidentiary standard `two-tabs.e2e.test.ts`
already sets for BROW-03 and BROW-04. What that leaves unmeasured is named in
`## What this plan does not measure` below rather than left for a reader to discover.

<objective>
Compose the provenance guard in `BrowserNode`, pin the demo's anchor in the demo, and
give the Playwright harness the one thing it now needs — a way to hand a signed record
across `page.evaluate`.

`BrowserNodeOptions.trustAnchors` is required and takes the same
`readonly PublicKeyHex[] | 'runs-unsigned-artifacts'` shape `FabricNodeOptions` took in
Plan 14-03, for the identical stated reason. But the `TabApi` surface above it exposes
**no opt-out at all**: `start` takes an optional anchor *list* that defaults to the
demo's committed anchor, and `runJob` requires a record. There is deliberately no value
a page or a harness can pass through `window.o2` that yields a tab resolving bare CIDs.
That asymmetry is the point — the opt-out belongs to whoever constructs a node in
TypeScript and has written down that they want one; it is not part of the tab's
contract.

Purpose: the demo tab is a production node. Every node runs the same code; the only
difference between them is discovery.
Output: the guard composed in `BrowserNode`; `runColouring` on the signed path; two
e2e files upgraded from bare CIDs to signed records, one of them carrying the refusal
proof.
</objective>

## What this plan does not measure

Stated in these words because unmeasured is not met:

- **`BrowserNode.start` has no unit test, before or after this plan.** It builds a real
  libp2p node and dials a relay. The composition is proved only end to end, in the e2e
  project. A defect that broke composition in a way both e2e runs happened to tolerate
  would not be caught here.
- **The factory-less arm of `worker ?? new WasmExecutor(...)` is exercised by no
  production path and by no test in this plan.** The demo always supplies
  `createTaskWorker`. Guarding the whole expression rather than one arm is what makes
  that gap harmless, and it is a structural argument rather than a measurement.
- **"Refused before `WebAssembly.instantiate`" is not observed in a browser.** Nothing in
  a page can watch that call. The property is carried by `module-provenance.test.ts`'s
  call-counter readings and by `signed-artifact.node.test.ts`'s never-fetched module
  block; neither of those runs in a browser, and this plan does not claim otherwise.
- **`runColouring`'s record-versus-bytes mismatch branch is unmeasured.** No test executes
  it. Drift itself is detected — `kernel-build.node.test.ts` compares the record's CID
  against `kernel.wasm` on disk and fails before any demo runs — but the *wording* of the
  error `runColouring` would throw, and the fact that it throws before dispatching rather
  than after, are unread. What would measure them: exporting the comparison from `@o2/demo`
  as a pure function and unit-testing it, which is a refactor of Plan 14-02's generated
  artifact and is not opened here.
- **No assertion reads a tab's pinned anchor list, because nothing exposes one.** The
  replacement property is measured through its consequence (a genuinely-signed demo record
  refused by a harness-pinned tab), which is strictly weaker than reading the set: it
  proves the demo anchor is absent, not that the set contains exactly one entry. Adding a
  reader would mean putting node configuration on `window.o2`, which is a surface this
  phase should not open.
