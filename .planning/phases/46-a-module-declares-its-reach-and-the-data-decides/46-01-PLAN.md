<objective>
CAP-01, half 1: give `NameRecord` a signed field a publisher uses to declare that a module
wants network reach, and make every hand-written codec in `naming.ts` — the signing payload
and the JSON file form — carry it under the exact discipline `translationKeyCid` and
`delegation` already established: absent means "never declares", present-and-unparseable
refuses the whole record, and the two states must hash byte-identically to a record signed
before the field existed.

Purpose: this is the interface every later plan in this phase reads. `network-reach-guard.ts`
(46-03) reads `NameRecord.wantsNetworkReach` off an unverified record; the wire codec (46-02)
must encode/decode the identical field under the identical rule or it reproduces the exact
transport bug `naming.ts:1064-1068`'s comment already describes for `translationKeyCid` and
`delegation`.
Output: `NameRecord` carries the field; `payloadOf`, `encodeNameRecord`, `decodeNameRecord`
all agree on it; `naming.test.ts` proves the three claims criterion 1 makes, as byte
comparisons rather than as sentences.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Publisher signature → NameRecord bytes | `payloadOf`'s output is what a private key signs; anything outside that computed value is unauthenticated no matter where it sits on the record |
| naming.ts JSON file → decodeNameRecord | A file on an operator's disk, or handed peer-to-peer, is untrusted input until `SignedNameResolver.accept` verifies it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-46-01 | Tampering | `naming.ts` payloadOf / encodeNameRecord / decodeNameRecord | mitigate | `wantsNetworkReach` follows the spread-omit idiom exactly, so it is inside the signed payload; Task 2's stripped/attached case proves altering it invalidates the signature |
| T-46-02 | Tampering | `decodeNameRecord`'s malformed-field handling | mitigate | present-and-not-`true` (including `false`) returns `null` for the whole record rather than silently dropping the field, so a decoding bug cannot present as an unsigned declaration |
| T-46-03 | Information Disclosure | none — this plan adds no new data path | accept | the field only ever travels inside an already-public signed record; nothing here reads or exposes node-side state |
</threat_model>
