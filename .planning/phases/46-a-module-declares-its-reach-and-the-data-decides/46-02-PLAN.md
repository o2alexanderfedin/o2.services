From packages/core/src/naming.ts (this phase's Plan 01, already landed):
```
readonly wantsNetworkReach?: true
```
`payloadOf`, `encodeNameRecord`, `decodeNameRecord` all spread-omit it and all refuse a
present-and-not-`true` value by returning `null`/throwing. `nameRecordToValue`/
`parseNameRecord` below must agree byte-for-byte with `payloadOf`, not with `encodeNameRecord`
— the wire form and the JSON file form are independent codecs that both happen to follow the
same idiom, and only the wire form's agreement with `payloadOf` is this plan's concern.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Peer wire frame → parseRequest | Bytes from any peer, including a hostile one; `parseNameRecord` must refuse anything it cannot parse rather than silently coercing it |
| parseNameRecord output → SignedNameResolver.accept | The parser's job is shape only; verification is a separate, later step and this plan does not blur that line |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-46-04 | Tampering | `parseNameRecord` | mitigate | present-and-not-`true` returns `null` for the whole frame rather than dropping the field, so a malformed wire value cannot silently become "no declaration" |
| T-46-05 | Repudiation-adjacent (transport-bug-wearing-a-forgery's-name) | `nameRecordToValue` | mitigate | Task 2's round trip proves the field survives the wire and re-verifies, closing exactly the class of bug this file's own history records for `translationKeyCid`/`delegation` |
</threat_model>
