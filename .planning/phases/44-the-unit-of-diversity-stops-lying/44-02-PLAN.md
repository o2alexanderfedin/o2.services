# 44-02 — The documentation half

Depends on 44-01 landing: these sentences describe a mechanism, and they must describe the one
that exists afterwards.

## Task 1 — `enrollment.ts:122`

It lists, among the reasons the attack radius is tolerable:

> `composeQuorum` enforces anti-affinity by `operatorId` so N sybils under one operator take
> exactly one quorum slot.

True, and about a **narrower** attack than it reads. It covers N identities under **one** name;
it does not cover N identities under N names, which cost one extra string and was checked
nowhere. A reader who stopped there concluded the fabric was protected. **This is the item that
ends a reader's search; correcting it is the point of the phase, not its tidying.**

Keep the sentence and qualify it in this file's own dated style — it was true, about the thing
it was about. Add: the field is now derived from `userKey` (Phase 44), so the extra string is
gone; and that this buys **truth-in-labelling, not a cost to the attacker** — rotating user
keys is free and `enrollment.ts:71` already measures it. Point at Phase 45 for the part that
an attacker actually runs into.

## Task 2 — RFC-0003 gains the missing threat and the missing invariant

`docs/architecture/RFC-0003-Decentralized-Cloud-Security-Architecture-v0.2.md`. Measured today:
`grep -niEc "sybil|operator"` → **0**. §14 lists twelve threats; §15 lists eight invariants.

- **§14** gains bulk identity minting: an applicant obtaining many certificates that a quorum
  reads as many parties.
- **§15** gains the invariant the code has been carrying without the RFC ever stating it: an
  attribute a quorum treats as a diversity dimension is determined by the issuer from material
  it verified, never asserted by the applicant.

Written in the file's own voice — short declarative bullets, no file:line citations, no
implementation vocabulary. The RFC is an architecture document.
