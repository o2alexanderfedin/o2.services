# Phase 22 · Plan 04 — The gate, and what "CI" means in a repository that may not have any

**Closes:** criterion 3, at whatever the checkpoint in 22-03 ruled it can be scored as.

<objective>
Criterion 3 asks that the guard *"runs as part of the same CI gate as the rest of the suite, so a
future change that builds a mechanism without wiring it to an entry point fails CI rather than
merging silently, the way the original 36 did."*

**There is no CI in this repository, and there may not be one.** Measured: no `.github` directory
exists at any depth; `disclosure-gate.node.test.ts` asserts its absence both tracked and untracked;
and `.githooks/pre-commit` states the reason in its own words — *"Adding CI to close this would
break the invariant it is meant to protect. **Do not 'fix' the absence of `.github/` by adding
it.**"* Public hosting is public disclosure, EPO and China forfeit permanently, and the US
provisional deadline is 2027-07-26.

So this plan does the implementable thing — put the guard in the gate this repository actually
has — and **records the discrepancy at the line rather than quietly redefining the word.** The
score was ruled at 22-03's checkpoint; this plan implements it and writes it down.
</objective>

**The gate as it exists.** `.githooks/pre-commit` (installed via `core.hooksPath`) runs **one**
vitest invocation — `--project node --silent=true` — over six specs: `vocabulary`, `purity`,
`mutation-guard`, `disclosure-gate`, `requirements-ledger`, `slow-specs`. Three details in its own
comments are load-bearing and each was paid for:

- `--silent=true`, **not** a bare `--silent`: the flag takes an optional value, so a bare one
  swallows the next argument. The hook shipped that way once and refused every commit including
  its own.
- `--project node` is **required** — four projects exist and a bare path fans out across all four.
- The filter on `STAGED` was removed deliberately. *"The population a guard **checks** was strictly
  larger than the population that **triggers** it, and the gap was exploitable by accident."*
  Do not reintroduce a filter.

**The budget, in the hook's own words:** *"Deliberately not run here: `tsc --noEmit` (~10 s) and
the full node suite (~290 s). A hook slow enough to be resented is a hook that gets disabled with
`--no-verify`, and then it guards nothing at all. These three take about 1.5 s of test time."*
That sentence says **three** and the list holds **six** — it is stale, and correcting it is part of
this plan rather than a separate courtesy.

**The reachability guard's measured cost, as a starting shape only.** The read-only probes ran the
whole TypeScript API load plus a declaration-level trace at `real 0.31` / `user 0.65` / `sys 0.21`,
i.e. `(user+sys)/real` ≈ 2.8 — the API spawns a server, so `real` understates the CPU. **That is a
probe, not this guard**, and vitest process startup is on top. Measure the real thing.

**`vitest.config.ts`.** `SLOW_CUTOFF_MS = 1000`; `MEASURED_NODE_SPANS` is a per-file span table;
`NODE_MEASUREMENT` records `date`, `load`, `loadPeak`, `files`, `tests`, `sumOfFileSpansMs`,
`wallClockMs`, `unitFiles`. `slow-specs.node.test.ts` **parses that file's source** and asserts,
among others, that `unitFiles === files - EXCLUDED.length`, that spans are sorted descending, and
that the node project's file count is within `FILE_COUNT_TOLERANCE` of `NODE_MEASUREMENT.files`.
Adding node specs moves that count.

**`mutation-ledger.ts`.** A `Mutation` carries an id, prose saying what breaks in the world, a
`find` string that must appear in its file **exactly once**, `caughtBy` files, an observed
`signature`, and a `signatureSource` saying whether the signature is source text. The cheap layer
(`mutation-guard.node.test.ts`) checks that each entry still describes the source; the planting
layer (`npm run test:mutations`, `mutation-guard.mutate.ts`) plants for real and requires a
non-zero exit carrying the recorded signature. **48 of 72 signatures are the test's own title**,
which is why a title rename has silently broken entries before.
