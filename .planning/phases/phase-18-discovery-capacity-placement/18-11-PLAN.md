# Phase 18 · Plan 11 — A full relay says so, to a real joiner

> **Numbers in this plan are configuration choices, not derived claims. Any quantity
> describing runtime behaviour must be measured before it is written down anywhere,
> including in a source comment.**

**Closes:** criterion 4 and NET-05 — *a relay run via `bin/seed.ts` at reservation capacity
reports the exhaustion by name to a joining node attempting to reserve, rather than the
joiner failing indistinguishably from a network outage.*

<objective>
The mechanism is complete and has been since Phase 3. `ReservationWatcher`
(`reservation-watch.ts:96-190`) classifies libp2p's own reported status into `at-capacity`,
`refused` and `protocol-error`; `relaying.node.test.ts:220-246` already drives the full
sequence in process — fill a one-slot relay, dial it with a second peer, read
`{kind: 'at-capacity', status: 'RESERVATION_REFUSED'}`, and confirm the relay agrees.

What is missing is stated by REQUIREMENTS.md in one line: ***ReservationWatcher is installed
by no process***. `FabricNode` only *accepts* one (`fabric-node.ts:408`, consumed
`:963-965`); `bin/seed.ts` does not construct one (`bin/seed.ts:43-49`); `bin/agent.ts` has
no flag that makes a node reserve on a relay at all. So the requirement is **Partial**: the
reading half is wired and the reporting half exists only in a test.

A second gap blocks the criterion's own configuration. `bin/seed.ts` prints a peer id and a
reservation limit (`:61`, `:63`) and **no dialable address** — it prints join *URLs* for a
browser. Nothing an operator reads tells them what multiaddr to point an agent at. That is a
real omission for an operator, not only for a test, and this plan closes it.

**And this plan pays a cost worth declaring up front.** `bin/seed.ts` boots a Vite dev
server; its own source says so and says that is why no test has ever spawned it
(`bin/seed.ts:66-74`). Criterion 4 names that binary, so the test spawns it and the run is
slow. The alternative — testing against an in-process relay — would not meet the criterion
as written, and lowering a bar is not clearing it.
</objective>

## Recorded decisions

- **A reservation failure is reported and is not fatal.** A node that could not get into one
  relay can still work; killing it would replace an indistinguishable failure with a worse
  one, which is the opposite of what NET-05 asks for. This is deliberately the opposite
  disposition from `--peer-addr` and `--provider-addr`, and the difference is that those fail
  before the node exists while this is a fact about somebody else's capacity.
- **Both outcomes are reported, not only the failure.** A channel that speaks only on failure
  cannot be told from one that is broken, which is the same class of defect NET-05 exists to
  remove one layer down.
- **The reports go to stderr and stdout keeps exactly one line**, so every existing parent
  that reads the handshake line is unaffected.
- **`bin/seed.ts` prints its dialable relay address** because an operator running
  `agent.ts --relay-addr` had no way to discover one. That is a product gap this criterion
  exposed, not a test affordance.
- **The Vite boot cost is paid deliberately** and the measured wall time goes in the summary.
  The criterion names the binary, and testing against an in-process relay would be lowering
  the bar rather than clearing it.

## Out of scope

- The relay's own side of the report. `FabricNode.capacity` already answers
  `granted`/`limit`/`remaining`/`atCapacity` (`fabric-node.ts:1385-1394`) and
  `relaying.node.test.ts` asserts it; nothing new is needed and nothing new is added.
- A retry or a relay-selection policy. A joiner that learns `at-capacity` now has a named
  condition to act on; what it should *do* about it — try another relay, back off, wait — is
  a policy decision no criterion here asks for, and inventing one would be a mechanism this
  phase could report on but not measure.
- The browser tier's own reservation reporting. `BrowserNode` takes no
  `reservationWatcher` option; whether it should is NET-06 / Phase 19's, which owns two
  browser peers finding each other with nothing dialled by a harness.
- The three-flag fold at `bin/agent.ts:74-78`. Carried forward, not attempted.
