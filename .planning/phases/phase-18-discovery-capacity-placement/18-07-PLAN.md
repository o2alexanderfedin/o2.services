# Phase 18 · Plan 07 — A duty cycle that can change

> **Numbers in this plan are configuration choices, not derived claims. Any quantity
> describing runtime behaviour must be measured before it is written down anywhere,
> including in a source comment.**

**Builds:** the kernel half of criterion 3. Plans 18-08 and 18-09 wire the two tiers.

<objective>
Criterion 3 is **new construction on both tiers**, not wiring, and 18-CONTEXT.md measured
why.

`DutyCycleGovernor` (`core/src/governor.ts:29-60`) has **zero production callers** — only
`governor.test.ts` constructs it. `FabricNode` composes **no governor at all**: its stack is
`new CountingExecutor(guardSovereignty(provenance(compute), sovereignty))`
(`fabric-node.ts:1202`). The browser tier composes `VisibilityGovernor`
(`browser-node.ts:804-808`, `:884`), a *different* class whose `dutyCycle` is a getter
driven by `visibilitychange` (`visibility-governor.ts:112-114`) with **no external setter**.
So on one tier there is nothing to set, and on the other there is nothing that would accept
a setting.

Criterion 3 also asks that *"the node's advertised capacity to `discoverExecutors` drops
accordingly, observable in what the requestor is offered next"*. There is nowhere in a
`CapabilityRecord` to put a capacity — it carries `nodeKey`, `features`, `sovereignFor`,
two timestamps and a signature (`core/src/discovery.ts:63-85`) — and a signed record is
the wrong place for a figure that changes by the minute. The observable the criterion names
is the *offer*, and Plan 18-04 put a slot count in it. `LocalCapacity` already scales its
slots by a duty cycle (`placement.ts:285`); it just computes them **once, in the
constructor**. Making that derivation live is what connects the cap to the figure a
requestor reads.

Purpose: one governor whose cap can move, and a slot count that follows it. Output: a
settable `DutyCycleGovernor` that composes with an environment source, and a
`LocalCapacity` whose `slots` is a reading rather than a memory.
</objective>

## Recorded decisions

- **Composition is a minimum, not a product.** Both values are ceilings on the same fraction
  of wall time, so the binding one is the smaller; a product would invent a third ceiling
  nobody chose and would break the browser tier's positive-floor argument.
- **`environment` is required with a named absence.** A silent `undefined` would make "no
  other signal binds this node" indistinguishable from "somebody forgot to pass the tab's
  governor".
- **One `dutyCycle` field, two ways of stating it.** A separate `governor` option would be
  one quantity with two answers.
- **A lowered cap bounds starting and never retracts a grant**, and `load` is reported
  honestly above 1 while it drains rather than clamped.
- **`advertisedCapacity` is deliberately not promoted to the `Governor` port and is not
  criterion 3's observable.** Nothing reads it. The observable is the slot count in the offer
  answer, which is a figure a requestor actually receives.

## Out of scope

- Composing a governor on either node factory, and any way for a user to set the cap —
  Plans 18-08 (Node tier) and 18-09 (browser tier).
- Putting a capacity figure into `CapabilityRecord`. It is a signed document with a validity
  window; a figure that changes by the minute does not belong in one, and criterion 3's
  observable is the offer answer instead.
- Changing `GovernedExecutor`. It reads `governor.dutyCycle` per `execute` already, so a
  live getter is honoured with no edit, and that is asserted by `packages/net` passing
  unchanged in this plan's verify command.
