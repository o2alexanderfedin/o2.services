# Phase 18 · Plan 09 — The same cap, in a tab

> **Numbers in this plan are configuration choices, not derived claims. Any quantity
> describing runtime behaviour must be measured before it is written down anywhere,
> including in a source comment.**

**Closes:** criterion 3, browser tier. Plan 18-08 closed the Node tier.

<objective>
Criterion 3 says *"Node tier and browser tier alike"*, and the two halves are unequal today
in opposite directions. The Node tier had no governor at all. The browser tier has one —
`VisibilityGovernor` (`browser-node.ts:804-808`, `:884`) — whose `dutyCycle` is a getter
driven by `visibilitychange` (`visibility-governor.ts:112-114`) with **no external setter**.
So a user cannot set a cap in a tab either, and the class that would accept one was never
composed there.

**This plan does not replace `VisibilityGovernor` and must not.** BROW-03 is a shipped,
measured behaviour with its own e2e coverage (`background-tab.e2e.test.ts:199-225`), and its
positive-floor argument — *"a hidden tab throttles rather than stops … turning a background
transition into abandoned work and a failed replica"* — is exactly the property a careless
composition would break. Plan 18-07 built the composition that preserves it: the user cap
and the environment governor compose by taking the **lower** of the two, so a cap of 0.5 on
a backgrounded tab still throttles to the background rate.

**And it reverses one recorded decision, in the open.** `browser-node.ts:885-894` says the
visibility duty cycle is *"deliberately not passed as `dutyCycle`"* to `LocalCapacity`. Plan
18-08 states the reasoning for the reversal — the pacing is the mechanism and the slot count
is the advisory statement about it, one cap seen twice — and this plan rewrites that comment
to carry it, rather than deleting a paragraph somebody wrote for a reason.

Purpose: the identical governor, the identical composition and the identical coupling on
both tiers, so nothing about a CPU cap keys on what kind of node something is.
</objective>

## Recorded decisions

- **`VisibilityGovernor` is composed with, never replaced.** BROW-03 is shipped and measured;
  the composition takes the lower of the two so a hidden tab throttles whatever the cap is.
- **The recorded decision at `browser-node.ts:885-894` is reversed in the comment that held
  it**, with the argument written out rather than the paragraph removed. Plan 18-08 states
  the same reasoning on the Node tier and the two cite each other.
- **`BrowserNode.governor` keeps its concrete type**, because the demo and an e2e read
  members only that class has. The cap governor is a second field, not a replacement.
- **Criterion 3's browser observable is a wire reading**, taken by a peer, and it is asserted
  to agree with the page's own surface.
