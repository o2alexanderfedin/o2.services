not behaviour: the code is right in each case and the reading that was supposed to hold it

**G-1 is the one that matters.** RULING A permitted criterion 2b to score PARTIAL on one
stated condition — that the missing re-pick was held as a measurement, so the clause *"turns
red the day WIRE-04 lands"* instead of surviving as a sentence in a summary. The instrument
does not meet that condition. `expect(shard.verification.agreeing).toHaveLength(1)` reads a
subset of `placement.nodeIds`, whose length **is** `redundancy` — 1 in this fixture — so the
value is structurally confined to `{0,1}` and cannot record a second attempt under any
WIRE-04 implementation. The shard it reads also succeeded on its first executor, so no retry
path would engage even if the assertion could see one. Its companion,
`expect(direct.ok).toBe(false)`, is taken on a bare `RemoteExecutor.execute()` **outside**
`submitJob`, where a retry added inside `submitJob`/`runResilient` cannot reach it.

This phase would otherwise hand Phase 20 a tripwire that had already been sprung. The
*behaviour* stays correctly scheduled to WIRE-04 / Phase 20 criterion 1 — only the instrument
is Phase 18's to fix.

*"observable in what the requestor is offered next"*. On the Node tier that observable is
measured — a peer reads `slots: 8 → 2` over tcp + noise + yamux
(`duty-cycle.node.test.ts:87-104`). On the browser tier it is argued from shared
construction, which RULING B declined in advance and which plan 18-09's own title asked for.
