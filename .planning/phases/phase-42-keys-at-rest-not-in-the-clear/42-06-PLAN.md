switch the owner asked for is read on a node nobody pressed Start for.

## What went red, and why it is a sweep rather than a repair

`42-04` made two changes that every spec driving the demo page can feel:

- `#allow` now reveals **`#signin`**, not `#main`.
- `window.o2.autoStart` **throws `SignedOutError`** when nobody has unlocked. There is no
  `writes-no-new-secret` fallback, and there is none because `consent.test.ts` requires
  `demo/main.ts` to carry **exactly one** `identityProtection` arm.

So the red files are not broken; they are driving a page whose front door moved. The sweep
teaches each of them the new door, and nothing else. **A file that goes green for a reason
other than the one `42-04`'s summary predicted for it is a finding**, not a success — say so
and stop.

## The four files that need thought, stated here so the executor does not improvise

**`artifact-fetch-gate.e2e.test.ts` — both arms keep every assertion they have, and the
change is smaller than it first looks.** The tempting rewrite is wrong and the reason is
measured: **this fixture has no relay.** Its `beforeAll` stands up a Vite server, a gateway
server on its own port and a browser, and nothing else — which is precisely *why* arm B gets
`node not started` today. Signing in does not produce a running node here; `42-04` reveals
`#main` on **unlock**, and the start that follows fails for want of a relay exactly as it
would have failed before.

So arm A is untouched — `#gate` is still the first thing rendered, the log is still empty, the
refusal still names consent. And arm B keeps `toEqual([\`/\${MODULE_CID}\`])`, keeps *"does
not contain `before you have agreed`"*, and keeps `toContain('node not started')`. **The only
change is the sign-in step between `#allow` and the fetch**, plus a docblock sentence saying
that `#main` now sits behind unlock and that the post-fetch refusal is still the blockstore
put's rather than a consent refusal.

**Do not loosen the log assertion to make anything pass** — the log is the instrument, and
widening an instrument to fit the page is the failure this file's own docblock warns about one
level up. The running-node reading is not lost by leaving it out: `42-04`'s
`signin-journey.e2e.test.ts` takes it on the visitor-enrolment harness, which has a real
relay.

**`disclosure-before-optin.e2e.test.ts:127`** asserts `#main` is visible after `#allow`. It

**`built-bundle.e2e.test.ts`** has the decline path (`:258-274`) and three `#join` clicks. Its
`isDisabled('#join')` assertions read a control inside a hidden `#main`; re-point them at the

This file runs against the **built** bundle, so it is also the one that proves `#signin`

**`visitor-enrolment.e2e.test.ts`** is where the two credentials meet, so it is where their

## The switch the owner asked for already exists, and this plan wires rather than builds it

The ruling's second follow-up asks for *"a visible switch — the panel always shows it is
running, and one click stops it."* Read before building, and all three parts are already in
the tree and already `[x]`:

- **`document.title`** carries `● Computing — ` whenever tasks are in flight
  (`packages/browser/src/computing-indicator.ts`), unconditionally rather than gated on
  `document.hidden` — and that is the requirement rather than a shortcut, because
  `background-tab.e2e.test.ts:16-42` records that Chromium under automation never reports a
  page as hidden. BROW-07.
- **`#bar`** (`index.html:1712-1718`) is rendered only while a node exists, is never
  dismissible while it does, and carries `#bar-what`, `#bar-stats` and `#stop`.
- **`#stop`** is a hard interrupt of the `Worker.terminate()` class, with CPU measured falling
  to zero. BROW-08.

So there is nothing to build. What is **new** is the trigger: every existing reading of those
three drives a node that a `#join` click started, and after `42-04` a node can exist that
nobody clicked anything for. `autostarted-switch.e2e.test.ts` reads them on that node. That is
not a re-mint of BROW-07 or BROW-08; it is the same requirements read on a path that did not
exist when they were closed.

## A consequence worth stating, and NOT planning: BENCH-06

Under `writes-no-new-secret` the demo minted a fresh key each visit, so distinct peer ids
counted **visits or tabs** — which is exactly what `BENCH-06` forbids. A sealed, reused
identity restores the per-**origin** property that `cold-start-seed-race.e2e.test.ts` (*"N tabs
opening one cold origin at once hold ONE identity"*) and `gated-seed.e2e.test.ts:60` (*"same
origin, same IndexedDB, therefore the same peer id"*) both pin, which puts the zero-network
machine-count bound back within reach.

**State it in the summary as a consequence. Do not plan `BENCH-06` work here** — that is
Phase 39's, and a phase that quietly closes another phase's criterion is a phase whose gate
nobody read.
