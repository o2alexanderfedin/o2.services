<objective>
Give this repository a vocabulary for **where an object is placed** that makes the difference
between a binding jurisdiction and a non-binding hint visible in source, and refuses an
undeclared placement value by name.

## Phase Goal

**As a** fabric operator, **I want** `bootstrap-us`, `bootstrap-eu` and `bootstrap-sam` to
exist as three identities in three objects under the closed name set, with nothing anywhere
claiming where any of them actually runs, **so that** a scheduled, repeated drill measures what
a region's loss costs instead of my discovering it during the run.

*(The three slots are quoted from `.planning/ROADMAP.md:2417` verbatim. The template's
`**I want to**` is not forced onto the owner's wording — the sentence says "I want … to
exist", and rewriting it to fit a bolding convention would edit the goal to fit the form.)*

**This plan's operator-visible slice:** after it, an operator can read one file and see that the
two placed regions are placed by two different platform mechanisms, and can watch an undeclared
placement value refused.

**Every task here is `agent-now`.** Nothing in this plan creates a Cloudflare resource, deploys,
or reaches the network.

Purpose: `HOST-06` (`.planning/REQUIREMENTS.md:2193`) states that the three regions *"must not
be created by one uniform code path that hides the difference"*. A single
`createRegion(name, placement)` taking a union and branching internally **is** that failure.
This plan supplies two separately-named helpers instead, each carrying its own literal, with no
shared parameter either of them branches on.

Output: an extended `hosted-object.ts` and extended cases in `hosted-identity.test.ts`. **No new
spec file** — so `vitest.config.ts`'s `tests` and `unitTests` move while `files` and `unitFiles`
do not. See the next section for why no new file.

## Why the new cases go in an existing file, decided rather than left open

`packages/node/src/hosted-tier-deploy.node.test.ts:198-215` pins the set of tracked `.ts` files
that **name** `idFromName` to exactly two, matching on `readFileSync(...).includes('idFromName')`
— any mention, not any call. A new spec asserting *"`idFromName` called once with
`'bootstrap-eu'`"* would be a third such file, and its spy fixture is typed
`Parameters<typeof stubFor<string>>[0]`, whose member key **is** `idFromName`. The literal is
unavoidable. A new file would therefore end this wave with a live guard red and plan 33-02
forbidding the only repair.

So the cases go into `packages/cloudflare/src/hosted-identity.test.ts`, which is already on that
permitted list, and into the block it already carries at `:191`:
`describe('criteria 4 and 6 — one call site, and a closed set of names', …)`. That block's subject
**is** the one call site and what may be handed to it, which is exactly what the placement cases
assert — this is a fit, not a convenience. No guard edit, no widening, no new file, and the
cases sit beside the `spyNamespace()` fixture they use.
