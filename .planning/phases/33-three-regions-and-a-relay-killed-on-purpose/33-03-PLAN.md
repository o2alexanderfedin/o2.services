## The instrument the criterion names cannot see the property, and this is measured

Measured 2026-09-13 against a throwaway worker on a local `wrangler dev`: `namespace.jurisdiction(v)`
throws `Error: Jurisdiction restrictions are not implemented in workerd.` for **every** `v` —
the permitted values and the hint value alike, byte-identical messages. A local arm that
"watched `sam` fail" would therefore be reporting a property of the runtime and not of the
value: a blind instrument, of exactly the kind this project has recorded catching twelve of in
one run.

So the proof moves to the earliest point at which creation code can exist, which is where the
refusal is real and discriminating: **the platform's own closed type**. The installed workerd
declares `type DurableObjectJurisdiction = "eu" | "fedramp" | "fedramp-high" | "us"`, plan 33-01
declared that union in source, and a module passing the hint value to it does not compile while
a module passing the permitted value does — in the same run, against the same compiler.

This is not a narrowing of the criterion. The criterion's stated instrument is recorded as
unable to see the property, a discriminating instrument is substituted, and the live half is
named as owner-gated rather than quietly dropped.
