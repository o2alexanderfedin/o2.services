Three deploy configurations that build, with the placement difference visible in each one, and
an owner script that can deploy exactly one of them at a time and refuses to spend before the
`HOST-10` ordering has been answered.

**This plan's operator-visible slice:** after it, an operator can run
`wrangler deploy --dry-run --outdir=<scratch>` against any of the three configurations and get a
bundle, and can read one guard that says the four things naming each region agree with each
other.

`waits on owner act 2` (`.planning/OWNER-ACTIONS.md` row 2: ≈$5/month per always-on object,
≈$15 for three, and **two regions also work** at two thirds, so the owner picks N). Nothing in
this plan deploys, and `--dry-run` needs no credential and reaches no network (measured
2026-08-26, recorded at `packages/node/src/hosted-tier-deploy.node.test.ts:20-25`).

Purpose: placement cannot be written in a wrangler configuration — measured 2026-09-13, the
`DurableObjectBindings` schema is `additionalProperties: false` over exactly `name`,
`class_name`, `script_name`, `environment`. So a region is one Worker script, one entry module,
one object name, and the configuration's job is to keep those from disagreeing.

Output: two entry modules, two configurations, an extended owner script, an extended guard, an
extended `OWNER-ACTIONS.md` row 2.

**The account subdomain is already known and needs no deploy to learn.** `wrangler.jsonc`'s own
corrected comment records it: the `workers.dev` subdomain belongs to the ACCOUNT, wrangler reads
it from `/accounts/{account_id}/workers/subdomain`, and the existing `ANNOUNCE_MULTIADDRS` names
`o2-bootstrap.af-4a0.workers.dev`. The two new addresses are therefore derivable now, and **one
deploy per region is enough**.

**A `worker-eu.ts` cannot be exercised under a local `wrangler dev`, and this is measured rather
than expected.** Its fetch handler calls `namespace.jurisdiction('eu')` on every request, and a
local `workerd` throws `Error: Jurisdiction restrictions are not implemented in workerd.` for
**every** value — `eu`, `us`, `fedramp` and `sam` alike, read 2026-09-13 off a throwaway worker
on a local `wrangler dev`. So that entry's only local verifications are the `--dry-run` build
and plan 33-01's spy-namespace spec. Say so in its docblock, or the next agent writes a boot
test and spends an hour on a `500` that is the platform and not the code. The drill in plan
33-05 is unaffected: it runs the base configuration with `--var O2_REGION`, which never reaches
`jurisdiction()`.

**`O2_REGION` does not belong in any wrangler configuration.** `scripts/deploy-hosted.sh:117-158`
derives it from `worker.ts`'s `SERVED_BY` and injects it as a `--var`, with its docblock stating
the reason: *"the region label is DERIVED from `SERVED_BY` rather than typed by whoever
remembers"*, written after the deployed object was found with `region: null` on a node that had
already relayed 143 connections for real people. A `vars.O2_REGION` entry would be a second
place the region is written, which is the defect that paragraph records.
