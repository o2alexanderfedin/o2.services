## Phase Goal

**As a** project owner, **I want to** send the first invite only after seven conditions hold on a dated
checklist with named evidence for each, and to send invites in stages by region and by cohort slice with
the funnel read between them, **so that** the fabric's headline claim is finally measured on hundreds of

<objective>
`GET /self` on the deployed node answers, read live 2026-09-04:

```
"traffic":{"direct":{"connectionSeconds":39178.906,"bytes":15958472},
           "relayed":{"connectionSeconds":0,"bytes":0}},
"relayService":{"inboundHopStreams":6715,"outboundHopStreams":0,"outboundStopStreams":53,
                "inboundStopStreams":0,"bytes":1793363,"firstInboundHopStreamAt":1788191433180}
```

**6 715 inbound hop streams against zero relayed connection-seconds and zero relayed bytes. That pair is an
anomaly and it is unexplained.**

It bears directly on criterion 4. If relayed traffic reads zero while the relay is plainly being used, then
any count of participants read off relay activity is read off a counter that does not move — and criterion 4
is a count of participants.

This plan takes the reading. It does **not** explain the anomaly from the source, and no other plan in this
phase depends on its answer.

Purpose: criterion 4 needs a defensible participant count, and a counter nobody has measured is not a source
for one.
Output: a spec that measures both counters across one relayed connection on a local `workerd`, and a dated
document recording what they were observed to count.
</objective>

```
export interface TrafficLeg { readonly connectionSeconds: number; readonly bytes: number }
export interface TrafficSplit { readonly direct: TrafficLeg; readonly relayed: TrafficLeg }
```
Counted at `trackMultiaddrConnection`, which `libp2p/dist/src/upgrader.js:140` calls on every upgrade,
inbound and outbound. `report()` adds `now - openedAt` for each live connection.

**THE HYPOTHESIS, and it is a hypothesis rather than an answer.** `TrafficSplitCounter` counts *this node's
own* connections and classifies each by its own address. Every connection the hosted relay holds is an
inbound `/tls/ws` from a client, which `classifyConnection` answers `direct` for. Traffic the relay carries
*on behalf of others* rides inside those same direct connections as hop streams, which `relayService` counts
separately. If that is right, `traffic.relayed` on a node in the relay role is zero **by construction** and
is not a defect — it is the node's own relayed traffic, of which a relay has none.

**Measure it. Do not conclude it.** Two hypotheses about a single defect have died in this repository
despite each having arithmetic that fit; a number that agrees with a theory is not the theory's proof.
