## Phase Goal

**As a** project owner, **I want to** send the first invite only after seven conditions hold on a dated
checklist with named evidence for each, and to send invites in stages by region and by cohort slice with
the funnel read between them, **so that** the fabric's headline claim is finally measured on hundreds of
independently-owned devices rather than asserted.

<objective>
Criterion 5: *"The kill switch and the stop control are exercised **during** the run and not only before it,
and the observed behaviour matches what Phase 36 measured on a quiet fabric — a control that works at three
tabs and not at three hundred is a control nobody has."*

Phase 36 measured everything on a **local `workerd`**, and its own ledger row says so: *"No deployed
reading: every measurement is local `workerd`."* So criterion 5 is not a re-run of Phase 36 — it is the same
control observed on the deployed object with a real cohort on it, compared against the quiet-fabric numbers
Phase 36 published.

The flip itself is an **owner act**: it is an operator-key write to the production object, and this project's
scope fence puts every production write on the owner's side. What an agent builds is the **instrument** — a
read-only sampler that timestamps the transition from outside — and the **comparison rule**, so the owner's
mid-run exercise produces a reading rather than an impression.

Purpose: make the mid-run exercise measurable before it happens, so the observation is not improvised while
several hundred volunteers are connected.
Output: a read-only sampler with a spec against a local `workerd`, and a dated document holding the baseline,
the band and the owner's exact script.
</objective>

```
export const PROPAGATION_WINDOW_MS = 29_880       // measured, 6 tabs, 30 000 ms poll

```
Its own docblock records the finding that makes a ratio the right comparison rather than a millisecond
figure: *"The raw window moved by very nearly the interval's own factor — 1 874 → 29 869, a factor of 15.9
against the interval's 15 — while the ratio stayed at or under 1 in both. So the window's dominant term is
the poll interval and nothing else contributes materially."*

From `packages/browser/demo/status.ts:202` — the two rendered verdicts, and there are exactly two:

From `packages/browser/demo/main.ts` via Phase 36's measurement — the volunteer-visible marker on the tab
title: `■ Not taking new work — `. Its precedence rule is deliberate: `inFlight > 0` outranks `halted`,
because *"a halted tab still draining is computing, and a title claiming otherwise is something a visitor
could catch by watching their own fan."*

From the deployed `GET /self`, read live 2026-09-04:

From Phase 36's ledger row (`.planning/REQUIREMENTS.md:1937`), the write-path facts the script must respect:
an object with no operator key refuses **every** write; a `POST` addressed to a region the object does not

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-39-28 | Spoofing | the halt write | mitigate | The operator key is required and an object with no key refuses every write; a keyless or wrong-key write is 401, and the script reads that back as a step |

| T-39-30 | Repudiation | an unobserved transition reported as instant | mitigate | `observedWindow` answers `null` and never `0` for a list that begins halted; that plant is run and its outcome recorded either way |
