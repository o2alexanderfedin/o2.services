# Phase 21 · Plan 03 — one node, both ABIs, chosen per artifact

**Requirement IDs closed by this plan:** AOT-04 (the wiring half: "a production node
constructs a real `WasiExecutor`"). The runtime proof against an artifact elfconv
actually produced is Plan 21-05; this plan builds the mechanism and gives it a
production call site with a node-level test behind it that needs no container.

<objective>
`WasiExecutor` (`packages/aot/src/wasi-executor.ts:739`) is constructed in eleven
places and every one of them is a test. `fabric-node.ts:376-379` and
`browser-node.ts:256-261` both compose `WasmExecutor` and nothing else, and neither
`@o2/node` nor `@o2/browser` even declares `@o2/aot` as a dependency — so today no
production code path can reach the class at all. A translated artifact dispatched to
a running node fails at `WebAssembly.instantiate`, naming `wasi_snapshot_preview1`,
because the only executor on the serving side does not supply it.

This plan adds `AbiExecutor`: one `Executor` over two, choosing which to delegate to
by reading the module's own declared import namespace. It is composed **innermost**
at both sites, replacing `new WasmExecutor(...)` in place, so the sovereignty gate,
the egress registration and the browser's duty-cycle governor all apply to a
translated artifact exactly as they do to a source-compiled one.

**The choice is per artifact and never per node.** This plan adds no `--wasi` flag to
`bin/agent.ts`, no second node factory, and no option. `admission.test.ts:28-36`
already settled why: a job names one `moduleCid` and the module decides the ABI;
handing either artifact to the other executor fails at instantiate, correctly, since
the runtime is the sandbox. Executor kinds are interchangeable per artifact, not
within one. Anything else would make a node's capability a property of how it was
started, which is the one thing this project does not permit.

**Say what is measured and what is not.** That this plan adds no flag is measurable —
`git diff --stat packages/node/src/bin/agent.ts` is empty when it finishes. That
*nothing else in the repository can construct a node able to run one ABI and not the
other* is **unmeasured**, and this plan does not measure it: five production sites
still build bare `WasmExecutor`s (`core/src/executor/task-worker.ts:41`,
`browser/src/task-executor.worker.ts:62`, `node/src/bin/bench.ts:146`, `:172`,
`:352`), and a note in a comment does not stop a sixth. What would measure it is a
source-scanning guard in `purity.node.test.ts`'s style, or Phase 22's reachability
guard. Neither is in scope here, and the summary must not report the design rule as
enforced.

Purpose: give `WasiExecutor` a production caller, without introducing a difference in
capability between one node and another.
Output: `AbiExecutor` exported from `@o2/aot`; both node factories composing it; a
routing spec that runs in Node and in real Chromium; and one node-level test that
fails if the `fabric-node.ts` call site is deleted, with no Docker in it.
</objective>

    `execute` does three things in this order.

    **First**, `if (task.partitionCount > MAX_PARTITIONS) return this.#native.execute(task)`
    — `MAX_PARTITIONS` imported from `@o2/core`, where it is already barrel-exported
    (`packages/core/src/index.ts:34`). This is not a duplicated check and it is not a
    second refusal: the router does not produce a reason, it hands the task straight
    to the executor that already refuses it at `wasm.ts:58-60`. The hoist exists
    because that refusal costs one integer comparison today and would cost a
    blockstore `get` — over the network, on a `FetchingBlockstore` — if the router
    read the module first. `protocol.ts:393-398` validates only that
    `partitionCount !== 0` and `partitionIndex < partitionCount`, so a peer can send
    `partitionCount: 1e9` with any `moduleCid` at all. Write that reasoning above the
    line; a reader who sees only "the native executor checks this anyway" will delete
    it.

    **Second**, read `task.moduleCid` from the blockstore. If the block is
    **undefined**, delegate to `native` and return its outcome. If
    `WebAssembly.compile` **throws**, delegate to `native` and return its outcome.

    **Third**, route on whether any entry of `WebAssembly.Module.imports(module)` has
    `module === WASI_NAMESPACE`: if so `wasi`, else `native`.

    The two delegate-on-failure branches are the load-bearing part and need their own
    comment. The router is not the component that reports a missing or malformed
    module; it reads the block before either executor does, so if it invented a reason
    of its own, every existing test asserting on a refusal *reason* would change its
    answer for a change that was supposed to be behaviour-preserving. Delegating puts
    the report back where it was.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a dispatched `moduleCid` → the host object it is instantiated against | The router decides which host object a module meets. It does not decide which imports are allowed — `WebAssembly.instantiate` does, and it names what it refused |
| the serving executor → the sovereignty gate | The router is composed innermost, so no path reaches it that has not passed `guardSovereignty`; getting the wrap order wrong would exempt translated work from a guard this project treats as unconditional |
