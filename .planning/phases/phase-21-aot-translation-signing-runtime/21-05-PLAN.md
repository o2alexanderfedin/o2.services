# Phase 21 · Plan 05 — a translated artifact completes a real job across two agent processes

> **Numbers in this plan are configuration choices, not derived claims. Any quantity
> describing runtime behaviour must be measured before it is written down anywhere,
> including in a source comment.**

**Requirement IDs closed by this plan:** AOT-04 (criterion 3 in full: "A translated
artifact produced by `tools/aot/cli.ts`, dispatched to a live node started via
`bin/agent.ts`, executes successfully — the node constructs a real `WasiExecutor` in
production, completing the same admission and verification path as a source-compiled
module").

<objective>
Plan 21-03 gave `WasiExecutor` a production call site and proved it with a
hand-written fixture inside one process. Plan 21-04 produced an artifact elfconv
actually emitted that can finish a task. This plan puts the two together across a
real process boundary and, more importantly, makes the claim *falsifiable*.

**"The node constructs a real `WasiExecutor` in production" is the one clause that
cannot be measured by asserting on a type.** After `guardSovereignty`,
`registerSovereignInputs` and (in the browser) `GovernedExecutor` have wrapped the
executor three deep, `node.executor instanceof …` proves nothing. What does measure
it is an equality: a translated artifact **cannot** produce a fabric result through
`WasmExecutor` at all — it fails at instantiate, naming `wasi_snapshot_preview1` —
so a job that completes over a lifted artifact and agrees field for field with the
source-compiled run can only have gone through the WASI path. That equality, plus a
planted mutation watched failing, is the proof.

Purpose: close the criterion in the evidentiary form it names, and leave behind a
number for the one question the criterion routes around rather than answers.
Output: `packages/node/src/aot-dispatch.node.test.ts`, and two mutation captures.
</objective>

## Out of scope

- **Cross-machine anything.** Two OS processes on one host is this project's testing
  standard. `CROSS_MACHINE_BLIND_SPOT` stays attached to every artifact and stays
  printed by the CLI.
- **A browser-tier runtime proof of the translated path.** The composition landed in
  Plan 21-03 and is structurally present and unmeasured; running it in a real tab
  needs the multi-browser standard recorded under WIRE-03 and belongs with that work.
- **Memoising the router's per-module decision.** Deferred on the resource bound, not
  on difficulty — Plan 21-03 records the reason.
- **Signing the artifact CID.** Phase 14. This phase produces an `artifactCid` that
  Phase 14's `signName` path can later name, and deliberately invents no second
  notion of a trusted artifact.
- **Making `bin/bench.ts` route.** It constructs `WasmExecutor` directly at three
  sites and keeps the native-only path deliberately, because the benchmark measures
  the native ABI. Plan 21-03 records that answer in `fabric-node.ts` so Phase 22 does
  not rediscover it as a finding.
- **The sovereignty path.** The shards are `public`; no sovereign label is set
  anywhere in this spec, so `guardSovereignty` and `registerSovereignInputs` are
  traversed and no-op. Stated so a reader does not assume the sovereignty path was
  exercised here. It was not, and DATA-09's own spec at
  `fabric-node.node.test.ts:228` is where it is.
