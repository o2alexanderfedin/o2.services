# Phase 21 · Plan 02 — the operator sees the name, and the borrowed name is refused

> **Numbers in this plan are configuration choices, not derived claims. Any quantity
> describing runtime behaviour must be measured before it is written down anywhere,
> including in a source comment.**

**Requirement IDs closed by this plan:** AOT-02 (the emission and refusal halves:
"the CLI prints that CID to the operator", and "re-tagging a local image under a
different name and pointing the CLI at it is refused rather than hashed under the
borrowed name").

<objective>
Plan 21-01 made the name exist. Two things stand between that and the criterion.

**The name is not printed.** `describeLift` (`lift.ts:838-873`) is the one string the
CLI writes to stdout, and it renders the target, the size, the verdict, the feature
set, every toolchain version, every finding and every blind spot — and not the CID.
The CID belongs *inside* that string, for the reason the function's own comment
gives: one string rather than a struct a caller renders piecemeal, so the
reservations survive being copied. A CID printed beside it in `main` is a CID that
gets separated from its reservations the first time somebody quotes one of them.

**The CLI cannot be pointed at anything.** `LiftOptions.image` and
`LiftOptions.docker` exist and carry the comments "Overridable so a test can point at
a tag that does not exist" and "…that is not Docker" (`lift.ts:319-327`), and
`main()` passes neither (`cli.ts:139-141`). The roadmap's second criterion says
"*pointing the CLI at it* is refused" — so the refusal is currently reachable from
`resolveImage`'s unit spec and from nowhere a person could type. Two words of argv
close that, and the payoff is that the refusal becomes measurable **on a host with no
elfconv image at all**.

Purpose: a refusal nobody can reach from the command line is a refusal that will be
removed by somebody simplifying the option surface. A CID nobody prints is the state
`translationCid` was in for a whole phase.
Output: `describeLift` carrying the emitted CID; `--image` and `--docker` on
`parseAotArgs`; and `cli.node.test.ts` spawning the real program for both halves —
the printed CID against a stub lift, and the refusal against a stub emitting foreign
digests, plus a real `docker tag` re-tag on a host that has the image.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| argv → the container that runs | `--image` and `--docker` let a caller choose both the toolchain image and the program that runs it. This is a build-time tool run by the repository's sole author on their own machine; the flags widen no boundary that `docker` itself does not already offer to the same person. `--docker` runs whatever the caller typed, with the caller's own privileges, on the caller's own machine — recorded here rather than left to be rediscovered as a finding |
| a local image tag → the toolchain it names | The one boundary this plan is about. A tag is mutable; `RepoDigests` is not. The refusal already existed and was unreachable from the command line, which is the state this plan ends |
</threat_model>
