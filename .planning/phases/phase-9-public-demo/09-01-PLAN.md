# Phase 9 — Plan 1 of 1: Public Demo, Consent UX & Disclosure Gate

**Mode:** mvp — vertical slices, each ending in something a visitor can see.
**Requirements:** DEMO-01, DEMO-02, DEMO-03, DEMO-04, BROW-01, BROW-02, BROW-04

## The ordering is load-bearing

Criterion 3 forbids spending CPU before consent exists, so the gate is built first and
everything else starts behind it. Slice B follows immediately because *"one click drops
CPU to zero"* is unachievable as the code stands: `BrowserNode` runs `WasmExecutor` on
the main thread, so an in-flight WASM call cannot be interrupted by anything. Stopping a
node that is mid-task today lowers CPU when the task ends, which is not what the
criterion says.

## Slice A — The consent gate (BROW-01)

- `packages/browser/src/disclosure.ts` — the disclosed terms as structured data with a
  version. Text lives beside the version so the two cannot drift.
- `packages/browser/src/consent.ts` — `ConsentStore` port (default `localStorage`),
  `readConsent`, `grantConsent`, `revokeConsent`. A stored grant records the disclosure
  version it answered; a version change invalidates it.
- **Structural, not procedural:** the value that proves consent is a token type only
  `grantConsent` can mint, and the demo's start path takes it as a parameter. A caller
  cannot start a node without holding one, so "check consent before starting" is not a
  rule anyone has to remember.
- Tests: portable unit tests with an injected store; an e2e test that clicks Start
  before consenting and asserts no node exists and no request left the page.

## Slice B — Worker-backed execution and a real Stop (BROW-04)

- `packages/browser/src/task-worker.ts` — a dedicated Worker running `WasmExecutor`
  over a `MemoryBlockstore` seeded from the posted module and input bytes.
- `packages/browser/src/worker-executor.ts` — `WorkerExecutor implements Executor`,
  constructed over an injected `() => Worker` so it is testable without a bundler.
  `terminate()` kills the thread and rejects everything in flight.
- `BrowserNode` gains `stop()` semantics that terminate the worker *and* close the
  connections.
- **Mutation test:** replace `terminate()` with a cooperative flag and require the
  suite to fail. A guard is worth nothing until a mutation proves it can fail.

## Slice C — The always-visible surface (BROW-04)

- A fixed bar in `demo/index.html`, not dismissible while running: what is running,
  whose job, live duty cycle, tasks completed, bytes sent.
- `VisibilityGovernor.onVisibilityChange` drives the throttle readout, so a visitor who
  switches tabs *watches* the guarantee rather than reading about it.
- `TabApi` gains an activity accessor; e2e asserts the bar exists, updates, and that
  Stop empties it.

## Slice D — The job, and checking it (DEMO-01, DEMO-02)

New portable package `packages/demo` — added to `PORTABLE` in `purity.node.test.ts`.

- `triples.ts` — enumerate every `a² + b² = c²` with `c ≤ N`, sorted by `c`. Used by
  the host to build the input block **and** independently by the verifier.
- `colouring.ts` — `verifyColouring(n, bits)`: checks a claimed colouring against the
  definition, in the visitor's own tab, trusting no node and no input block.
- `kernel.wat` → `kernel.wasm`, compiled by `wabt` at build time, committed, with a
  test that recompiles and requires byte-identity. A committed artifact that nothing
  checks is a claim about the source beside it.
- Guest contract: input is the triple list plus a deterministic backtrack budget; the
  shard's cube is derived from `partition()`, so shards need no distinguishing input.
  Output is `{status, colouring}` — found, exhausted, or budget-reached. All three are
  results; only exhaustion of every cube proves impossibility.
- `job.ts` — build the `JobSpec`, and pick the answer out of the shard results.

## Slice E — Start-failure reporting (BROW-02)

- `packages/core/src/start-outcome.ts` — the enumerated causes, the record, and the
  aggregation. **The unreported population is a field**, so a report cannot be rendered
  without stating what it could not see.
- `packages/browser/src/browser-id.ts` — coarse family plus major version from a fixed
  enumerated set, with `other` as the fallback. Not a UA string.
- A `report` RPC kind in `@o2/net/protocol.ts`: one round trip both publishes an
  outcome and returns the aggregate. Any node serves it — all nodes are equal.

## Slice F — Static hosting and the disclosure gate (DEMO-03, DEMO-04)

- `build:demo` npm script. **No deploy script**, and no workflow file.
- `disclosure-gate.node.test.ts` — asserts `.github/workflows` does not exist and that
  no script in any `package.json` publishes anything.
- `vocabulary.node.test.ts` — repository-wide, with expressible exceptions for ordinary
  English and for the security sense of "token". A rule that cannot state its own
  exceptions gets deleted the first time it fires wrongly.
- Fix the one existing violation: `docs/p2p-native-cloud-design.md` §3.8.
- `demo/policy.html` — written for a human reviewing a blocklist submission.
- Update `built-bundle.e2e.test.ts`, which asserts on the markup this phase changes.

## Verification

Each slice lands with tests. The phase is done when: no CPU or network before consent
(e2e), Stop terminates a real Worker (mutation-tested), a colouring the fabric produced
verifies in the page from the definition, the start-outcome report states its blind
spot, and the repository still contains no deploy workflow file.
