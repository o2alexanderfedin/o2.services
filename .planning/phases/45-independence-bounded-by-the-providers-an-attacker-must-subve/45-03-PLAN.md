Create `packages/node/src/attestation-claims.node.test.ts`. Node-only: it reads real source
off disk by repo-relative path.

**The corpus.** Build it from `trackedPaths(ROOT)` filtered to paths under `packages/` ending
`.ts` or `.tsx`, minus anything matching `.test.ts`, `.test.tsx`, `.node.test.ts`,
`.browser.test.ts`, `.e2e.test.ts`, `.perf.test.ts`. Also include `packages/browser/demo/**`
`.ts` files, which are source and are not under a `src/` directory. Run every file's text
through `stripComments` before scanning, so a comment naming a literal is never a finding.

**What it forbids.** Findings are, over stripped text:

1. A comparison of anything against one of the four strength literals, in either operand
   order: the four literals `owner-attested`, `owner-domain`, `single-issuer`, `independent`
   adjacent to `===`, `!==`, `==` or `!=`.
2. A `case` label naming one of the four.
3. A `switch` whose discriminant is an expression ending `.strength` — the shape that would
   reintroduce the same coupling without any of the operators above.

**How the four literals are written into this file matters.** Compose them from a single
exported-shaped constant list declared once at the top with a stated reason, so the file names
each string exactly once and a fifth strength added later is one edit. Do not scatter them.

**The exemption — one ENTRY, and its shape is specified rather than left to taste.**
`packages/core/src/quorum.ts`'s two exhaustive switches — `attestationRank` and
`describeAttestation` — are the **definition** of the ordering and the words, not a caller
comparing against them, so their `case` labels are exempt.

**A per-line entry cannot express this and must not be attempted.** Measured: `quorum.ts` yields
**6** case-label findings today (`:129/131/133` and `:141/143/145`) and **8** after 45-01 inserts
the fourth strength into both switches. One `{ file, phrase, reason }` row in
`vocabulary.node.test.ts`'s line-exemption shape covers one line, so eight rows would be needed
and each would die the moment a sentence was re-wrapped. So the entry is **scoped to the two
function names**: a single record naming `packages/core/src/quorum.ts` and the enclosing
functions `attestationRank` and `describeAttestation`, with findings inside either function
body suppressed and findings anywhere else in that file still reported. Implement the scoping by
locating each function's `export function <name>` line and its closing brace and testing whether
a finding's line falls between them — not by a line number, which drifts on the first edit.

Give the entry a stated reason of more than 20 characters, and hold it to a **dead-exemption
check** in `vocabulary.node.test.ts`'s form: if neither named function still produces findings,
the entry is dead and must be deleted, and a case says so. The narrowing this buys is the point
— a **new** string comparison added to `quorum.ts` anywhere outside those two function bodies is
still a finding, which a path-shaped exemption would have hidden.

`packages/node/src/mutation-ledger.ts` must pass with **no** exemption — its `find`/`replace`/
`signature` strings are data about mutations, not comparisons, and the patterns above do not
match them. Assert that as its own named case, so a later widening of the patterns that starts
catching the ledger is a red rather than a silent new exemption.

**The cases that make this a proof rather than an empty read.**

- *The scan is alive*: the corpus is non-empty, holds more than 50 files, and contains
  `packages/core/src/quorum.ts`, `packages/net/src/reduce-job.ts` and
  `packages/core/src/job/submit.ts` by name. A wrong `ROOT` or a wrong glob would otherwise
  report the tree clean for a reason that has nothing to do with the tree.
- *The guard is not in its own corpus*: assert `packages/node/src/attestation-claims.node.test.ts`
  is absent from the corpus, with a comment saying this is why no exemption for its own prose
  exists and why none may be added.
- *The checker can fail — positive control.* Run the same checker function over synthetic
  source strings and require a finding from each: `if (receipt.strength === 'independent') {}`,
  `const weak = a.strength !== 'owner-domain'`, `switch (receipt.strength) { case 'single-issuer': }`.
  Require **three** findings, written as the literal 3 and not as the length of the fixture
  array — an assertion that reuses the value it tests moves with it.
- *The checker does not over-fire — negative control.* Require **no** finding from
  `attestationRank(a.strength) < attestationRank(b.strength)`, from
  `const s: AttestationStrength = 'independent'` (an annotation is not a comparison), and from
  a comment containing all four literals.
- *The property the criterion is actually about, asserted positively.* `reduce-job.ts` and
  `submit.ts` each contain `attestationRank(` — so "nothing compares by literal" cannot pass by
  nothing comparing at all.
- *Rank ordering across the insertion*, read from the module rather than transcribed:
  `attestationRank` is strictly increasing over `['owner-attested', 'owner-domain',
  'single-issuer', 'independent']` in that order, and the four ranks are four distinct numbers.

Report findings through `blocking('attestation-claims/…', findings, SCOPE)` with
`SCOPE = commitScope()`, attributing each finding to the union of the offending path and this
file — the participants rule `mutation-guard.node.test.ts:56-68` states. Run every path the
guard emits through `pathFormProblems` in a case, so a finding can actually match a commit
scope.
