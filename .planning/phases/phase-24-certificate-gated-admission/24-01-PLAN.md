`FabricNodeOptions.trustedIssuers?: readonly PublicKeyHex[]` **already exists** and is the only
input to `PeerVerifier.start`'s `trustedIssuers: new Set(options.trustedIssuers ?? [])`. Nothing
above `FabricNode` can set it on a seed.

`SeedServerOptions` — six fields: `httpPort?`, `wsPort?`, `blockstoreDir`, `trustAnchors`,
`maxReservations?`, `allowedHosts?`. `trustAnchors` is documented as *"the build authorities this
seed's node will run a module for — DET-03, DATA-08"*. **It is not an issuer set and must not be
overloaded into one.**

`bin/seed.ts` parses `'trust-anchor': { type: 'string', multiple: true }` and defaults to
`[KERNEL_TRUST_ANCHOR]`. **That default line is asserted in both its branches by
`trust-anchors.node.test.ts`** — read that test before touching the surrounding output.

`fabric-node.ts` constructs `circuitRelayServer({ reservations: { maxReservations, reservationTtl,
defaultDurationLimit, defaultDataLimit } })` under a `canRelay` spread, inside the `services` block
of `createLibp2p`. `createLibp2p` also takes a top-level `connectionGater` — `browser-node.ts` is
the only site in the tree that passes one today.

`peer-verifier.ts` imports `verifyCertificate` from `@o2/core` plus `@libp2p/interface` types,
`@o2/libp2p` and `@o2/net`. Its own header states the move to `@o2/net` is *"a barrel change with
no code change"*. **Verify that import list yourself** — if it has acquired a Node-only import
since that sentence was written, the move is not a barrel change and this task changes shape.

The established named-union sentinels to copy, and the guard idiom that pins them:
`'keeps-no-ledger'`, `'serves-no-records'`, `'signs-nothing'`, `'relays-for-nobody'`,
`'checks-no-combine-signatures'`, `'carries-no-certificate'`. `serve-agent-hooks.node.test.ts`
count-pins several of them per file and **its own comment records that a needle can match inside a
longer line** (`index: records` matches inside `index: records ?? 'serves-no-records'`).
