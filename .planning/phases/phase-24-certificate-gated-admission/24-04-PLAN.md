# Phase 24 · Plan 04 — Read the criterion, and measure what it does not fix

**Closes:** criterion 1 — *"a node that cannot present a provider-issued certificate cannot join the
fabric, advertise itself, or be dialled by another node"* — and the residual the criterion's own
rationale requires be pinned rather than argued away.

<objective>
Three plans built a door. This one is the only plan entitled to say it works, and the criterion has
**three separate clauses** — join, advertise, be dialled. 24-03 measured the first at close range
and made a **structural claim** about the other two: that `BootstrapInfo.peerAddrs` and `agent.ts`'s
`reservations` answer are both derived from `node.reservedPeerIds`, so a peer that never reserved
cannot appear in either. **A structural claim is a hypothesis until something reads it**, and this
is where it gets read — across real `bin/agent.ts` processes, not in a unit fixture, because
`reservedPeerIds` is in-process state and an in-process reading would be asking the same object
twice.

And there is a fourth thing to measure, which is the honest part: **this phase does not stop a
provider spending CPU refusing enrolments.** It cannot — enrolment must stay open, because it is how
a node gets its first certificate. What changes is that the attacker gains **no foothold** for it.
Phase 19 measured the old ratios (refuse-over-mint ~3.0, refuse-over-replay ~1397). Those numbers do
not improve here and **must not be presented as if they did**. What improves is what the minted
identity is worth, and that is a different measurement.
</objective>
