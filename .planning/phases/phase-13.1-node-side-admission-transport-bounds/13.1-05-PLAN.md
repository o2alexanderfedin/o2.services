## Execution order and shared-tree safety

**Wave 4, and wave 4 contains only this plan.** Every wave in phase 13.1 is one plan wide,
because three of the five plans plant mutations into production source and verify while the
mutation is live. This plan mutates `packages/node/src/fabric-node.ts`; Plan 13.1-03 mutates
`packages/net/src/agent.ts` and Plan 13.1-01 mutates `agent.ts` and `placement.ts`. Run
concurrently, each would read the others' planted edits as its own failure. Order:
01 → 02 → 03 → 05 → 04.

**No task in this plan may run a `git` command that writes** — not `checkout`, `add`,
`commit`, `stash`, `reset`, or `branch`. Task 2 restores its planted file by `cp` from the
session scratch directory and verifies with `cmp`. `git checkout -- packages/node/src/fabric-node.ts`
restores from the index and would discard Task 1's entire wiring along with the mutation,
then report a clean tree as success — which would satisfy this plan's `done` block with a
file that no longer contains the feature.

## Cross-phase file contention

This plan sits on the phase's worst hotspots. `packages/node/src/fabric-node.ts` and
`packages/browser/src/browser-node.ts` are each edited by phases 13.1, 14, 15, 17 and 21, all
inside the same options object and the same `serveAgent(...)` call.
`packages/node/src/bin/bench.ts` is edited by 13.1, 14, 15, 16, 17 and 23.
`.planning/ROADMAP.md` is edited by 13.1 and 15 as an explicit deliverable, and by GSD's
