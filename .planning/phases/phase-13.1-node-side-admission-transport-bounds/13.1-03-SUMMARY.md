## What changed

`EgressGuard` gained the two members `serveAgent` needed and did not have:

- **`violationIn(frame)`** — the old private `#scan`, promoted. A pure query: it
  records nothing, so it can be asked about a frame that has not been offered to the
  exit. Its doc carries the sensitivity argument, because a reader will ask why
  scanning a reply *body* is enough when `send` scans the whole encoded frame:
  `contains` is a contiguous-run search and dag-cbor encodes a byte string as a
  header followed by the raw bytes, so a payload in the body is the same contiguous
  run once nested in the frame. The pre-scan is not a weaker check; it is the same
  check, earlier.
- **`refuse(to, frame)`** — the same query with the answer recorded, for a caller
  that will substitute a smaller frame. Records **only** on a hit, which is the one
  asymmetry with `send`, and the reason is in source: `send` is the node's sole exit
  and must account for every frame that crossed it, while `refuse` is asked about a
  frame that may never be offered — recording clean answers would count every reply
  twice.
- **`#record`** is now the single place an `EgressEntry` is constructed. Two
  producers reach it, so they cannot drift about what a refusal looks like on the
  manifest. An entry from `refuse` is asserted deep-equal to one from `send`.

`serveAgent` now asks that question on both branches whose reply can carry a
registered payload, through one local helper that also owns the reason string:

```
egress refused: <label> on <nodeId>
```

- **exec branch** → substitutes `{kind:'exec', outcome:{ok:false, reason}}`, a
  **task** condition, so `churn.ts` classifies it against
  `DEFAULT_MAX_TASK_FAILURES` rather than condemning the node.
- **block branch** → substitutes `{kind:'error', reason}`, per 13.1-CONTEXT.md
  decision 4 and the owner ruling of 2026-07-28 recorded in `egress.ts`.

`rpc.ts` is unchanged. Its responding leg still swallows a send failure by design;
`egress.ts`'s class comment now states that as a rule **with a named exception and
its scope** rather than being left contradicted.

   repo-wide `npx tsc --noEmit`, which exits 0.

  tell a pre-scan from the exit doing its job. Both counters exist and both are read —
  `scans > 0` is the proof the instrument was live for the `prescans === 0` reading.

## What this does not close, stated plainly

- **A sovereign block refused at rest, indefinitely.** The registration is
  job-scoped. A peer asking for the same block after the job gets the raw bytes.
  Closing it needs a persistent per-node set of sovereign CIDs surviving the job and
  the process; 13.1-CONTEXT.md already lists it as deferred, and nothing here implies
  otherwise.
- **DATA-10, the submitter-side registration.** Plan 13.1-04, which depends on this
  plan's `violationIn` and block-branch refusal.
- **`RpcBlockSource.fetch` degrades a refusal to a miss.** Any non-`block` reply
  sends it to the next peer, so a multi-peer fetch degrades rather than loops while a
  caller that asked one node directly gets a named reason. That is the shape the owner
  ruling of 2026-07-28 accepts, and the block branch's comment cites it rather than
  re-deriving it.
