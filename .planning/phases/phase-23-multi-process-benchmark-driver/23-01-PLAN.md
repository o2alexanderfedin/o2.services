# Phase 23 · Plan 01 — Pre-registration amendment, declared provenance, and the integrity checker

> **Numbers in this plan are configuration choices, not derived claims. Any quantity
> describing runtime behaviour must be measured before it is written down anywhere,
> including in a source comment.**

> **Cite by grep-able symbol, never by line number.** This is not style. Forty-one of
> forty-six citations in this repository had rotted when they were last counted; six more
> rotted inside the very plan written to correct that drift; six more were found in the
> 2026-08-05 audit of this phase's own first plan set. A line-citing plan produces the
> seventh generation. Every reference below names a symbol a reader can grep.

> **Every proof named below states the mutation that reddens it.** A proof that cannot fail
> is not a proof — two criteria in this repository have been carried at PARTIAL because
> their instruments turned out to be tautologies. If a step in this plan specifies an
> assertion with no stated mutation, the step is incomplete and the executor should say so
> rather than record a green.

**Closes:** BENCH-07 (criterion 4's structural half, and the mechanism criterion 1 is checked
by), under BENCH-06's reporting discipline. **Wave 1. Depends on nothing.**

**Amended 2026-08-05.** The 2026-07-29 version of this plan was written against `SHARDS = 8`
and pre-registered an ideal speedup of `6.3×` derived from an eight-partition measurement.
`SHARDS` is `16`. Both figures are withdrawn here, and this plan no longer carries any
per-shard number at all — see Task 1. The plan also gains the declared dimension criterion 5
needs, which did not exist when the first version was written because criterion 5 did not.

<objective>
Four things have to exist before the multi-process driver can publish anything honest, and
none of them needs the driver.

1. **The amendment.** `.planning/BENCHMARK-METHODOLOGY.md` reserves an `## Amendments`
   section and says in its own preamble that changes to the pre-registered plan go there,
   dated, with the reason. Phase 23 changes the plan in four ways — a second fixture, a
   third driver, a fixed-redundancy speedup sweep, and an opt-in dispatch leg. Writing them
   into the plan body would defeat the ordering property BENCH-02 exists for; writing them
   *after* the run would defeat it more thoroughly. This plan is wave 1 and the run is wave
   5, so the ordering is a fact about `git log` rather than an intention.
2. **The declared dimensions.** `RunConfig` already carries `transport` and `skew` — data
   that is rendered nowhere and travels everywhere, into `SweepResult` and thence into
   `.planning/bench/raw.json`. `driver`, `fixture` and `leg` join them as **required**
   fields, for the same reason `Inventory.machines` is required: a figure that *can* be
   published without its provenance eventually is.
3. **The checker.** Criterion 1 requires that a run which silently falls back to in-process
   nodes fails the harness rather than reporting a curve. That check has to be a pure
   function over plain data, because `bin/bench.ts` runs `main()` on import and nothing in
   CI will ever execute it (23-CONTEXT.md `<constraints>`). A guard nobody has watched fail
   is worth nothing, so the checker ships with planted inputs proving each of its readings
   can report — including the two cardinality readings that stop an *absent* instrument from
   being mistaken for a clean rung, and one gate function so there is exactly one place a
   rung's verdict is consumed.
4. **A tax that cannot silently collapse.** `connectivityTax` keys a `Map` on
   `config.nodes`, so two curves appended into one array lose a rung with no error.

Purpose: make provenance structural instead of editorial, and make "the harness is not
measuring what it says it is" an error class rather than a hope.
Output: four dated amendment entries; three new required `RunConfig` fields rendered as
columns and headings; a `multiProcess` curve the report knows how to render; a
`connectivityTax` that refuses to silently collapse two drivers into one row; and
`@o2/bench`'s `integrity.ts`, barrel-exported and wired by Plan 23-03.

**Scope note on the checker's reach, stated because it bounds what Plan 23-03 can claim.**
Every function here is pure and every one of them is proved by planting an input and
watching it report. What that does *not* prove is that the driver builds its observation
from the live fabric rather than from a constant — nothing executes `bin/bench.ts` in any
suite (`main()` runs on import), so the wiring is held by a source-shape guard and by the
call-site count in Plan 23-03, not by an execution. That half is **unmeasured**; what would
measure it is an entry point that runs one rung under a stub fabric with a planted defect
and asserts the abort, which needs `main()` split from the module body and is not this
phase's work.
</objective>
