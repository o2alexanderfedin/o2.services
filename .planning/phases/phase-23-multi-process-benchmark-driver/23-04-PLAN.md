# Phase 23 · Plan 04 — The excluded rungs, measured instead of asserted

> **Numbers in this plan are configuration choices, not derived claims. Any quantity
> describing runtime behaviour must be measured before it is written down anywhere,
> including in a source comment.**

**Closes:** BENCH-07 criterion 3, and the half of criterion 4 that says an excluded row is a
published figure too. **Wave 3. Depends on Plan 23-03.**

<objective>
`bin/bench.ts:408-431` wraps `measure(...)` in a `try`/`catch` and converts every error it
catches into an excluded row whose reason is a stored paragraph asserting that libp2p's
per-host inbound cap of five killed the handshake. The paragraph is attached without
inspecting the error beyond interpolating its message. **Criterion 3 cannot be satisfied by
that shape at all**: it asks for a measurement showing the cap is the cause, and the code
asserts that cause for every failure mode there is.

There is a second reason to distrust the stored paragraph, measured while this phase's
context was gathered. A default `FabricNode` on this machine reports
`inboundConnectionThreshold: 15` today, not the 5 the published exclusion names — the
coupling that derives it from the reservation limit landed in `f879b9d` (2026-07-27), and
the harness commit that produced the excluded rungs is `677a6d2` (2026-07-26), an ancestor.
The published exclusion is describing a version of the code that no longer exists. So "the
cap is still the cause" is not the expected answer here; it is one of the possible answers,
and only a measurement can say which one is true.

Three independent levers exist and only one of them is what BENCH-07 is about: raise the
option, stagger the joins, or change which side receives the dials. Adopting the spawn
pattern changes the dial direction *and* the process split at once. This plan separates
them: seven attempts at the 8- and 16-node rungs, one variable at a time, each recording what
happened and the configuration it happened under.

**Why seven and not five, corrected against the source.** An earlier draft of this plan
called attempt E — process-per-node, submitter dialling outward, the cap pinned to five on
every agent — "D's cap control". It is not one. Under that dial direction the submitting node
is the dialler and each agent is a dial target, so the population
`inboundConnectionThreshold` governs — it is a per-second rate *per host*
(`fabric-node.ts:294-301`, `LIBP2P_INBOUND_CONNECTION_THRESHOLD` at
`libp2p/src/constants.ts:65`, and the option's own doc at `fabric-node.ts:164-173`) — sits on
the agent side and arrives from one host. The submitting node is dialled by nobody, because
`Libp2pTransport.send` reaches a peer with `dialProtocol(peerIdFromString(to))`
(`libp2p-transport.ts:122-126`) and reuses the connection whichever side opened it — which is
why the three existing spawn tests complete jobs without any worker ever dialling in.
**How many inbound connections either side ends up with under that direction is a quantity
this plan does not derive.** E's outcome is recorded as an observation and labelled as one;
whether the cap it pins was ever exercised is not established by an argument about dial
counts, and Task 3 says so in the published table.

Criterion 3 asks specifically for a measurement showing the cap is still the cause **under
separate processes**. That needs a process-per-node cell in which many peers on one host dial
one node — i.e. workers dialling the submitter, which is exactly the arrangement Phase 8's
excluded rungs died in. No such cell existed. Attempts F and G add it, E is relabelled as
what it is, and 23-CONTEXT.md's criterion-3 table (which carries the same wrong label) is
superseded by the table in Task 3 below.

Purpose: make a published exclusion a record of an observation rather than a claim carried
forward, and find out whether these two rungs still fail at all.
Output: `describeExclusion` in `@o2/bench` with a production caller; an agent that can be
given an inbound limit and a dial target and that announces the limits it actually ended up
with; a `processFabric` that can be built in either dial direction with the cap pinned on
whichever node receives the dials; and a seven-cell factorial at the two disputed rungs whose
result is published in whichever of the two honest forms the evidence supports — including
the form that says the block reproduced nothing and therefore measured nothing about the
original cause.
</objective>
