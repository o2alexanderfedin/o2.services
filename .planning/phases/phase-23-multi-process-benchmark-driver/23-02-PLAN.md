# Phase 23 · Plan 02 — The agent announces its pid, and the fabric that spawns N of them

> **Numbers in this plan are configuration choices, not derived claims. Any quantity
> describing runtime behaviour must be measured before it is written down anywhere,
> including in a source comment.**

> **Cite by grep-able symbol, never by line number.** Forty-one of forty-six citations in
> this repository had rotted when they were last counted; six more rotted inside the plan
> written to correct that drift; the 2026-08-05 audit of this phase's first plan set found
> six more, and the previous version of *this* plan cited a `Fabric` interface with five
> fields that has ten. Every reference below names a symbol a reader can grep.

> **Every proof named below states the mutation that reddens it.** A proof that cannot fail
> is not a proof.

**Closes:** BENCH-07 (criterion 1's mechanism — N operating-system processes, verifiable by
reading the child pids). **Wave 1. Depends on nothing.**

**Amended 2026-08-05, and three of the amendments matter.**

1. The `Fabric` seam is **ten members**, not the five this plan used to reproduce. A
   `processFabric` returning five would not type-check.
2. `stdio` is `['pipe','pipe','pipe']`, not `['ignore','pipe','pipe']`. `'ignore'` puts
   `/dev/null` on fd 0, which is this repository's orphan leash — the previous shape would
   have leaked agent processes out of every benchmark run.
3. The claim that `--port` now has no default and therefore breaks a bare spawn is
   **retracted**. A bare `--dir` spawn still binds `/ip4/127.0.0.1/tcp/0`. The surviving rule
   is narrower and is stated in Task 2.

<objective>
`bin/bench.ts` builds every node in both published curves inside its own process.
`realFabric` calls `FabricNode.start(...)` in a loop, so N libp2p nodes share one V8 isolate
and one event loop, and `WasmExecutor.execute` is synchronous CPU work inside that loop —
which is why the published makespan column is flat across 1, 2, 4, 8, 16 and why the report
says so in its own opening section.

The remedy already exists in this repository, built for an unrelated reason. Roughly twenty
node-tier specs spawn real `bin/agent.ts` child processes and drive jobs across the boundary,
and they all share one `spawnAgent` shape. This plan turns that shape into a module the
benchmark driver can call, and adds the one field that makes criterion 1's check possible:
`child.pid` proves *a* process was spawned, not that the process which announced the address
is that process. One extra key on the handshake line closes it.

Deliberately **not** in `bin/bench.ts`. That file runs `main()` on import, so anything living
there can only ever be checked by reading its source text. A module can be spawned, dialled
and driven by a real job in a real test — which is the difference between "the wiring is still
written down" and "the wiring works".

Purpose: make "N nodes" mean N operating-system processes, and make that claim checkable.
Output: `pid` on the agent handshake; `packages/node/src/bench-fabric.ts` exporting the
ten-member `Fabric` seam, `spawnAgent`, `stopAgent` and `processFabric`; and a test that
spawns two real agents, runs a real job over them, and reads every identity the checker in
Plan 23-01 will be given.
</objective>

**`packages/node/src/bin/agent.ts` — the handshake, as it stands.** One JSON line on stdout,
carrying **nine** keys:

```ts
process.stdout.write(
  `${JSON.stringify({
    peerId: node.peerId,
    multiaddrs: node.multiaddrs,
    trustAnchors,
    nodeKey: node.nodeKey,
    certificate: node.certificate,
    issuerKey: node.issuerKey,
    peers,
    dutyCycle: node.dutyCycle,
    relays: node.circuitAddrs,
  })}\n`,
)
```

Every existing reader destructures `{peerId, multiaddrs}` and ignores the other seven, which
is what makes a tenth key additive by construction.

**Its flags are sixteen, not four**: `--dir` (required), `--port`, `--owner-id`,
`--owner-key`, `--can-execute-sovereign`, `--trust-anchor`, `--provider-addr`, `--user-key`,
`--operator-id`, `--trusted-issuer`, `--peer-addr`, `--max-concurrent-tasks`, `--duty-cycle`,
`--issues-certificates`, `--max-issued-per-window`, `--relay-addr`. The `USAGE` string in that
file is the authoritative grammar.

**The `listen` table, which the previous version of this plan got wrong.** `values.port`
present ⇒ that port; absent with no `--relay-addr` ⇒ `/ip4/127.0.0.1/tcp/0`; absent **with**
`--relay-addr` ⇒ binds nothing. So a bare `spawn(process.execPath, [AGENT, '--dir', dir])`
binds a port exactly as it always did. **The rule that survives: state `--port 0` whenever
`--relay-addr` is stated.**

**`packages/node/src/two-process.node.test.ts` — the spawn shape to lift**, by symbol
(`spawnAgent`, `stopAgent`):

```ts
const AGENT = fileURLToPath(new URL('./bin/agent.ts', import.meta.url))
type AgentProcess = ChildProcessByStdio<Writable, Readable, Readable>

const child: AgentProcess = spawn(
  process.execPath,
  [AGENT, '--dir', dir, '--trust-anchor', publisher.pub, ...extraArgs],
  { stdio: ['pipe', 'pipe', 'pipe'] },
)
// 30s timer; accumulate stdout to the first '\n'; JSON.parse it; reject on early
// 'exit' with the accumulated stderr. stopAgent: SIGTERM, wait for 'exit', SIGKILL at 10s.
```

**`stdio[0]` is `'pipe'` and must stay `'pipe'`.** The child watches fd 0 and exits when it
closes; `'ignore'` puts `/dev/null` there and silently opts the caller out of the orphan
leash. `orphan-leash.node.test.ts` demonstrates and guards this.

**`packages/node/src/bin/bench.ts`'s `Fabric` — ten members, verbatim**, comments abridged:

```ts
interface Fabric {
  readonly executors: readonly Executor[]
  readonly nodes: readonly NodeDescriptor[]
  readonly blockstore: MemoryBlockstore
  readonly moduleCid: Awaited<ReturnType<MemoryBlockstore['put']>>
  readonly moduleRecord: NameRecord
  readonly guard: EgressGuard
  readonly rpc: RpcEndpoint
  readonly admit?: AdmissionControl
  readonly combineIssuers: CombineTrustAnchors
  close(): Promise<void>
}
```

`FabricNode`, everything this plan uses, by symbol: `peerId`, `multiaddrs`, `nodeKey`,
`certificate`, `issuerKey`, `dutyCycle`, `circuitAddrs`, `dial(address) → peerId`, `store`,
`rpc`, `egress`, `libp2p`, `stop()`. `FabricNode.start` builds the `EgressGuard` and
constructs `rpc` over it, so the fabric only has to surface `submitter.egress`, never
construct one.

`Libp2pTransport.send` dials by peer id and reuses an existing connection whichever side
opened it, so dialling outward from the submitter does not change how the RPC reaches a peer
— only which side receives the inbound connection.

**Four source-shape guards constrain `bin/bench.ts`, and this plan does not edit that file at
all**, so all four are untouched: `bench-egress.node.test.ts` (seven named call-site
requirements plus a 5,000-character floor and both fabric function names),
`serve-agent-hooks.node.test.ts` (sixteen pinned counts), `discover-arm.node.test.ts` and
`coverage-agents.node.test.ts`. Plan 23-03 owns that file.

## Out of scope

- **Lifting the ~twenty existing `spawnAgent` copies onto this export.** Consolidating them is
  attractive and is explicitly deferred: the shared export would need a production caller to
  be reachable at all, the driver would be the only one, and that is the conversation Phase 22
  owns. Named here so it is a scheduled duplication rather than an unnoticed one.
- **An agent-side inbound-limit flag, and a dial flag.** Neither is added here. `processFabric`
  takes an `agentArgs` passthrough, which is enough for a flag that only needs to reach the
  spawned agents. Plan 23-04 adds both flags and, with them, three options this plan's
  signature does not have — `inboundThreshold`, `submitterInboundThreshold` and `dial` —
  because its factorial needs many peers on one host dialling one node. Expect that signature
  to grow in wave 3; do not anticipate it here, and do not build the outward dial in a way
  that makes the inverse ordering impossible: the submitting node's construction and the agent
  spawn are two steps, and 23-04 swaps their order for one of the two directions.
- **The sovereign leg.** `processFabric` names the unauthenticated sentinel at its
  `RemoteExecutor` construction and `'checks-no-combine-signatures'` for `combineIssuers`.
  Plan 23-06 owns criterion 5 and it lands on `realFabric`'s discover arm, not here.
- **Exporting anything from `packages/node/src/index.ts`.** `bin/bench.ts` reaches
  `fabric-node.ts` by relative path today and reaches this module the same way. A barrel export
  whose only consumer is a sibling file inside the same package is an export nobody needs.
- **`bin/bench.ts` itself.** Plan 23-03 owns it. This plan deliberately does not edit it, so
  none of the four source-shape guards over it can be disturbed by wave-1 work.
- **Narrowing the environment a spawned agent inherits.** `spawn` is called without an `env`
  override, matching the existing spawn tests. Every agent is a local process started by the
  same user, on the same host, running the same binary. Recorded as a decision rather than left
  as an oversight.
