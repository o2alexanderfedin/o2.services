# Phase 23 · Plan 03 — The saturating fixture and the process-per-node driver, wired into the published run

> **Numbers in this plan are configuration choices, not derived claims. Any quantity
> describing runtime behaviour must be measured before it is written down anywhere,
> including in a source comment.**

> **Cite by grep-able symbol, never by line number.** The 2026-07-29 version of this plan
> had a Task 2 read block wrong by 300 to 1,100 lines, and that is the seventh instance of a
> defect this repository has measured at forty-one of forty-six citations. Every reference
> below names a symbol a reader can grep. If a symbol cannot be found, that is a finding to
> report, not a line number to guess at.

> **Every proof named below states the mutation that reddens it.** A proof that cannot fail
> is not a proof. If a planted mutation leaves a check green, say so and name which check
> actually carries the claim — a green you did not watch fail is worse than a gap you
> reported.

**Closes:** BENCH-07 criteria 1, 2 and 4 (criterion 3 is Plan 23-04, criterion 5 is Plan
23-06, the run itself is Plan 23-05). **Wave 2. Depends on Plans 23-01 and 23-02.**

**This plan is a rewrite, not an amendment.** The 2026-07-29 version was falsified on six
independent grounds and nothing survives but its intent: it was written against `SHARDS = 8`,
against a five-member `Fabric`, against a `submit.ts` that placed each shard once, against a
`realFabric` with no conditional provider arm, against a pre-registered `6.3×` keyed to eight
partitions, and against two source-shape guards where there are four.

<objective>
Everything this phase needs now exists except the call sites. `@o2/bench` carries the declared
dimensions, the process-per-node report section and the integrity checker; `@o2/node` carries
a fabric that spawns N real agent processes and reports their identities. None of it is wired,
and a mechanism nobody calls from a production entry point is not wired — this project keeps a
list of exports in exactly that condition.

This plan makes `bin/bench.ts` the caller. Three things happen to it:

1. **A second fixture.** The current one is four `i32.store8`s and a shift. It cannot produce
   a speedup at any node count because there is nothing to parallelise, and the roadmap's own
   trap note says the published crossover measures the guest ABI rather than the fabric
   because of it. The replacement is not hand-assembled: this repository already ships a
   committed, integer-only, budget-bounded search kernel whose per-shard cost is a *declared
   input* rather than a property of the host. Its parameter is **chosen by measurement in this
   plan, at sixteen partitions**, against three stated acceptance conditions. The trivial
   fixture stays, and the COST crossover and the single-threaded baseline stay defined
   against it.
2. **A third driver.** `processFabric` becomes a real runner with per-rung disposal, and the
   fixed-redundancy speedup sweep runs across it — with the identical sweep under the
   in-process driver as its control, because a single curve whose shape has to be interpreted
   is not a finding.
3. **A gate.** Today `main()` wraps `measure(...)` in a `try`/`catch` that converts *any*
   thrown error into an excluded row blamed on a libp2p limit. Under that shape a failed pid
   check would be published as an excluded rung with a curve around it — the exact opposite of
   criterion 1. `HarnessIntegrityError` propagates out of `main()` and the run produces no
   report at all. That propagation is a property of **every** catch block in the file, not of
   the raise site, so the gate is one function with one call site per rung and every catch
   re-throws it — held by a count assertion rather than by a presence pattern, because a
   presence pattern can only prove that one catch behaves.

Purpose: make "N nodes" mean N operating-system processes in the published run, and make a run
that did not achieve that fail loudly instead of reporting a curve.
Output: a driver that publishes three makespan tables, a process table, a two-driver speedup
comparison carrying an ideal bound derived from the run itself, a coordination ratio per rung,
the three confound readings a ratio at R=1 is meaningless without, and an `unmet` list that is
per-driver rather than universal.
</objective>
