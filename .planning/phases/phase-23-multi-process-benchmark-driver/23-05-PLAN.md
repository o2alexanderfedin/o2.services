# Phase 23 · Plan 05 — Run it, publish it, and hold the published file to its provenance

> **Numbers in this plan are configuration choices, not derived claims. Any quantity
> describing runtime behaviour must be measured before it is written down anywhere,
> including in a source comment.**

> **Cite by grep-able symbol, never by line number.** Every reference below names a symbol or a
> heading a reader can grep.

> **Every proof named below states the mutation that reddens it.** A proof that cannot fail is
> not a proof — and this plan contains the one guard in the phase whose subject is a file rather
> than a program, which is exactly where a tautology hides best.

**Closes:** BENCH-07 criterion 4 in its operational form, and produces the measurement criteria
1, 2 and 3 are about. **Wave 5. Depends on Plans 23-03, 23-04 and 23-06.**

**Amended 2026-08-05, and two of the amendments are load-bearing.**

1. **The freeze had no source.** This plan used to copy
   `.planning/BENCHMARK-RESULTS.md` to `.planning/BENCHMARK-RESULTS-2026-07-27.md` and assert
   `573.16×` and `| 1 | 1.3ms |` against it. **No file in this tree supports that run date and
   none of those values is in the committed report.** The committed report is stamped
   `2026-08-01T06:09:01.272Z`, publishes `7086.14×`, and its 1-node memory p50 is `22.4ms`. The
   frozen artifact is `.planning/BENCHMARK-RESULTS-2026-08-01.md`, named for the run's own
   timestamp — the old filename asserted a run date as a fact and no artifact backed it.
2. **The section scan's floor was six against a 79-line file.** The committed report is 105 lines
   with **ten** `## ` sections, two of which (`## Reduce tree — memory transport` and
   `## Reduce tree — real transport`) did not exist when this plan was written. Eight carry a
   figure and are not exempt. The floor is **eight**.

It also now depends on Plan 23-06, so the run is taken against a driver that already contains the
sovereign leg — a leg that broke the default run has to be caught before the numbers are taken.

<objective>
Everything is built and nothing has been measured. This plan freezes the previous run, then runs
the benchmark and commits what comes out, and it puts a guard on the committed file first —
because criterion 4's second half, *no figure is silently replaced*, is a property of the
artifact, not of the code that generated it. A driver that renders provenance correctly and a
report file that lost half its rungs to a partial commit are indistinguishable from inside the
driver.

**The freeze comes first and is not optional.** `main()` rewrites
`.planning/BENCHMARK-RESULTS.md` wholesale and re-measures the memory and real ladders on the
same rungs, so every 2026-08-01 value is overwritten the moment the run starts. Criterion 4's
second half is met by those values surviving in a file nothing regenerates, and by the new report
stating the re-measurement — not by a guard matching the shape of a table row, which passes
against any numbers at all.

Three things make this plan different from the five before it. It is the only one that produces
numbers. It is the only one that must **stop and revise a declared parameter** if the fixture
does not behave through the fabric the way it behaved in isolation. And it is the only one where
the honest outcome may be a curve that is flat: a flat curve is published flat, with the figures
that make it a finding about the fabric attached.

Purpose: publish, and make the published file checkable.
Output: a frozen `.planning/BENCHMARK-RESULTS-2026-08-01.md`; `bench-results.node.test.ts`
reading the committed report, the frozen artifact and the two sources that generate the headings;
a regenerated `.planning/BENCHMARK-RESULTS.md` and `.planning/bench/raw.json`; and, if the
fixture needed moving, a fifth dated amendment entry recording that it did and why.
</objective>

## What this phase measures once, and what stays unmeasured

Stated here in the words the project uses, so the phase's closure cannot be read as covering them.

- **Criterion 1's pid evidence is measured once and is unmeasured on every subsequent change.**
  The `## Processes` table is produced by one hand-run benchmark. Nothing re-derives it:
  `bin/bench.ts` executes `main()` on import so no test can import it, and the root
  `package.json`'s twelve scripts include none that runs it. After this phase, an edit that breaks
  the process driver leaves the published pid table intact and every artifact requirement green.
  What would measure it: a script running the full gate on a short ladder in CI, whose failure
  would then be a red build — and even that would not re-derive the *published* full-ladder table.
  The source-linkage block in Task 1 is the partial mitigation: it makes a deleted renderer red,
  but it cannot make a broken one red.
- **The gate's wiring is source-proved, not execution-proved.** `assertIntegrity` and its four
  readings are unit-proved with planted inputs; that the driver builds its observation from the
  live fabric is held by a call-site shape guard and a catch-count assertion. No test executes a
  rung. What would measure it: `main()` split from the module body so one rung can be driven under
  a stub fabric with a planted pid mismatch.
- **The stagger lever is unmeasured** — named in Plan 23-04's factorial as a lever this phase did
  not exercise, recorded as `stagger: 'none'` in every attempt.
- **The agents' inbound connection counts are not instrumented**, so no attempt's outcome in the
  factorial is explained by a count nobody read.
- **BENCH-06's distinct-machine half is descoped and unmeasured — not met.** One host has one CPU,
  one V8 and one libc.
