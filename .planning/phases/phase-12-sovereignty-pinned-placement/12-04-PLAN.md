(`fabric-node.ts:311`, `browser-node.ts:181`) — it is being reused as a *test
instrument*, wrapping a hand-built RPC transport the same way the existing
`criterion 6`/`criterion 7` tests in this file already do, only now driven by
`submitJob` (the live job path) instead of hand-called `discoverExecutors`/
`planWithOffers`/`executeVerified`. This is not a second, weaker byte-counter — it is
the one that already exists, pointed at the new caller.

**DATA-09 without conflating with AUTH-03.** Criterion 4's node is Bob's — a
different operator from Alice, holding a plaintext copy of Alice's block for
availability purposes only (the `ownerFabric` helper in this file already builds
exactly this node for its own Phase 6 discovery-exclusion proof). Wrapping its

(bypassing placement, the same way `distributed.test.ts`'s AUTH-03 test bypasses
placement to prove its own server-side gate) is what proves "even though that same
node answers availability queries for the data" — placement would never route there;
the refusal has to hold regardless.
