# Phase 36, Plan 1 — The Kill Switch and a Status Page

**Goal, verbatim from `.planning/ROADMAP.md`:** *As a fabric operator, I want to tell the cohort
to stop admitting new tasks with no redeploy, sliced by region and by client version rather than
all at once, so that I can halt exactly the slice that is misbehaving instead of the whole
fabric.*

**And the ORIGINAL wording, which the roadmap itself flags as carrying a clause the user-story
form dropped:** *The cohort can be told to stop admitting new tasks with no redeploy, sliced by
region and by client version rather than all at once, **and a volunteer can see both that control
and the fabric's state without being given operator access***.

The roadmap's own note: *"The original's closing clause — a volunteer can see both that control
and the fabric's state without being given operator access — is a volunteer's capability, a second

4 are that clause, and Tasks 6 and 7 are where it is measured.

## The four success criteria, VERBATIM from `.planning/ROADMAP.md`

Each clause is load-bearing. Plan and verify against these words, never against a paraphrase —
including the ones in this plan's own task titles.

  1. The cohort stops admitting new tasks with **no redeploy**, and the stop is sliceable **by region and by client version** — flipping one region's slice is observed leaving the other two admitting work. A global-only switch fails this criterion by construction: one bad region would take offline volunteers whose region was never affected

  4. A minimal status page is reachable by a volunteer before Phase 39 sends anything — a read-only view over data the fabric already publishes (DHT records, benchmark output) is enough. What is not enough is nothing

## THE OPEN QUESTION THIS PHASE CARRIES AND DOES NOT CLOSE

**Three things about it, and all three go in the SUMMARY.**

1. **This plan produces the number and does not rule on it.** Criterion 3's own sentence licenses
   exactly that: *"Open question 2 governs what is done about that number; this criterion only
   requires that it exists."* Nothing in Tasks 1–7 waits on the answer, and Task 8 presents it.

2. **The mechanism is SUBSTITUTED, and the substitution must be stated rather than slipped in.**
   The question is framed in Workers KV's terms. This plan uses **Durable Object storage**, because
   the scope fence forbids creating a KV namespace and because the object every tab already dials
   is the cheapest place a boolean can live. So **the ~60 s KV propagation figure stays unmeasured

   dominant term is the poll interval this plan chooses. That number informs the question — it
   says what a poll costs — and it does not answer the half of the question that is about KV.
   Say this in the SUMMARY in these terms. Silent substitution reads as pre-empting.

3. **Do not build the push path.** Building a Durable Object broadcast over the already-open socket
   would settle the question in the other direction by fait accompli. The roadmap's own sequencing
   is *"a Durable Object broadcast layered on **only if** the sub-minute window proves unacceptable

## THE TRAP — a tab admits its own work by a different rule from a peer's

**Read this before writing Task 5. It is the one design fact that decides whether this phase can
observe anything at all, and it was measured in the tree rather than assumed.**

`AgentOptions.paused` is consulted at `packages/net/src/agent.ts:1092`, inside `serveAgent`.
`serveAgent` answers **peers**. A tab running its own work does not go through it:

- `packages/browser/demo/main.ts:2090` — `admit: rpcAdmission(node.rpc, { local: node.admission }),`
- `packages/net/src/discovery.ts:198-207` — `rpcAdmission`'s first branch is
  `if (offer.nodeId === rpc.localId) return local?.would(offer) ?? …`. It short-circuits the wire,
  because *"a node does not learn its own capacity over a wire"*, and `local` is
  `node.admission`, a bare `LocalCapacity`. **`paused` is not consulted on that branch.**
- `packages/browser/demo/main.ts:1717` and `:1862` — `capacity: node.admission` again, on the
  `prefers-local-combining` placement. Two more sites, same omission.
- `packages/browser/src/browser-node.ts:1813-1815` — a tab's own shards reach the executor by
  *"a page's own local self-dispatch (`includeSelf`, `demo/main.ts`)"*, not through `serveAgent`.

**So a paused tab today refuses every peer and admits itself.** That is the exact inverse of the
rule the tree states twice, in its own words:

- `browser-node.ts:2067-2069` — *"a tab that admitted its own work by a rule other than the one it
  admits a peer's by would be more permissive to itself than to everybody else. One value, two
  readers, no way for them to disagree."*
- `demo/main.ts:1702-1706` — *"Both ports are **this tab's own**, not second copies… A tab
  admitting its own work by a different rule would be more permissive to itself than to everybody
  else."*

**That is the licence for Task 5's change, and it is the tree's own sentence rather than this
plan's opinion.** Task 5 introduces `BrowserNode.localAdmission` — one reading every local path
takes, with `paused` folded in — and moves all three call sites onto it. The bound goes on the one
reading and not at the call sites, which is Phase 31's recorded pattern
(*"a bound is enforced on the one reading every path takes, never at the call sites"*).

**And it moves a guard, which must land in the same commit.**
`packages/browser/src/colouring-surface.node.test.ts:519` asserts the **exact trimmed line**:

```
expect(wiring).toEqual(['admit: rpcAdmission(node.rpc, { local: node.admission }),'])
```

That equality exists because a prefix match once let the `local` port go missing silently. Changing
the line to `node.localAdmission` reddens it. **Move it in the same commit, keep it an equality,
and record in its docblock why the port changed** — the reason is the paragraph above, not a
refactor.

## The design, in one page

**The flag lives in the Durable Object's own storage.** One boolean and its slice, banked with
`relay-service-journal.ts`'s durability pattern. No KV namespace (the scope fence forbids creating
one), no flag server, no SaaS — the roadmap's own words: *"it is one boolean, read rarely."*

**The slice is the object.** Each region's object holds its own directive, so flipping one region
cannot reach the other two by construction rather than by care. A write **names the region it is
for** and an object refuses a write addressed to a region that is not its own — so an operator tool
that fans one command out to every endpoint gets three refusals and two untouched objects instead
of a global halt.

**A new route is forced, and the forcing is enumerated** because `worker.ts:428-431` states the
opposite default (*"It is a field on the one route this object serves and **not a second route**:
every route is a surface, and this tier's surfaces are not"*). Three reasons, none of them taste:
(a) `wrangler` has no surface that writes Durable Object storage remotely — the write has to arrive
as a request; (b) a write cannot be a field on a `GET`; (c) carrying it over libp2p would make the
operator a peer and need a new protocol, a key distribution story and a signed record — for one
boolean. So: **`GET /self` gains an `admission` field** (the field precedent: `instance`, `version`,
`traffic`, `relayService`) and **`POST /admission` is the one write surface this tier has**, with a
fail-closed key.

**The client polls `/self` and feeds `paused`.** The endpoint is *derived* from the relay multiaddr
the tab already has, so there is no second configuration knob to drift. The poll starts **after
consent** — see the P10 trap in Task 5. The client applies `isHaltedFor(directive, thisPageVersion)`
locally, which is the node-local reading `STACK.md` argues for and which makes the decision cheap
and offline-safe.

**The volunteer's two surfaces** are `document.title` (browser chrome, no catalogue entry — Phase
35's precedent) and `status.html` (a second static page, `policy.html`'s precedent, this time
actually in the build).
