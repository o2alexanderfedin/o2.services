**Phase 16 — Decomposable Tree-Reduce Wiring · Plan 01 of 04**
**Closes (in part):** MR-03, MR-06 — the combine function and the frame that names one.
**MR-02 is not listed and is not closed by this phase.** Its text is *"Each owner computes a
local partial over its own data with no map-side data movement"*, and every job this phase
runs is a **public** one whose shard inputs are fetched by CID from the submitter — data
does move map-side, by construction. Nothing in Plans 16-01…16-04 distinguishes a map that
moved data from one that did not, so MR-02's map-side half is **unmeasured** by this phase,
and unmeasured is not met. What would measure it: a job whose inputs carry an owner label
and land on that owner's node, with Phase 13's `EgressGuard` refusing the raw input's
egress — the machinery exists (`registerSovereignInputs`, `guardSovereignty`), and pointing
a reduce at it is a criterion no plan here has.

<objective>
Give the fabric one combine function and one way to ask a peer to run it.

Today `Combiner` is a type with no exported instance: every combine that has ever run in
this repository was merged by a function defined inside `reduce.test.ts` (`:22-39`) and
never seen by production code. And `AgentRequest` has seven kinds, none of which can name
more than one input CID — `exec` carries a `Task`, and `Task` has exactly one `inputCid`
(`ports.ts:25-48`). A combine has *k*.

This plan closes both gaps and nothing else. It adds no caller: `serveAgent` does not
learn to answer a combine here (Plan 16-02), no node dispatches one here (Plan 16-02), and
no job reduces here (Plan 16-02). What it produces is a merge function with a home and a
frame with a parser, each proven in isolation, so the wiring plan has contracts to build
against rather than shapes to invent.

**One exception, forced by the type system and named rather than discovered.** `serveAgent`'s
handler chain ends in a bare `} else {` (`agent.ts:201`) whose only narrowing is exhaustion
of the earlier `if`s; inside it the code reads `request.task` (`:219`, `:224`, `:234`) and
`request.capability` (`:220`). Adding an eighth kind to `AgentRequest` makes that residual
union `exec | combine`, and under `"strict": true` (`tsconfig.json:5`) those four property
accesses become compile errors. So a whole-repository `npx tsc --noEmit` **cannot** pass
after this plan's union change unless `agent.ts` also changes. Rather than publish a gate
this plan cannot satisfy, Task 2 adds exactly one narrowing branch to `agent.ts` — a
placeholder that answers the null arm — and `## Out of scope` names it as the single
permitted line. Plan 16-02 replaces that branch with the real handler. The alternative,
moving the union extension into 16-02, was rejected because it would leave `protocol.ts`'s
codec and its parser bounds untestable in isolation, which is the whole reason this plan is
separate.

Two decisions from 16-CONTEXT.md are made concrete here and are worth restating because
the rest of the phase rests on them:

- **Decision 1** — an eighth request kind, not an overloaded `exec`. `protocol.ts`'s own
  docstring (`:1-36`) narrates each kind's arrival by phase, so adding one is a documented
  act. The rejected alternatives were a WASM combine module (the guest would have to decode
  DAG-CBOR, which nothing in this repository has ever done) and a requestor-assembled input
  block (which would put a *payload* in the combine request, destroying the property
  `reduce.test.ts:210-231` exists to hold).
- **Decision 3** — the combiner is fabric-fixed. If two nodes could hold different
  `Combiner`s, `executeReduce` would report a `disagreement` (`reduce.ts:305-307`) with no
  way to name the cause, because the tree is *derived, never agreed* (`reduce.ts:8-12`) and
  there is no negotiation step at which a mismatch could surface. Fail-loud with no
  diagnosis is worse than no configuration knob.

Purpose: one merge, one frame, both bounded, before anything calls either.
Output: `fabricCombiner`, `asFabricPartial`, `FabricPartial` and `MAX_COMBINE_INPUTS`
exported from `@o2/core`; a `combine` request and response encoded and parsed in
`@o2/net`; `reduce.test.ts` holding the production combiner rather than a private copy.

```ts
const combiner: Combiner = (inputs) => {
  const counts = new Map<string, number>()
  let rows = 0
  for (const input of inputs) {
    const record = input as { readonly counts?: CanonicalValue; readonly rows?: CanonicalValue }
    rows += typeof record.rows === 'number' ? record.rows : 0
    const partial = record.counts
    if (partial === null || typeof partial !== 'object' || Array.isArray(partial)) continue
    for (const [word, n] of Object.entries(partial)) {
      if (typeof n !== 'number') continue
      counts.set(word, (counts.get(word) ?? 0) + n)
    }
  }
  const merged: { [k: string]: number } = {}
  for (const key of [...counts.keys()].sort()) merged[key] = counts.get(key) as number
  return { counts: merged, rows }
}
```
