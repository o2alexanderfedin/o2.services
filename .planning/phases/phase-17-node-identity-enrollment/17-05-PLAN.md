# Phase 17 · Plan 05 — Real processes, and the three criteria measured

> **Numbers in this plan are configuration choices, not derived claims. Any quantity
> describing runtime behaviour must be measured before it is written down anywhere,
> including in a source comment.**

**Closes:** AUTH-01, AUTH-02, AUTH-04 — the cross-process measurement of all three, and
the production entry point that makes ROADMAP criteria 1 and 2 say what they say
(*"starting a node via `bin/agent.ts`"*, *"a second node started via `bin/agent.ts`"*).

<objective>
Plans 17-01 to 17-04 built and proved every mechanism in process. This plan adds the one
production entry point that reaches them — five flags on the agent binary — and
measures the three ROADMAP criteria the way their wording demands.

**Same-process is not sufficient here, unlike Phase 13.** 13-CONTEXT.md argued that two
`FabricNode`s in one Vitest process were accepted evidence for "started via
`bin/agent.ts`". That argument does not carry: criterion 1's subject is *what happens on
first start of a process against a fresh directory*, and criterion 2's is *a second node*.
Both need real processes and real directories, and both already have a harness —
`egress-refusal.node.test.ts:62-95`, whose `spawnAgent(name, extraArgs)` takes a
pass-through argv array, which is exactly what these flags need.

**And here is the half of criterion 2 that this plan cannot reach, stated before anything
else so the rest is not read as covering it.** The *verifying* node in Task 3 is a
`FabricNode` in the test process, not a spawned one, because a verifier has to be connected
to the nodes it verifies and **`bin/agent.ts` has no flag that makes a spawned agent dial
another agent** — the only outbound dial it can be told to make is `--provider-addr`, which
also enrols. So criterion 2's *accepting* side — a spawned `bin/agent.ts` verifier
accepting a certificate that chains to its pinned issuer — is **unmeasured through
`bin/agent.ts`**, in those words, and is measured in process. Descoped is not satisfied;
unmeasured is not met.

What *is* measured across a real process boundary is `--trusted-issuer` itself and the gate
it turns on: Task 3 spawns one agent with the flag and one without, connects both to the
test process (which serves no records and is therefore unverifiable by anyone), dispatches
the identical task to each, and reads opposite outcomes. That exercises the argv entry, the
conditional spread into `FabricNodeOptions.trustedIssuers`, and `PeerVerifier`'s
fail-closed path, in a genuine operating-system process. Without it the whole
argv→option mapping would have **zero** coverage anywhere in the phase — a typo in the flag
name or a forgotten conditional spread would leave every test green while the flag did
nothing. What would close the remaining half: a dial/bootstrap-address flag on
`bin/agent.ts`, which is a real production need and Phase 18's bootstrap work, not this
phase's.

Two more things this plan records rather than papers over.

**Criterion 3 cannot be measured as written.** "Making mass fake-node creation measurably
costly" is not what the mechanism does. `enrollment.ts:22-30` states it plainly:
rate-limiting makes fake nodes *rate-limited, not expensive*; an attacker holding many
user keys is not slowed at all, and the ceiling is a policy number rather than a physical
one. Both measurements are run and both are published: the limit holds under one user key,
and it does nothing under twenty. The phase reports criterion 3 as **rate-limiting
measured; cost unmeasured**, in those words.

**The stated threshold is a threshold per provider uptime.** `#history`
(`enrollment.ts:173`) is a `Map` in the authority object, so a provider that restarts
forgets every issuance. The burst measurement is valid — a burst against one running
provider is genuinely refused — and the limit's actual scope goes in the summary rather
than being left for a reader to infer.

Purpose: turn every mechanism this phase built into something a real process reaches, and
measure the result rather than reporting it.
Output: five flags, an extended handshake, two cross-process test files, and four
mutation captures proving the phase's guarantees can fail.
</objective>

## Recorded decisions

Three boundaries this plan crosses deliberately, recorded so a later addition that breaks
one of them is a visible decision rather than a slip.

- **argv becomes a signed statement.** `--user-key` and `--operator-id` become fields of a
  certificate a provider signs. Nothing verifies that the operator id is *true*; what is
  enforced is that it was *stated*, because a defaulted one would be a lie in a signed
  record and `operatorId` is the unit of quorum diversity (`enrollment.ts:83-84`). That is
  what the exit-2 path buys, and it is the whole of what it buys.
- **The handshake line is public, by construction, and must stay that way.** After Task 1
  it carries a peer id, addresses, a public node key, a public certificate and a public
  issuer key — nothing secret crosses that boundary. Task 1's module-comment paragraph
  states the rule so that any later field which breaks it is a decision somebody has to
  make on purpose rather than a slip. Accepted risk, stated: nothing enforces the rule
  mechanically.
- **`--trusted-issuer` is the whole of this node's trust, and there is no live authority to
  correct a mistake.** An operator who pins the wrong key gets a node that talks to the
  wrong fabric. The malformed-key exit-2 path catches a value that is not 64 lowercase hex
  characters; it cannot catch a well-formed key belonging to somebody else, and this design
  does not protect against that.

Two accepted limits carried into the summary rather than fixed here: mass fake-node
creation stays cheap for an attacker holding many user keys (`enrollment.ts:26-30` names
the proof-of-work, payment or out-of-band identity check that would change it — out of
scope for v1.1), and the stated threshold resets whenever a provider process restarts,
because `#history` is in-process memory (`enrollment.ts:173`). Persisting it is a
straightforward addition that no criterion asks for.
