# Phase 19 · Plan 02 — The anchor VER-03 never had, and the strength the quorum always declared

**Closes:** VER-03 and VER-04 in the kernel — *at least one replica of every verification
quorum is anchored on a backbone node*, and *quorum members are selected with anti-affinity*.

<objective>
**The ROADMAP says this phase needs no research because `composeQuorum` "exists and is
unit-verified". Half of that is false and the other half hides a defect.**

**VER-03 is UNIMPLEMENTED, not unwired.** `composeQuorum` (`quorum.ts:110`) sorts candidates
by `relayIds.length` ascending (`:140-142`) and refuses on a *shared* relay via `sharedRelay`
(`:145-153`). **Nothing requires a member that is backbone-anchored.** There is no `backbone`
symbol anywhere in `packages/*/src` — the only occurrences are prose in
`libp2p/src/constants.ts:13,85`, `fabric-node.ts:34` and `sovereignty.ts:46`. The ascending
sort *tends* to put a seed first, because a seed usually lists no relays; it guarantees
nothing, and a tendency is not a rule. So a quorum composed today can consist entirely of
nodes discoverable only through relays, none of which they share — passing `sharedRelay` and
satisfying nothing VER-03 asks for.

**And `composeQuorum` returns `strength: 'independent'` unconditionally** on its ok arm
(`:159`), and **never calls `classifyAttestation`** — which exists, at `:202`, and is the
only place the three labels are computed. Wire it as it stands and every quorum reports
`independent`, **including a size-1 one**, which is one node reporting that separate
operators agreed with each other. That is precisely the conflation criterion 2 and VER-10
exist to forbid, so it is this phase's fix and not a follow-up.

**Why `discoverability` and not a new certificate field.** The project's cardinal rule is
that all nodes have equal functionality and **the only difference is discovery**. Backbone-
anchored is therefore a statement about *discovery*, which the certificate already carries:
`'seed'` means dialable directly and usable as a bootstrap entry point, `'via-relay'` means
findable only through the relays named in `relayIds` (`enrollment.ts:76-94`). A new explicit
field would mint a second concept beside `discoverability` and would read as a node tier —
the one thing a decision here is forbidden to introduce.

Pure module, pure change. No caller is wired here; that is Plan 19-06.
</objective>


Note what the one-per-operator map already buys: **anti-affinity is a property of the
construction**, not a check bolted on after. The anchor must be built the same way.

From `packages/core/src/quorum.ts:169-193` — `sharedRelay`, and the reason it already treats
a seed as depending on nothing:
```ts
const dependenciesOf = (member: NodeCertificate): readonly string[] =>
  member.discoverability === 'seed' ? [] : member.relayIds
```
`sharedRelay` returns `null` the moment any member is a seed. **That is a different question
from VER-03's** — it answers "do all members share one discovery path", and a quorum of five
`via-relay` nodes on five different relays answers `null` while containing no anchor at all.

From `packages/core/src/quorum.ts:202-211` — the classifier that has never been called from
the composer:
```ts
export function classifyAttestation(agreeing: readonly NodeCertificate[]): AttestationStrength {
  if (agreeing.length <= 1) return 'owner-attested'
  const operators = new Set(agreeing.map((c) => c.operatorId))
  if (operators.size >= 2) return 'independent'
  return 'owner-domain'
}
```

From `packages/core/src/enrollment.ts:90-94`:

```ts
export type Discoverability = 'seed' | 'via-relay'
```

process started without a listen address is `via-relay` exactly as a tab is.

## Recorded decisions

- **Backbone-anchored is derived from `discoverability`, not from a new field.** All nodes
  have equal functionality and the only difference is discovery; a statement about discovery
  belongs in the field that already carries discovery. A second field would read as a node
  tier.
- **The anchor is chosen before the other slots are filled.** A constraint applied after a
  preference is not a constraint — this repository has recorded that shape twice under
  different names.
- **The anchor rule ignores `requireIndependentPaths`.** That flag exists so a single-relay
  fixture can compose; eclipse resistance has no fixture excuse.
- **`strength: 'independent'` was a defect, not a simplification.** It was correct in every
  case the unit tests reached and wrong at size 1, which is exactly why nothing found it.

## Out of scope

- Any caller. `submitJob`'s use of `composeQuorum` is Plan 19-06; the cross-process
  measurement is 19-08.
- `attestationReceipt` and `classifyAttestation` themselves. Both are correct and are left
  alone — only the composer's failure to call one of them is fixed here.
- The `owner-domain` path. It does not run through `composeQuorum` at all: a quorum here
  holds one node per operator by construction, so it can never return `'owner-domain'`.
  Owner-domain agreement is `resolveReplicaSets` + `attestationReceipt`, and it is 19-07's
  and 19-09's. **Do not try to make `composeQuorum` serve both** — that would mean relaxing
  anti-affinity, which is the one thing it exists to enforce.
