2026-08-02. Do not plan against either.**

   `packages/node/src/browser-capability.e2e.test.ts` dispatches three `label:'sovereign'`
   tasks (`:280-281`) to a live tab started with `canExecuteSovereign: true` (`:213`) and
   asserts the third is **accepted and executed** (`:349-353`). The `authorize`/AUTH-03
   refusal is likewise already executed in a real tab (`:296-338`, the absent-chain and
   expired-chain arms).

**What genuinely remains unexecuted is narrower, and the source is more precise than the
roadmap was.**

- **The `EgressGuard` / `withholdingFrom` refusal is unconfirmed.** No spec drives a
  sovereign payload out of a tab and reads the guard's refusal.
  `two-tabs.e2e.test.ts:275-277` reads the *clean* manifest on a **public** job — the
  positive arm only. `sovereign-block-refusal.node.test.ts:53-62` states outright that it
  proves the Node tier's submitter path and **not** the browser tier's, and names WIRE-03 /
  Phase 19: *"that file dispatches **to** a browser node and reads what it serves, which is
  the other direction."*
- **The `capacity` / SCHED-06 refusal is explicitly unexecuted, and the source names this
  phase.** `packages/browser/src/browser-node.ts:1176-1184`: *"nothing drives a refusal
  through this hook, so the number this node would answer an over-committed requestor with
  has never been read … WIRE-03, Phase 19 builds the harness that would measure it."* Note
  what is **not** this: `duty-cycle-tab.e2e.test.ts:263` reads a tab's advertised slots fall
  8 → 2, which is an **offer answer, not a refusal**.

Those two are WIRE-03's whole content. This plan builds the harness the source asked for.
