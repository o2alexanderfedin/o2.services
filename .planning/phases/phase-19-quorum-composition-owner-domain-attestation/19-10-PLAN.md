# Phase 19 · Plan 10 — The label on the CLI

**Closes:** criterion 3's CLI half, and VER-10 on the one surface that already publishes job
outcomes to a person.

<objective>
Criterion 3 asks that a one-replica result read **owner-attested rather than verified,
*wherever it is displayed***. Three surfaces display a job outcome in this repository: the
`JobResult` itself (Plan 19-06), the demo UI (Plan 19-11), and this one — `bin/bench.ts`,
the only CLI that submits jobs at all. `bin/agent.ts` does not: zero hits for `submitJob`,
`JobSpec` or `executeVerified`, and its only stdout is a handshake line.

**A receipt nothing renders is built, not wired** — the single condition this whole milestone
exists to eliminate, reappearing in a new place. That is why the display half is not deferred.

**Two readings are available on the sweep as it already runs, and neither needs the published
curve to change shape.** The `--discover` rig is the only one whose descriptors carry
certificates (`bench.ts:701-707` assigns `found.nodes`, and the comment at `:766-769` already
records that re-deriving them with `publicNodes` would throw away what they carry). Its
workers enrol with distinct operator ids — `operatorId: \`bench-worker-${i}\`` at `:624` —
and each listens on tcp, so each is `discoverability: 'seed'` and therefore anchored. The real
ladder runs `redundancy: Math.min(2, nodes)`, so:

- the **1-node real rung** runs at redundancy 1 and must read **`owner-attested`**;
- the **2-node real rung** runs at redundancy 2 across two operators and must read
  **`independent`**;
- every **memory rung** builds descriptors that carry no certificate and must read the
  **named absence**, not either label.

The driver's own report already contains the sentence *"the same reason a sovereign shard with
one owner node is owner-attested"* (`bench.ts:1053-1056`). The vocabulary is there; the
measurement is not.
</objective>

**READ THIS BEFORE CHOOSING A RIG — checked at planning time, 2026-08-02, and it decides
whether this plan can close criterion 3's CLI half at all.** Plan 19-06's receipt now requires
**two** things of every shard, not one: descriptors carrying certificates, *and* an agreeing
replica whose signature over that result verifies. Two facts about this binary follow from
that, and both are measurable now rather than at verification:

- **`discoverCandidates` runs only inside `if (DISCOVER)` and `--discover` is off by
  default** (`bin/bench.ts:680`). Off that path the descriptors carry no certificate, so
  condition one fails and every shard reads the named absence.
- **The executors must be remote to enrolled agents.** An in-process executor reports the
  unsigned sentinel by construction (Plan 19-13), so condition two fails on any memory rig
  however its descriptors were built.

So the three readings **must** be taken on a rig that is both `--discover` and backed by
spawned, enrolled, signing agents. On any other rig this plan's honest output is three named
absences — which is a true reading and is **not** criterion 3 met. If the rig cannot be made to
satisfy both, say so in the summary and let the criterion score PARTIAL; do not print a
strength the run did not establish, and do not relax Plan 19-06's conditions to obtain one.

**One thing the 2026-08-03 ruling makes easier, and one it makes different.** An
over-concentrated fabric no longer *refuses* — it degrades, so a run that would once have
produced no reading now produces a real one. But the strength it produces is the weaker label:
a bench fabric whose workers share an operator reads `owner-domain`, not `independent`. **Take
whatever strength the run establishes and print it.** A reading of `owner-domain` off a one-operator fabric is
criterion 3 working, not criterion 3 failing, and a plan that engineered the fabric until the
label read `independent` would be measuring its own fixture.

From `packages/core/src/quorum.ts` — what a receipt offers a printer:
```ts
export interface AttestationReceipt {
  readonly strength: AttestationStrength      // 'owner-attested' | 'owner-domain' | 'independent'
  readonly description: string                // "a one-line description fit to surface next to a result"
  readonly replicas: number

```
`describeAttestation` is where those sentences live, and they are written for exactly this:
*"owner-attested — computed once by the data owner and not independently verified"*,
*"owner-domain agreement — replicated across the owner's own nodes, not across operators"*,
*"independently verified — replicas from separate operators agreed"*.

From `packages/node/src/bin/bench.ts:745-800` — `run`, which builds one `submitJobWithEgress`
call per iteration and returns an `Observation`. The receipt is on `result.job`.

From `packages/node/src/bin/bench.ts:952-1000` — `main`, and the lines it already writes per
rung: `  memory transport, ${nodes} node(s)…` and `  real transport, ${nodes} node(s)…`, plus
the egress manifest summary per transport and `    excluded: ${detail}` for a rung that threw.

From `packages/node/src/bin/bench.ts:568-707` — the `--discover` arm: a spawned provider,
workers enrolled with `operatorId: \`bench-worker-${i}\``, `discoverCandidates` with
`trustedIssuers` from the provider's issuer key, and the refusal
*"--discover found no candidates; refusing to report a curve measured on nothing"*.

From `packages/node/src/discover-arm.node.test.ts` — the whole shape this plan extends: it

## Recorded decisions

- **The label is read off `JobResult`, never derived from the rig.** A driver computing it
  from `config.redundancy` would print the right answer for the wrong reason and keep printing
  it after the mechanism broke.
- **The three sentences are `describeAttestation`'s.** The CLI and the demo UI must not drift
  into describing one result differently, and the only way to guarantee that is one source of
  the words.
- **A rung that established nothing says so.** *"We cannot say"* and *"one node said so"* are
  different statements, and keeping them different is the whole of VER-10.
- **The sweep's shape does not move.** A benchmark whose configuration changed between runs
  has rows that cannot be compared, and this repository has already published one row-order
  confound it could not fix afterwards.
