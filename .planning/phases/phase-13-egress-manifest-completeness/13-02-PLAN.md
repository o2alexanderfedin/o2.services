<objective>
Wire the two production call sites this phase's whole roadmap goal names:
`fabric-node.ts:327` and `browser-node.ts:197` currently construct `RpcEndpoint` over the
raw `Libp2pTransport`. This plan makes both construct it over a new `EgressGuard` field
instead -- a new field, per 13-CONTEXT.md decision 2's structural corollary, not a type
change to the existing `transport` field (which callers rely on for `.stop()` and
`.peers`, neither of which `EgressGuard` declares). It also wires Plan 13-01's
`registerSovereignInputs` around each factory's served executor, so every sovereign task
either node runs has its input declared to that node's own tap before execution --
closing 13-CONTEXT.md's Risk 1 (nothing in production ever called `.guard()`) on the two
places a task actually gets dispatched.

Purpose: make the egress manifest complete by construction on both real node classes,
with a guard that has something to watch.
Output: `FabricNode` and `BrowserNode` both expose `readonly egress: EgressGuard`;
`tsc --noEmit` clean; the existing DATA-09 test (`fabric-node.node.test.ts`) and the full
suite stay green, since this plan is purely additive -- no test in the repo yet exercises
`.egress` (that is Plan 13-03's job).
</objective>
