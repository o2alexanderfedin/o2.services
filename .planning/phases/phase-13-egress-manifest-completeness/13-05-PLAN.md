- **In process** (`egress-manifest.node.test.ts`) the test holds `alice.egress`, so it

  the test proves the *consequence*: the job fails, it does not relocate, and a control
  job through the same two agent processes immediately afterwards succeeds — which is
  what rules out "the node died" and "the budget was too short" as explanations.

Purpose: the criterion says a running cross-owner job fails. Make that a measurement
rather than a claim, at the process boundary the criterion names.

`packages/node/src/fs-blockstore.ts` — how the owner's directory is seeded before the
agent process opens it. `open()` creates the directory if absent; `put()` writes one
file named by the CID and renames it into place; `get()`/`has()` read from disk on every
call, so a directory written by this process is readable by the child that opens it
afterwards:

```ts
static async open(dir: string): Promise<FsBlockstore>
async put(bytes: Uint8Array<ArrayBuffer>): Promise<CID>
```

`packages/node/src/fabric-node.ts:344-379` — what the spawned process composes, and why
the seeding above is mandatory rather than convenient:

```ts
const sovereignty = options.sovereignty ?? { ownerId: '', canExecuteSovereign: false }
const egress = new EgressGuard(transport, sovereignty.ownerId)
const rpc = new RpcEndpoint(egress, …)
const blockstore = new FetchingBlockstore(store, new RpcBlockSource(rpc, () => transport.peers))
const executor = registerSovereignInputs(
  guardSovereignty(new WasmExecutor({ nodeId: …, blockstore }), sovereignty),
  { blockstore: store, guard: egress },      // `store` — the LOCAL tier, no network fallback
)
```

`registerSovereignInputs` reads the registration bytes from `store`, and it runs
**before** `inner.execute`. On a first dispatch the executor has not yet fetched
anything, so if the input is not already on the owner's disk the registration silently
skips and the tap has nothing to watch for. Seeding the directory before spawn is
therefore what makes the test test anything — and it is also the honest model, since an
owner-pinned input is resident on its owner's device by definition.

`packages/core/src/job/submit.ts` and `verify.ts` — the failure shape to assert:
a `'sovereign'` shard is narrowed by `planPlacement`/`eligibleNodes` to the owner's own
nodes **before** load is consulted, each selected executor is run exactly once with no
retry and no re-placement, and when every receipt fails the shard is
`{ status: 'insufficient', reason: 'every executor failed', failures: [{ nodeId, reason }] }`
with `JobResult.complete === false`.

`packages/net/src/index.ts` (after Plan 13-04): `EgressRefusal` joins `EgressGuard`.
`submitJobWithEgress(spec, blockstore, guards)` returns
`{ ok: true, job, manifests }` or `{ ok: false, error }`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| spawned agent process → submitter process | The wire criterion 1 names. Nothing but the socket is shared, so a shared-heap artefact cannot produce a passing result |
| test process → the owner's blockstore directory | The test writes the sovereign row to alice's directory before her process opens it. That write is the owner-pinned premise, and if it silently failed the tap would watch for nothing |
| submitter's reading → the claim "the bytes never left" | The submitter cannot see alice's manifest. It can only observe that no output arrived and that alice is alive and serving |
