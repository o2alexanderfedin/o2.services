<objective>
Make `EgressGuard.send()` refuse rather than annotate.

`egress.ts` already computes `const violation = this.#scan(message)` before
`await this.#inner.send(...)`. Today a match is recorded and the frame is forwarded
anyway; the class comment states that intent outright ("A match is recorded as a
violation rather than thrown"). 13-VERIFICATION.md measured the consequence: the
leaking shard completes as `agreed`, and `manifest.violations` has zero production
readers, so nothing can turn an observation into an outcome. ROADMAP criterion 1 was
amended on 2026-07-28 to require the refusal instead: *the bytes never leave the node,
and the running cross-owner job fails rather than completing as `agreed`.*

This plan makes that true inside `@o2/net`, and inverts every assertion in this package
that encoded the old behavior. Plan 13-05 proves the consequence at the `FabricNode`
level and across real `bin/agent.ts` processes; this plan proves the mechanism.

Purpose: an observer that reports after the fact is not what "data stays on the owner's
device" promises. A refusal costs one branch and makes the promise structural.
Output: `EgressRefusal` exported from `@o2/net`; a refusing `send()`; a `totalBytes`
that means what it says; and five inverted assertions plus three new ones, each of
which is watched failing in Task 3.
</objective>

  readonly to: string
  readonly bytes: number
  /** Set when the frame matched a registered sovereign value. */
  readonly violation?: string
}

export interface EgressManifest {
  readonly nodeId: string
  readonly ownerId: string
  readonly entries: readonly EgressEntry[]
  readonly totalBytes: number
  readonly violations: readonly string[]
}

// EgressGuard.send, as it stands:
async send(to: string, message: Uint8Array<ArrayBuffer>): Promise<void> {
  const violation = this.#scan(message)
  this.#entries.push(
    violation === null
      ? { to, bytes: message.byteLength }
      : { to, bytes: message.byteLength, violation },
  )
  await this.#inner.send(to, message)
}

// EgressGuard.manifest, as it stands:
totalBytes: entries.reduce((sum, entry) => sum + entry.bytes, 0),

How a `Transport.send` failure already propagates — `packages/net/src/rpc.ts`, the
justification this plan's error type is chosen against:

```ts
// The REQUESTING leg (rpc.ts:114-126) — a send failure is a first-class, typed error.
this.#transport.send(to, frame).catch((cause: unknown) => {
  ...
  reject(new RpcFailure({ kind: 'send-failed', to, detail: cause instanceof Error ? cause.message : String(cause) }))
})

// The RESPONDING leg (rpc.ts:189-194) — deliberately swallowed.
try {
  await this.#transport.send(from, this.#encode({ k: 'res', id, body: reply }))
} catch {
  // The requester will time out. Nothing useful to do here — and throwing
  // would surface inside the transport's delivery path.
}

export type RpcError =
  | { readonly kind: 'timeout'; readonly to: string; readonly afterMs: number }
  | { readonly kind: 'send-failed'; readonly to: string; readonly detail: string }
  | { readonly kind: 'closed' }
  | { readonly kind: 'undecodable'; readonly from: string; readonly detail: string }

export class RpcFailure extends Error { readonly detail: RpcError }
```
