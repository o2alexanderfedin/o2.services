<objective>
Give a registration a lifetime, and put its end after the frame it guards against.

`EgressGuard.reset()` clears `#entries` and deliberately not `#guarded`, and nothing in
production calls it. So `#guarded` grows for the process lifetime and `#scan` runs
`contains()` over every registration on every send. Plan 13-04 moves that cost onto the
correctness path — it is now what decides whether a frame leaves — which turns an
untidiness into an unbounded ceiling on how long a node can serve.

The release point is the whole of the difficulty, and it is why this is a plan of its
own rather than three lines in 13-04. **The frame being guarded against is the RPC
response**, and `rpc.ts` sends that response *after* `serveAgent`'s handler has returned,
which is after `inner.execute` has resolved. So releasing anywhere inside
`registerSovereignInputs` — the obvious place, where the guard and the label are both
already in scope — reopens the exact hole the registration exists to close: the reply
would be scanned against an empty set and forwarded. Task 3 plants precisely that and
watches it let the leak through, because that mutation is the justification for the
whole shape of this plan and an argument is not evidence.

The split this plan builds: `serveAgent` decides **what** to release, because it is the
only place that has parsed the task and knows the label. `rpc.ts` decides **when**,
because it is the only place that knows the reply frame has settled. Neither can do the
other's half.

Deliberately not built: no eviction, no cap, no least-recently-used policy. A guard that
silently stops guarding is the shape this project keeps removing, and
`.planning/PROJECT.md`'s "An optional hook with a silent default is a hole" is the
recorded decision that says so.

Purpose: per-frame scan cost becomes proportional to the sovereign tasks a node has in
flight, rather than to how long it has been running — without the release ever preceding
the scan it exists to feed.
Output: `release`/`registrations` on `EgressGuard`, an `afterSent` contract on
`RpcHandler`, a required `egress` option on `serveAgent`, and two mutations watched
failing.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| registration lifetime → the refusal it feeds | Every millisecond the release moves earlier is a frame the tap might not scan. The boundary is the response send, and it is enforced by which layer invokes the callback |
| `serveAgent`'s caller → the guard it supplies | A node that passes the sentinel when it has a real tap registers without releasing, and nothing fails |
| `rpc.ts` → what `afterSent` does | The generic layer invokes a callback it cannot inspect. A handler that returns a slow or throwing `afterSent` runs it inside the transport's delivery path |
