# Phase 15 · Plan 03 — wiring both factories, and repairing what the refusal breaks

> **Numbers in this plan are configuration choices, not derived claims. Any quantity
> describing runtime behaviour must be measured before it is written down anywhere,
> including in a source comment.**

**Closes (in part):** AUTH-03. Also **re-proves** DATA-09, whose only production-path test this
phase would otherwise make unreachable. This is the plan that turns the two mechanisms into a
running node's behaviour.

<objective>
Install a real `authorize` hook on both node factories, give it a key to verify against, and
expose that key on `bin/agent.ts` — then repair the four test files whose assertions this
refusal invalidates, deliberately and one at a time rather than as a bulk update.

Three things land together because they cannot land apart:

1. **`NodeSovereignty.ownerKey`** (15-CONTEXT.md decision 4). The serving node needs
   `VerifyOptions.ownerKey` and must not learn it from the request — a chain carrying its own
   root anchor would verify against itself. It goes on the existing record rather than beside
   it: `ownerId` and `ownerKey` name the same owner and must never disagree, and
   13-CONTEXT.md decision 2 already had to hoist the sovereignty default in both factories
   precisely because two independently-defaulted copies drift.
2. **Both factories wired**, plus `--owner-key` on `bin/agent.ts`. All three of this phase's
   success criteria name `bin/agent.ts`, so the evidence is Node-tier — but the browser tier is
   wired identically anyway, because leaving it on the sentinel would reintroduce exactly the
   two-disjoint-capability-sets shape whose deletion `fabric-node.ts:16-33` records, and it
   costs one argument.
3. **The four files this breaks.** Enumerated in 15-CONTEXT.md, and one of them breaks quietly:
   `egress-refusal.node.test.ts` already expects its submission to fail, so it would keep
   passing while measuring a completely different refusal and DATA-05's proof would silently
   evaporate.

Purpose: a mechanism is not wired until a production entry point calls it. After this plan
`bin/agent.ts` calls `verifyChain`, through `authorizeCapability`, on every sovereign dispatch it
receives.
Output: two production `authorize` arguments that are functions, a new flag, a shared chain
fixture for the node tier, and four repaired test files — with the DATA-09 proof restructured
rather than deleted.
</objective>
