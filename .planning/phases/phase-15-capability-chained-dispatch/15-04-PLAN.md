# Phase 15 · Plan 04 — the three criteria, across two real processes

> **Numbers in this plan are configuration choices, not derived claims. Any quantity
> describing runtime behaviour must be measured before it is written down anywhere,
> including in a source comment.**

**Closes:** AUTH-03, in the evidentiary form ROADMAP Phase 15's three success criteria name.
Plans 15-01 through 15-03 built and wired the mechanism; this plan is where it is measured, where
the measurement is shown able to fail, and where the three things it cannot measure are said
plainly, in those words.

<objective>
Prove ROADMAP Phase 15's three criteria against genuine operating-system processes spawned from
`bin/agent.ts`, then plant three mutations and watch what each one actually breaks.

"Started via `bin/agent.ts`" means here what `sovereignty-placement.node.test.ts` established and
`egress-refusal.node.test.ts:26-29` states outright: the nodes under test are real processes
sharing nothing with the test process but a socket, and the submitter is a `FabricNode` in the
test process, because the binary is serving-only and never calls `submitJob` — there is no third
process it could be. Same machine, different OS processes, which is this project's testing
standard.

One thing this plan will **not** claim. Criterion 1 says the hook verifies "before calling
`WebAssembly.instantiate`". Across a process boundary, no instrument in this repository observes
`WebAssembly.instantiate`, and this plan invents none. What it measures instead is the submitter's
own outbound frame count to the child: only the submitter holds the module, so a child that never
came back for it never compiled anything. The stronger reading — a counting `Executor` that reads
0 — exists in process, in `packages/net/src/capability-dispatch.test.ts` and
`packages/net/src/capability-authorizer.test.ts`, against the same code path minus the process
boundary; it is stronger because `packages/core/src/executor/wasm.ts:106` is the only caller of
`WebAssembly.instantiate` **on the `serveAgent` dispatch path** (`packages/aot/src/wasi-executor.ts:827`
is a second caller in the repository, off this path — verified 2026-07-28). A literal
`instantiate` counter across a process boundary is **unmeasured**, and would need a new hook.
That sentence goes in the test file and in the summary, in those words.

And one step further, because the disclosure above is still not the whole truth. Criterion 1's
"before calling `WebAssembly.instantiate`" clause, *at the process boundary*, can only be
**reported** as met. What is measured is a relation between two frame counts. Whether that
relation is the criterion or a proxy for it is a judgement written in prose, not a measurement,
and the summary must say that rather than let the passing relation stand in for the clause.

Purpose: this is the phase's evidence. Everything before it is machinery.
Output: one spawn test covering all three criteria with its frame counts *recorded rather than
predicted*, three mutation captures pasted verbatim, one known Phase 22 finding written into the
roadmap instead of left to be discovered, and an amended Phase 15 goal line that no longer claims
more than the phase delivers.
</objective>

`FabricNode` builds its `rpc` over its `egress` guard (`fabric-node.ts:351-355`), so **every**
outbound frame from the submitter is recorded — including the block replies it serves back to a
child. `node.egress` is the public field (`bench.ts` reads `requestor.egress`;
`egress-manifest.node.test.ts` passes `alice.egress`).

The exact refusal texts that must reach the submitter, from `capability.ts:101-122`, prefixed
`unauthorized: ` by `agent.ts:225` and returned verbatim by `remote-executor.ts:57`:

```
empty-chain     'no capability chain supplied'
expired         `link 0 expired at <ms>, now <ms>`
not-delegable   `link 1 was re-delegated, but its issuer was never granted "delegate"`
broken-link     `link 1 is issued by <hex>, but link 0 delegated to <hex>`
```
Do not reword these to make an assertion pass. Note what the first line does and does not carry:
`empty-chain` is the one failure kind with **no index**, because an empty chain has no link to
index. ROADMAP criterion 2's phrase "names the missing or expired link" is therefore satisfied at
two different strengths — the expired case names `link 0`, the missing case names the mechanism
by its own words and nothing more. Assert the empty-chain text with `toContain` on the exact
string and **do not** assert an index for it; a plan or a summary that claims the missing-chain
refusal names a link is claiming a string `capability.ts:101-122` never produces.

`packages/core/src/executor/fixtures.ts` — `MODULE_WRITES_PARTITION` ignores its input and emits
a record derived from the partition index and count read off the four-function host ABI, so a
`label: 'public'` copy of a sovereign task produces the identical output. That is what makes a
local single-node reference computation possible without a second chain.
