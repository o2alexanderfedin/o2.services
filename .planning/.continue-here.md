## The new track: WASM guest capabilities (design only, nothing built)

Spec: `docs/superpowers/specs/2026-08-17-wasm-guest-capabilities-design.md`, 391 lines, on `main`.
Goal is parity with a serverless programming model — handler, outbound HTTP, object store, KV,
sockets — without losing the auditable sandbox or the per-class integrity story.

**The premise the request started from was half wrong, and correcting it shrank the work.** Guests
are *not* limited to console I/O. `abi-router.ts` chooses per artifact between a WASI preview1 path
(`_start`, stdio — for elfconv-lifted binaries) and a **native path that is already
handler-shaped**: exported `run`, `input_len`/`input_read`/`output_write`/`partition`. Most of
"act like a Lambda" extends an ABI that exists.

Three findings from the tree that decided the design, each worth not re-deriving:

- **WASI preview1 has no `sock_connect`.** Confirmed against this repo's own implementation: the
  `sock_*` set is exactly `accept`, `recv`, `send`, `shutdown`. So the inviting `ERRNO_NOTSUP`
  stubs in `wasi-executor.ts` are a seam for *inbound* sockets only and cannot be the whole answer.
- **A guest `run()` is synchronous inside a worker and cannot yield**, and `SharedArrayBuffer`
  needs COOP/COEP that GitHub Pages cannot send. So **Asyncify is the baseline**, and
  `Atomics.wait`/JSPI become host-side fast paths that make asyncify's unwind path never execute —
  one binary, three hosts, no ABI fork.
- **Effectful work leaves the N-version lane because a replay performs the effect twice**, not
  because bytes might differ. No serialization change touches that. Protobuf specifically would be
  a regression — `encode.ts` already records why, and DAG-CBOR's refusal of NaN/±Infinity is what
  keeps WASM's nondeterministic NaN sign bit off every hashed path.

The design in one line: **five host imports** (`call`/`poll`/`read`/`write`/`close`), services as
DAG-CBOR `op` strings on that bus, capability grants as signed data. A new service costs zero new
imports, so the sandbox stays one auditable object rather than becoming the allow-list this
codebase has removed twice.

Two ideas in it that are load-bearing rather than decorative:

- **The fetch/compute split** recovers real verification for most network work. One node fetches
  under a grant, the response is pinned by CID, then N replicas compute over that CID with **no
  grant at all**. Only work whose *purpose* is the side effect needs the weak lane — far less than
  "anything that touches the network".
- **A sovereign-labelled task gets no egress grant.** Not a setting. Egress plus sovereign data is
  exfiltration, and that claim is the product rather than a preference.

**Nothing in the spec is measured**, and §0/§10 say so in those words. Asyncify's real size and
speed cost, `poll` round-trip latency across the worker boundary, and whether an exit node's extra
hop is tolerable all need measuring before layer 1 is designed in detail.

## The two determinism claims, stated at the width they were measured

- **Build reproducibility.** Three links of the same objects gave three modules differing only in
  the `name` section. `--strip-all` gives one hash, `33b6ba7f…`, at 8 087 408 bytes. **This removes
  the symptom, not the cause** — wasm-ld still emits those names in an unstable order. The 40 LLVM
  archives reproduce, and the module through them.
- **Run determinism.** The lift is byte-identical across runs and across four engines (Node V8,
  Chromium, SpiderMonkey, JavaScriptCore). The *intermediate bitcode* from native `elflift` is not.
  **AOT-03 separately records the FINAL `.wasm` from the full elfconv driver as byte-identical on
  one host, and that case runs and passes.** Different stages; both true. Do not repeat the
  unqualified claim "native elfconv does not equal itself".
  - **Amended 2026-08-17:** the native-scatter case asserted *two* runs must differ and two
    collided. Four-of-four-distinct is evidence the scatter is **wide**, not that any pair must
    differ — the comment claiming "two runs suffice" was an inference, not a measurement. It now
    samples four and asserts they do not all agree.

## Do not

- Do not re-add `set -e` to the build scripts. It cost a silent failure and an hour.
- Do not make `rm -rf build-wasi` unconditional. It threw away every compiled object per run.
- Do not read a bare `MODE` in a script. vitest exports `MODE=test` from Vite; the link script
  died on `MODE must be command or reactor, got test`. It is `LINK_MODE` now.
- Do not declare `sigaltstack`, `getrlimit`, `setrlimit` or `posix_spawn` in
  `tools/aot/wasi-compat`. cmake probes them by compiling AND linking, so declaring them flips
  `HAVE_*` on and compiles code back in. It makes MORE work.
- Do not trust a shell probe with no sanity arm. One inventory reported every identifier missing
  because this shell is **zsh** and an unquoted `$FLAGS` reached clang as a single argument. The
  same trap silently emptied a `grep` list later the same day via an unmatched glob.

  the cheap guards — and a caller-set guard reddened on the very next e2e run, reading a register
