## A NEW SHARED-TREE HAZARD, DIAGNOSED AND FIXED IN FLIGHT

**`git commit -F -` from a tool-invoked shell deadlocks the entire repository.** A heredoc bound to
a *trailing* command, so git read its message from the shell's inherited stdin — a unix socket with
no writer — and blocked forever holding `.git/index.lock` against every agent.

Diagnosed by measurement, not plausibility: no children (the hook had already run and exited, which
is why the log file held guard output), fd 0 a unix socket, 0.0% CPU in state `SN` for 6+ minutes,
and `.git/COMMIT_EDITMSG` **older than** `.git/index.lock`, so the message was never written.
Resolved with `SIGTERM` to the `git` process only — git removes the lock on term — and the lock
released in 1 s with nothing lost.

**Rule: never `git commit -F -` from a tool shell. Use `-m`, or `-F <real path>`.** And
`Unable to create '.git/index.lock': File exists` is normal contention — wait and retry. Only a
lock whose owning process is *provably dead* is safe to remove.
