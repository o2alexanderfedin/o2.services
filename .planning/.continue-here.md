# BLOCKING CONSTRAINTS — Read Before Anything Else

> Each was learned through an actual failure or an explicit owner correction.
> Acknowledge every one before proposing work.

- [ ] **ALL NODES HAVE EQUAL FUNCTIONALITY.** No tier, no class, no lesser node. Every
      node executes tasks, holds blocks, serves records, hosts reduce combines, and
      takes quorum slots on identical terms. **The only difference is discovery**: a
      browser cannot bind a listening socket, so it cannot be a seed a newcomer dials
      cold and must be found through a relay that can. Once connected, peers are
      indistinguishable.
      **Structural mitigation:** if a decision keys on *what kind of node* something
      is, it is wrong. The only legitimate use of `discoverability` is
      shared-dependency analysis over the discovery graph. The owner stated this three
      times because the first two applications were too weak — the words were changed
      while `backbone`/`edge` survived as classes.

- [ ] **DEMO-04: no deploy workflow file may exist in the repository at all** — absent,
      not disabled. Publishing is public disclosure, and EPO/China rights for anything
      disclosed are already permanently forfeit. Deployment stays a separately-triggered
      human action. **This binds Phase 9 directly**, which is the next unit.

- [ ] **Vocabulary discipline is a hard constraint on Phase 9.** No "mining",
      "hashrate", "earn", "credits", or "tokens" anywhere in the UI *or the repository*.
      The demo ships with a plain-language policy page written for a human blocklist
      reviewer, and pre-registered appeal paths.

- [ ] **Do not reintroduce static determinism analysis.** An admission gate parsing
      WASM instruction streams was built, hardened, fuzzed, then deleted (1,214 lines,
      `afb3cad`). Divergence is *detected* by byte comparison, never *predicted*.

- [ ] **Verification never spans different implementations.** It compares the *same*
      `moduleCid` on independent nodes.

- [ ] **Do not write an allow-list for host imports.** `WebAssembly.instantiate`
      already refuses any import the host does not supply, and names it.

- [ ] **The kernel must never require `crypto.subtle`.** A LAN origin is not a secure
      context. `multiformats/hashes/sha2` uses WebCrypto and silently broke every CID
      on any non-localhost page — while the node still *started*, so it failed at the
      first block rather than at join. Hashing is `@noble/hashes`, pure JS.
      **Structural mitigation:** `insecure-context.browser.test.ts` deletes
      `crypto.subtle` and requires hashing to survive.

**Do not proceed until all boxes are checked.**

## Critical anti-patterns

| Pattern | What happened | Prevention |
|---|---|---|
| Prediction instead of detection | Tried to prove statically that a computation could not diverge, rather than running it twice and comparing bytes. | Before adding analysis, ask what the existing comparison already catches. |
| Reimplementing the platform | Hand-wrote an import allow-list, a WASM validator, and a `ComponentLogger` that crashed every dial. | Test whether the runtime already does it, in a throwaway script, first. |
| Applying a correction to the words only | Told browsers are equal peers, I rewrote comments but kept `backbone`/`edge` as classes and left the quorum rule discriminating on them. | After a design correction, grep for the *mechanism*, not the vocabulary. |
| Believing my own summary | A table row read "3 servers behind one relay → refused". Sounded right; concealed a real false positive. | Restate rules as concrete tables and probe each row. |
| Trusting an unfalsified check | Phase 1's opcode table had 6 of 18 entries wrong — a false negative in a security gate. | Every new checker gets a planted violation before it is trusted. |
| **Writing the anti-pattern already in this table** | Phase 7's disagreement test wrapped every assertion in `if (outcome.disagreements.length > 0)` — a condition that could never be true. "Assertions guarded by an `if()`" was *already listed here*. Knowing the rule did not prevent breaking it. | **Mutation-test every new guard.** Delete the behaviour, run the suite, require a failure. Only that catches it. |
| A fake faster than the real thing | Three Phase 7 defects — a hang, an unexamined disagreeing copy, an OOM spin — were invisible to a suite whose dispatch resolved on a microtask. | Any timing claim needs a test with a real endpoint in it. |
| A unit living in a name | `JobResult.grossNodeSeconds` held *bytes*. The ratio was fine; the absolute would have been published wrong by an unguessable factor. | Rename rather than document — a comment does not travel with the number into a report. |
| A documented bound that is not enforced | The churn loop's header promised silence gets a bounded wait; the code never read `expiresAt` anywhere. | Whenever a comment states a guarantee, grep for the mechanism. |

<decisions_made>

- **All nodes equal; only discovery differs.** See the blocking constraint.
- **Disagreement is reported, never voted on** — in execution, reduce, quorums, and now
  speculation. At R=2 there is no majority anyway.
- **Sovereignty is structural**: one exported `eligibleNodes` gate, and every placer —
  including speculative re-dispatch — routes through it.
- **Derive topology, never agree on it**: the reduce tree is a pure function of sorted
  partial CIDs. HRW ranking *is* the fallback list.
- **A lease is a deadline, not a lock** (Phase 7). Nobody releases it and no keeper
  notices the coordinator left, so "never orphaned leases" needs no cleanup code.
- **Liveness changes who computes and when, never what the answer is** (Phase 7). The
  invariant every churn mechanism rests on; re-check it first if that code changes.
- **A node failure and a task failure warrant opposite policies** (Phase 7). Collapsing
  them makes 30% node loss unsurvivable rather than merely slow.
- **Pre-registration is an ordering, not a document** (Phase 8). The methodology commit
  contains no harness and no number, so `git log` proves it.
- **A fast failure is not a fast run** (Phase 8). Excluding incomplete runs from
  makespan turned a silent 19/19 failure into a visible bug.
- **Relay capacity is capped by inbound limits, not reservations.**
  `INBOUND_CONNECTION_THRESHOLD` is 5 **per host**. This bit twice — once in Phase 3,
  again in Phase 8 where it killed two benchmark ladder rungs.
- **A relayed circuit cannot carry a job.** The relay is a signalling channel; the data
  path is WebRTC.
</decisions_made>

## Environment notes

- **Node 23.11.0 is the host runtime and is not LTS.** Outside vitest's declared range,
  so every install prints `EBADENGINE`, and the `bin/` scripts rely on experimental
  native type stripping. Everything passes; `STACK.md` specifies Node 24.
- **Test file suffixes are load-bearing.** `*.browser.test.ts` browser-only,
  `*.node.test.ts` Node-only, `*.e2e.test.ts` drives Playwright itself and runs with
  `fileParallelism: false`.
- **`purity.node.test.ts` gates the portability tiers.** A new package must be added to
  `PORTABLE` or `DUAL_TARGET` there or the invariant silently misses it. `@o2/bench`
  was added to `PORTABLE` in Phase 8.
- **Vite `optimizeDeps` pre-bundling must stay on** — several libp2p transitive deps are
  CommonJS (`netmask` via `@libp2p/utils`).
- **The seed server needs `allowedHosts: ['.local']`.** Vite allows only localhost and
  IP literals by default, and IP-only tests could never have caught it.
- **Chromium under automation never reports a page as hidden.** `bringToFront()` fires
  no `visibilitychange`, headless or headed.
- **Running the benchmark:** `node --experimental-strip-types packages/node/src/bin/bench.ts`
  (add `--quick` for a 6-iteration smoke run). Writes `.planning/BENCHMARK-RESULTS.md`
  and `.planning/bench/raw.json`.
