### The two determinism claims, stated at the right width

- **Build reproducibility.** Three links of the same objects gave three different modules, all
  13 565 617 bytes with every section the same size; the first differing byte, 8 087 429, is the
  first byte of the `name` section. `CODE` and `DATA` reproduce exactly. `--strip-all` gives one
  hash, `33b6ba7f…`, at 8 087 408 bytes, and the same bitcode out. **This removes the symptom, not
  the cause** — wasm-ld still emits those names in an unstable order.
- **Run determinism.** The lift is byte-identical across runs and across four engines. The
  *intermediate bitcode* from native `elflift` is not — four runs, four hashes.
  **AOT-03 already records the FINAL `.wasm` from the full elfconv driver as byte-identical on one
  host, and that case runs and passes.** Both are true; they are different stages. Do not repeat
  the unqualified claim "native elfconv does not equal itself".

## How to rebuild the wasm translator

```bash
bash tools/aot/build-wasi-llvm.sh      # ~10 min from scratch, skips what exists
bash tools/aot/build-wasi-deps.sh      # glog + gflags
bash tools/aot/link-elflift-wasm.sh    # -> $ROOT/elflift.wasm, 8 087 408 bytes
node tools/aot/run-elflift-wasm.mjs --elf <aarch64-elf> --semantics <aarch64.bc> --out out.bc
npx vitest run --project node tools/aot/elflift-wasm-determinism.node.test.ts
npx vitest run --project browser packages/aot/src/elflift-cross-engine.browser.test.ts
```

State outside the repo, in `/Volumes/ProjectsSSD/o2-wasi-llvm/`: `lib/` (40 archives), `obj/`
(27 objects), patched `wasi-sdk/`, `llvm-16/`, `elflift.wasm`, and `fixtures/` — `hello_static`
and `aarch64.bc`, extracted from `ghcr.io/yomaytk/elfconv:arm64`, which is present locally. The
browser spec needs those three staged into `packages/aot/artifacts/` (gitignored).

**`--bitcode_path` is a DIRECTORY, not a file**, despite the name: remill searches it for
`<arch>.bc`. That cost one run.

## Do not

- Do not re-add `set -e` to the build scripts. It cost a silent failure and an hour.
- Do not make `rm -rf build-wasi` unconditional. It threw away every compiled object per run.
- Do not read a bare `MODE` in a script. vitest exports `MODE=test` from Vite; the link script
  died on `MODE must be command or reactor, got test`. It is `LINK_MODE` now.
- Do not declare `sigaltstack`, `getrlimit`, `setrlimit` or `posix_spawn` in
  `tools/aot/wasi-compat`. cmake probes them by compiling AND linking, so declaring them flips
  `HAVE_*` on and compiles code back in. It makes MORE work.
- Do not trust a shell probe with no sanity arm. One inventory reported every identifier missing
  because this shell is **zsh** and an unquoted `$FLAGS` reached clang as a single argument. The
  same trap silently emptied a `grep` list later the same day via an unmatched glob. Control arms
  caught both.
- Do not gate a commit on vitest alone. A commit went in on a red `tsc --noEmit`.
- **Do not infer contention from load average.** It predicted nothing here: at load 9.58 the
  measured CPU share was 0.774, *above* both regimes in which a load-sensitive defect reproduces.
  Use `/usr/bin/time -p` and the derived `(user+sys)/real`. Measure the process, not the machine.
