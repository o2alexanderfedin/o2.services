# BLOCKING CONSTRAINTS — Read Before Anything Else

> Each was learned through an actual failure or an explicit owner correction.
> Acknowledge every one before proposing work.

- [ ] **ALL NODES HAVE EQUAL FUNCTIONALITY.** No tier, no class, no lesser node.
      **The owner has now stated this four times.** The fourth was this session, and it
      was right again: `RelayNode` was a class that *structurally could not compute* —
      no blockstore, no executor, no `RpcEndpoint`, never called `serveAgent` — while
      `FabricNode` could bind a socket and never relayed. Two classes with artificially
      disjoint capability sets: `backbone`/`edge` wearing new words. **`relay-node.ts`
      is now deleted** and relay capability is *derived* from whether a node binds a
      listening address. **The only difference is discovery.**
      **Structural mitigation:** if a decision keys on *what kind of node* something is,
      it is wrong. Grep for the mechanism, never the vocabulary. Three of the four
      corrections were absorbed as renames; only the fourth removed the class.

- [ ] **DEMO-04: no deploy workflow file may exist in the repository at all** — absent,
      not disabled. Now *enforced* by `disclosure-gate.node.test.ts`, which also checks
      by content so relocating a workflow does not evade it, and forbids any
      publishing script. `build:demo` builds and publishes nothing.

- [ ] **Vocabulary discipline**, enforced repository-wide by `vocabulary.node.test.ts`
      with reasoned, auditable exemptions. Note it matches `earn` inside `learning`.
      **It skips any file containing a NUL byte** — see the open defects below; that is
      currently an unregistered permanent exemption waiting to happen.

- [ ] **Do not reintroduce static determinism analysis.** Built, hardened, fuzzed,
      deleted (1,214 lines). Divergence is *detected* by byte comparison, never
      predicted. The Phase 10 ELF pre-screen is permitted because it predicts whether a
      *toolchain* can consume an input — being wrong costs a failed build, not a wrong
      answer. Do not let it drift.

- [ ] **Do not write an allow-list for host imports.** `WebAssembly.instantiate` already
      refuses any import the host does not supply, and names it.

- [ ] **The kernel must never require `crypto.subtle`.** A LAN origin is not a secure
      context. Hashing is `@noble/hashes`, pure JS. The Phase 9 start-probe checks
      `crypto.getRandomValues` for exactly this reason.

**Do not proceed until all boxes are checked.**

## Critical anti-patterns

| Pattern | What happened | Prevention |
|---|---|---|
| Prediction instead of detection | Tried to prove statically that a computation could not diverge, rather than running it twice and comparing bytes. | Before adding analysis, ask what the existing comparison already catches. |
| Applying a correction to the words only | **Four times now.** Told all nodes are equal, I renamed things while `backbone`/`edge` survived as classes — most recently as `RelayNode`, a node that could not compute. | After a design correction, grep for the *mechanism*. Ask: what construction path still yields a node that cannot do X? |
| **Writing the anti-pattern already in this table** | Phase 7's disagreement test wrapped assertions in a condition that could never be true. Phase 10 repeated the shape: `cache-key.test.ts` had only relative assertions, so the whole hashed record could change unnoticed. | **Mutation-test every new guard.** Conformance vectors are hardcoded literals, never computed. |
| A documented bound that is not enforced | The churn header promised a bounded wait and never read `expiresAt`. `BootstrapInfo.seedPeerId` promised a lone phone a peer while that node listened on plain TCP, which no browser can dial, and published no address at all. | Whenever a comment states a guarantee, grep for the mechanism. |
| **Asserting the attribute, not the screen** | The always-visible bar was always visible: `#bar { display: flex }` is an id selector and the browser's `[hidden]` is an attribute selector, so the id rule won. Every test asserted the `hidden` attribute, which was always correct. Found on a phone. | `isVisible`, never `getAttribute('hidden')`. |
| A substring match against a structured string | `address.includes(peer)` against `<relayAddr>/p2p-circuit/webrtc/p2p/<target>` matched the *relay's* id inside every address, so every peer was skipped: `dialed: []`, `failed: []`, nothing attempted, no error. Two devices sat on one relay and never met. | Parse the component. And treat "nothing attempted **and** nothing failed" as a signature worth asserting against. |
| A fake faster than the real thing | Phase 7's hang, unexamined disagreement and OOM spin were all invisible to a microtask-resolving fake. | Any timing claim needs a real endpoint. |
| A unit living in a name | `grossNodeSeconds` held bytes. | Rename rather than document. |
| **"Was not run" is not "works"** | DEMO-01's multi-machine half was about to be closed by reasoning from Phase 3's transport proof. The owner ran it and it found two defects the whole e2e suite had passed over. | Run it. The gap between "should work" and "was run" was two real defects wide. |

### Phase 9, and what the owner's two-device run cost to skip

Consent is a value, not a check: `GrantedConsent` is minted only by `grantConsent` and
`start` takes one, so a caller without one fails to compile. Nothing touches CPU *or the
network* before it. Stop calls `Worker.terminate()`; the probe proving it is a bare
`loop br 0` that no flag or governor can reach. Six mutations planted, six caught.

Then the owner ran it on an iPhone and a laptop, and it found **two defects the whole
e2e suite had passed over** — the always-visible bar that was literally always visible,
and two devices that could never have found each other. Both fixed and now tested.

Then three more, each from the owner looking at a number and asking why:

- **The relay was counted as a peer and given work.** `transport.peers` is every libp2p
  connection and a reservation *is* a connection, so `executorsFor` handed a third of
  the shards to a node that cannot run them. Fixed by **asking, not classifying**: an
  offer is the cheapest request that proves a peer speaks the protocol.
- **The lone-visitor peer was a comment, not a mechanism** — that node listened on plain
  TCP and published no address.
- **`RelayNode` could not compute at all.** See the blocking constraint.

<decisions_made>

- **All nodes equal; only discovery differs.** Now structural: one Node-side class,
  relay capability derived from binding a listening address.
- **Ask, never classify.** Whether a peer computes is established by an offer, not by a
  field. A node relaying for nobody and a node that cannot relay give the same answer,
  deliberately — a distinguishing field would be a kind to branch on.
- **Consent is a value, not a check** (Phase 9). No test-only bypass.
- **Cooperative stopping cannot exist for WASM.** A synchronous `run()` admits no flag.
  Off-main-thread execution is the requirement, not an optimisation.
- **A metric publishes its own blind spot.** A node that cannot reach a peer cannot
  report that it cannot reach a peer.
- **Overlapping views merge by maximum, never by sum** — otherwise eight peers multiply
  the sample size by eight while every percentage stays plausible.
- **Chromium throttles timers in a background tab** (measured: 400 ms poll → one tick
  per second). Anything a visible surface depends on must be pushed.
- **A cube must fix the *constrained* variables** (Phase 9). Ordering by degree moved
  the colouring wall from n=205 to n=600 and made more nodes reach further.
- **`exhausted` and `budget` must stay different answers.** One is a proof; the other is
  a shortage of compute.
- **Never trust elfconv's exit code** (Phase 10). It exits 0 on binaries it cannot fully
  translate.
- **Same-host reproducibility is not reproducibility.** Two runs here were byte-identical;
  cross-machine is **unmeasured**, and there is a pointer-keyed map and a
  `std::set<BBBag*>` in the register-promotion pass whose iteration order shapes the IR.
</decisions_made>
