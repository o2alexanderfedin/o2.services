> Each was discovered through failure **in this session**, not predicted.

- [ ] **A green run is not a proof, and a silent one is worse.** Three errors this
      session were caught by a COUNT moving the wrong way, never by a red test: the
      skip count going `1 → 2` with nothing printed beside it; the perf-suffix literal
      count going `2 → 3` because a COMMENT quoted the literal it was explaining; the
      project file count `209 → 198` that `slow-specs` did not notice. Before trusting
      green, name what would have gone red.
- [ ] **On a SKIPPED vitest test, `console.log` and `ctx.skip(note)` are both swallowed
      by the default reporter.** Only `process.stdout.write` reaches the terminal.
      Measured on vitest 4.1.10. A skip nobody can read is a fail-open.
- [ ] **Never write a measured value carried out of a context summary.** Two premises in
      a subagent brief were false for exactly this reason and would have written a
      number beside an option that has no number in the code. Re-derive with one
      command, or mark it in the brief as unverified.
- [ ] **A column-0 comment inside YAML frontmatter breaks gsd-sdk's parser nesting.**
      It silently lifted a nested key to top level. Indent comments into the mapping,
      and verify with a differential parse before/after rather than by eye.

- [ ] **A plant that stays green, or reddens the WRONG assertion, proves nothing — and three
      of this session's plants did exactly that.** `PLANT-N` threw in the outer function the
      re-attempt does not call, so two independent stand-ups each retried once and the file
      passed; `PLANT-G` tripped the assertion ABOVE the one it was aimed at, because the
      target was outbound as well as relayed; `PLANT-R` set a 1 ms budget and stayed green,
      because `until` evaluates its predicate once before checking the deadline. Each was
      re-done and each is recorded as retracted in its commit message. **Read WHICH assertion
      rendered, never just the exit code.**
- [ ] **`console.*` is swallowed on a PASSING test and printed on a FAILING one.** Measured
      2026-08-26 on vitest 4.1.10 with a two-case probe: `console.log`/`info`/`error` all
      absent from a passing test's output and all present from a failing one;
      `process.stdout.write` and `process.stderr.write` reach the terminal in both. So a
      diagnostic meant to be read on GREEN runs — a calibration, a reading — must be a direct
      stream write, and three files were converted for that reason. The narrower claim already
      recorded here, about SKIPPED tests, remains true and is a special case of it.

- [ ] **A BLOCKER IS THE MOST EXPENSIVE THING TO REPORT, AND I REPORTED A FALSE ONE.** I wrote
      that the inbound listener "cannot be written" from a single failing command —
      `ERR_PACKAGE_PATH_NOT_EXPORTED` — and it reached FIVE documents before the owner caught
      it in one line. Two errors, and the second is the larger: (a) that is **Node's** resolver
      refusing a package specifier, while the one that matters here is esbuild's, and a FILE
      PATH bypasses `exports` entirely; (b) three documents under `.planning/research/v2.0/`
      already covered the listener — `STACK.md:146` says it *"is already built"*. **Before
      writing "blocked" anywhere: name which instrument produced the failure and ask whether it

- [ ] **A rejected tool call can still have written to disk.** The owner stopped a command that

      interrupted command, read `git status` rather than assuming nothing landed.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Guard models structure, not truth | `state-frontmatter` passed 6/6 over `status: completed` on an unstarted milestone and `total_phases: 42` against 13. It checked that keys were PRESENT. Same shape: `slow-specs` reimplemented the config's globs and never read the config back, so it stayed green while modelling a project that no longer existed. | blocking | When a guard checks a field exists, ask what a FALSE value in it would look like and add the cheapest closed-vocabulary or cross-file count check. `opt-in-only-sources` reads the config text back and caught the same change instantly — copy that. |
| Discrimination rule in the message, not the condition | `late-combine` printed "ALL THREE inflated together is a starved host, not this code" and then failed anyway. It could tell the two apart in prose and not in the assertion. | blocking | If a failure message explains which of two causes it is seeing, that explanation belongs in the condition. Move it; do not raise a budget. |
| Skipping on a count instead of on an identity | A count-only skip in `discovery-agents` would hide an issuer-gate regression: a genuine defect drops the same one executor a starved host does. | blocking | Key the discriminator on WHICH item is missing, never on how many. If the print that would say which does not exist, writing it is part of the work. |
| Raising a budget to close a red | Raising the 900000ms hook budget would have addressed 2 of 5 container failures and said nothing to the 3 killed by a signal. | advisory | Measure `(user+sys)/real` first. Below ~0.1 the process is WAITING, so a wall-clock budget over it measures the host and never the code — remove the contention instead. |
| Editing the tree while another agent's specs run | `coverage-agents`, `discover-arm` and `bench-attestation` snapshot `git status --porcelain` around themselves. Editing `.planning/BENCHMARK-RESULTS.md` mid-run reddened one of them. | advisory | Hold edits and the index while any sweep is in flight. Four `tools/aot` specs also read git status. |
