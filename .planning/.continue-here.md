### Two things worth carrying about method

- **Ratification reads no clock, deliberately.** The obvious implementation calls
  `verifyCertificate(…, Date.now())`, which refuses `not-yet-valid` on a **strict**
  `issuedAt > now` — provider's clock against the visitor's. A machine one second slow would
  have had an honest certificate refused, fatally on the browser tier.
- **`relayIds` is sorted on both sides.** `enrol` signs `[...relayIds].sort()`; `requestEnrollment`
  does not. A naive compare would accuse **honest** providers, and only when a caller's ids
  arrived unsorted — the worst shape of intermittent.

## Not done, and why

**The visitor-enrolment feature is NOT built.** Three full design rounds, each returned
FIX-FIRST by three independent adversarial reviews: **7, then 6, then 10 blocking defects**.
Every citation spot-checked held against the tree.

**The diagnosis is mine, not the reviewers'**: I let the scope grow each round instead of
decomposing. Round 3 designed a whole issuer hierarchy and still never wired the visitor path it
existed to serve. Ratification was the first piece of the decomposition and it landed clean.

The rejected designs, so nobody re-proposes them:

1. **Passphrase identity** — the passphrase is typed into an input the ORIGIN serves, so one line
   of the origin's own script reads it. Constant salt + no production revocation + 30-day
   certificates = permanent cross-origin impersonation.
2. **Flat certificate with the anchor from the page** — `demo/main.ts:350` verifies peers against
   `new Set([held.issuer])`, so accepting a certificate promotes whoever served the page to the
   authority on every other peer, and `discoverExecutors` then excludes every node that provider
   did not certify. The origin curates who you compute with.

**Owner rulings that stand**: the device key is a non-extractable `CryptoKey` (measured working,
secure contexts only — `crypto.subtle` is **absent** on a LAN origin, so the QR-code path cannot
create an identity); a tab's capability follows from what it **holds**, not from a round trip;
adopt RFC-0003's hierarchy, **not** X.509.
