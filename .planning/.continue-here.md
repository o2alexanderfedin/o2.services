# ⚠ THE DECISION — `PeerVerifier` settles a verdict once and never revisits it

Found by plan 17-06 on its first test failure, **deliberately not fixed**, held under
Rule 4. It is the only open defect in the merged tree.

`PeerVerifier` decides a peer's verdict on `peer:connect` and never asks again. **A node
that enrols *after* a peer has already connected to it is permanently excluded by that
peer.** Observed directly rather than inferred: an enrolled tab holding a valid certificate
sat at `'not asked yet'` for 20 seconds.

**It is not browser-specific.** `FabricNode` also dials its provider before `serveAgent` is
up, so the same window exists on the Node tier.

Why it was not fixed: every candidate changes how often a node re-asks its peers **across
the whole fabric** — re-ask on a timer, re-ask on a records-changed push, or re-ask on
first refusal. That is a fabric-wide behaviour decision, not a bug fix, and it interacts
directly with discovery. **Phase 18 owns the dial path this defect lives on, so decide
before Phase 18 is planned.**

# THE LESSONS THIS SESSION COST THE MOST TO ESTABLISH

**1. A worktree has no `node_modules`, and the obvious fix is silently wrong.** The main
install's `@o2/*` are **relative** symlinks resolving back to the main checkout, so
symlinking wholesale makes `tsc` and `vitest` verify the wrong tree and report clean
**without reading a line of the agent's changes**. Build a farm — third-party from the main
install, every `@o2/*` repointed at the worktree — and **prove it** with
`createRequire(...).resolve('@o2/core/package.json')`. Every executor prompt must carry
this. Saved as a project memory.

**2. Run vitest by project, never by bare path.** Four projects: `node`, `browser`
(chromium+firefox+webkit), `e2e`, `perf`. A bare path filter fans out across all four and
exceeded ten minutes twice before this was understood.

**3. `vocabulary.node.test.ts` scans `git ls-files`.** Run it *after* committing or it does
not read your work. A verification pass reported its guards green from a run that could not
have read the file it was about to write — and then the entry documenting that failure
**failed the same guard**, because describing forbidden text meant quoting it.

**4. Assume every `file:line` in an unexecuted plan is stale.** Phase 15's four plans
carried **41** wrong citations; Phase 16's and 17's carried dozens more. Several were
*wrong* rather than drifted, and **six would have shipped a false statement into production
source** — a security claim that NET-08 had not landed when it had, a citation to a test
that tests something else, and a `userKey: PublicKeyHex` where only a private key can sign
(every enrollment would have been refused, with a correctly-named refusal).

**5. A reddening claim is a hypothesis, and roughly a quarter were wrong.** Four separate
`<proof>` claims failed, each for a different reason: a narrowing rejected the field first;
two derivations were byte-identical by the plan's own premise; two values encoded
identically on the wire; a placeholder answered with the same sentinel. **Plant every
reddening claim; never restate one.**

**6. A fabric cheaper than the real thing cannot observe a gate keyed on the real thing's
configuration.** Twice a phase discovered its own goal did not work in production at all —
combine refused on every real node, browser peers excluded from the fabric entirely. Both
invisible to in-process fabrics, both found by real processes.

**7. A comment asserting a fact about every call site is a claim with an expiry date.** The
combine gate's comment was true when written and Phase 15 falsified it silently one phase
later. If it matters, a test must hold it.

**8. A refusal that names the wrong thing is a defect even when the job correctly fails.**
Hit four times. Assert the refusal **text**, never merely its kind.

**9. The read count, not the reason string, proves a bound's placement.** A cap planted
*below* a fetch loop left both refusal-text assertions green while reads went 0 → 2. Same
shape as NET-08.

**10. Site a threshold between two measured populations, never by arithmetic.** Used for
`transport-bounds.node.test.ts`'s load gate (passes 7.70–11.55, failures 12.4/12.4/18.12,
gate at 12) exactly as the file already did for its byte threshold.

**11. `git commit --amend` on `develop` is an ordinary commit and the hook blocks it**, even
for a merge commit. The merge message has to be right at merge time, via `git merge -m`.
