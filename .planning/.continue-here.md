## What shipped: the enrolment signer port

`requestEnrollment(nodePrivateKey, user: UserSigner | Uint8Array, fields)` is async. The
second parameter is a **capability to sign** rather than the material to sign with, so a
visitor's owner key can be a non-extractable `CryptoKey` the page that rendered it cannot
read. `subtleUserSigner` adapts a `CryptoKeyPair`; `seedUserSigner` is the backbone's arm;
both tiers' `enrollment.userPrivateKey` takes `Uint8Array | CryptoKeyPair`.

**The WebCrypto call is in `ed25519-backend.ts`, not `enrollment.ts`**, because CRYPTO-01
permits exactly one such file and `one-crypto-implementation.node.test.ts` reported the
second one **by path** within minutes of it being written.

**45 files, against an estimate of 15** — helper fixtures cascade when a signing API goes
async. Budget for that shape next time.

### Four guards fired, and each was fixed at its cause

Reusable, because this is what a change to a signing API costs *in this repository*:

1. **CRYPTO-01** named `enrollment.ts` by path. The call moved; the module's "pure module,
   one stated exception" header is true again **by re-measurement rather than assertion**.
2. **The reachability collision bound** read 17 against 16 — two object-literal `sign`
   methods in one file. **Not raised.** Once the WebCrypto call moved out, that arm has
   nothing left to implement and delegates as a property.
3. **The enrolment-cost ratio, and this is the one to carry.** Verifying the `ownerProof`
   on *both* arms put an `ed25519.verify` into the attacker's mint, and
   `enrollment-dos.node.test.ts` priced it instantly: **1.22 against a floor of 1.5**, down
   from a recorded 2.96–3.16. Those floors are lower bounds on an exposure this repository
   has **not** removed, so halving one by accident and restating it would have been moving a
   cost model sideways. **Derivation and verification are alternatives, not a stack** — the
   check now runs only where a *caller* supplied the pairing.
4. **AUTH-04's caller-side guard changed shape and catches strictly more.** `userKey` used
   to be derived, making a stranger's key unspellable; a signer supplies its own public
   half, so it became a check (`UserKeyMismatchError`) — which also catches a
   `CryptoKeyPair` whose halves came from two generations. Derivation never could.

## A measurement lesson worth more than the fix it produced

`late-combine.node.test.ts` asserted `pausedDispatchMs >= RPC_TIMEOUT_MS` and failed at
*"expected 1499.6706249999997 to be greater than or equal to 1500"* — 0.33 ms short, on an
otherwise green solo run. **That was not the dispatch returning early.** The RPC timeout
fires on libuv's cached loop time; the span is measured with `performance.now()`; Node
guarantees nothing about the two agreeing.

Measured on this host rather than argued — `setTimeout(1500)` × 40:

```
fired early (< 1500 by performance.now): 1/40
min 1499.2653ms  median 1501.1710ms  max 1505.8683ms
worst deficit: 0.7347ms
```

One libuv tick of slack, **sized from that measurement and not from the deficit that
exposed it** — which is the difference between reading a bound and widening one. Watched
red by feeding the assertion a healthy-path span: *"expected 24.096457999999984 to be
greater than or equal to 1499"*. An early return is three orders of magnitude away; nothing
behavioural fits in the tick.

**The general form: before relaxing any wall-clock assertion, measure the clock.**

## What NOT to do, each earned

- **Do not widen a threshold to buy a green.** Three separate opportunities arose today and
  all three were refused: the DoS ratio (fixed the code), the collision bound (fixed the
  code), CRYPTO-01 (moved the code). The one relaxation made — one libuv tick — was sized
  from a measurement of the clock, and it was watched red.
- **Do not quote load average to decide whether a run is trustworthy.** It counts
  I/O-blocked threads. Read `(user+sys)/real` off `/usr/bin/time -p`. The `node` project's
  green band is **≥ 0.830**; today's runs read 0.951, 0.594, 0.780 and 0.957, and only the
  0.951 and 0.957 ones said anything about the branch.
- **Do not polyfill a non-extractable key.** Any JS implementation holds the material where
  the origin can read it — the API shape without the property, which is worse than absence
  because it looks safe.
- **Do not add an export with no production caller** to dodge a refactor's cost.
  `reachability-guard.node.test.ts` reddens on exactly that.
- **Do not edit tracked files while a suite is running.** At least two specs snapshot
  `git status --porcelain` around themselves.
