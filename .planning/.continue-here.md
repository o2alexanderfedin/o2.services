## Three lessons worth not relearning

**A mutation that PASSES is a finding, not a nuisance.** Silencing the relay watcher's
`onFailure` changed nothing, because two paths reported one event and the settle-wait
guaranteed the replay always won. **A listener registered after a settle-wait is dead by
construction.** One path now; the same mutation times out.

**Renaming a test can silently detach a mutation-ledger entry.** M14 keys on a test *title*;
M8 keys on a literal source *line*. Both drifted this session and both were caught by the
guard. When re-aiming one, follow the new form exactly — do **not** loosen `find` to a
prefix, which would keep matching while the half it names stopped running.

**Never record a duration from a red run.** Three candidates were discarded on that rule
(6.24 s, 5.91 s, and a whole span table). The rule is now written into `vitest.config.ts`.

## The DATA-10 design decision — do NOT merge the two mechanisms

The obvious fix for criterion 7 was to never release the `EgressGuard` hold. **That is wrong
and the source says so in advance**: `egress.ts`'s `guard()` forbids eviction because *the
set is bounded by giving holds back, which is a bound somebody can be shown*, and
`submit-with-egress.ts` names holding-forever as reintroducing *exactly the unbounded scan
cost Plan 13-07 was written to remove*.

| | keyed on | lifetime | cost |
|---|---|---|---|
| `EgressGuard` | **payload bytes** | job-scoped | scan — catches sovereign bytes anywhere in any frame |
| `SovereignCids` | **CID** | process + disk | lookup — answers "is this block sovereign" forever |

A `block` request names a CID, so the at-rest case never needed the scan. **They coexist.**
Anyone tempted to unify them should read this section first.

Registration sits at `submit.ts`'s blockstore-put — the boundary `submit-with-egress.ts`
itself nominated — which is what covers bare `submitJob` rather than only callers who
remembered.
