### 5. Durable Object siting is decided once, and two of the three knobs are not what they look like

Read from Cloudflare's data-location documentation on 2026-08-25, not assumed:

- **`locationHint` is not a guarantee.** The object goes to a datacenter chosen to minimise
  latency *from* the hint. **No claim may be made about where an object actually runs** — not
  in a report of the public run, not anywhere.
- **`jurisdiction` is binding, and takes only `eu`, `us`, `fedramp`.** So `bootstrap-eu`
  should be created in the `eu` jurisdiction rather than merely hinted at `weur` — the
  difference between "probably there" and "must be there" is load-bearing for a project whose
  pitch is data sovereignty. **South America has no jurisdiction at all** and can only ever
  be a hint (`sam`).
- **Location is fixed by an object's very first `get()`, and objects never move.** Exactly
  one call site may create these three; a stray `get()` from any other path sites the object
  permanently wherever that call came from, and the only repair is a new name.

### 6. Two cost constraints, both design-level rather than operational

Budget alerts now exist — shipped 2026-04-13, default-on since 2026-07-20 at **$10** — but
Cloudflare's own wording is *"informational only. It does not cap your usage."* **There is
still no hard ceiling.**

- **No preview deployments of the hosted tier, ever.** In the incident behind the widely-cited
  figure the multiplier was **60+ preview Worker deployments**, each with its own objects
  running the same bug — not the alarm itself.
- **The set of `idFromName()` names stays closed and short.** It creates an object for any
  name given, so a visitor-derived name lets a public cohort create unbounded objects, each
  with storage and an alarm. `bootstrap-us` / `bootstrap-eu` / `bootstrap-sam` is the whole
  namespace; it grows by adding names, never by widening the rule.

## Two things the research says are structural, not nice-to-have

- **Runaway Durable Object cost, and the qualifier matters.** The often-cited figure —
  $34,895 over 3–11 April 2026 — comes from **one self-report on Hacker News** (`thewillmoss`,
  31 points, 4 comments, no billing response from Cloudflare at time of writing). Read at the
  source: the bill was for **row reads at ~930 billion/day**, not for alarm invocations, and
  the cause was an unconditional `setAlarm()` **times 60+ preview deployments** — a CI hazard
  as much as an alarm one.
  **The part that is independently corroborated and matters more than the number: Cloudflare
  has no spending limits.** A second, unrelated report ($8,846, two looping objects) says the
  same. So: an interval floor, a billing alert before launch, and note from Cloudflare's own
  docs that `setAlarm` *overrides* rather than stacks, while a throwing `alarm()` handler
  retries **six** times with backoff.
- **The hosted tier becoming load-bearing is the median outcome**, with IPFS's own measured
  cloud reliance and Matrix's homeserver dominance as precedents. The prevention is two
  counters — P2P-carried bytes versus relay-carried bytes — and a scheduled relay-kill drill.

## What is measured and does not need re-measuring

`.planning/consults/2026-08-24-cloudflare-as-a-fabric-node-measured.md` — 20 sections, every
figure taken against a **deployed** worker rather than `wrangler dev`, which diverges on the
two questions that mattered most. Highlights a planner will need:

- A Durable Object is a **dialable libp2p peer** over WSS and a working **Circuit Relay v2
  server**; peer B reached peer A only through it and pinged in 54 ms.
- One object held **599 simultaneous connections**; the ceiling found was the test machine.
- **50 subrequests per invocation, cumulative** — but traffic on an already-open socket is
  free, so a warm pool is not bound by it.
- The relay enforces its data limit **bidirectionally**: **64 KiB each way, not 128**.
- Runtime WASM compilation is refused; `instantiateStreaming` does not exist there at all.
- `Date.now()` does not advance without I/O. Alarms fire 1 ms late and survive eviction.
- Two listener fields are required and silent when omitted: `direction: 'inbound'`, and a
  remote address from `CF-Connecting-IP` — without the second, libp2p rate-limits the whole
  internet as one host to five connections per second.
