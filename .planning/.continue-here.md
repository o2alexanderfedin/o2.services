## STILL OPEN — `tools/aot/lift.node.test.ts` (pre-existing, NOT caused by this branch)

**8 of 73 tests fail reproducibly** — in the full suite *and* in isolation (`Tests 8 failed | 65
passed`). This is NOT a flake, and the diagnosis is complete. An agent is fixing it; if that
work is lost, everything needed is here.

The file declares **zero** timeouts, and makes **48 real `docker` invocations via `execFileSync`**
(per `vitest.config.ts`, which clocks it at 217 s). Two distinct mechanisms:

1. **Six tests: an internal budget equal to the framework's budget.** Durations of 5006/5002/5003
   ms against the node project's 5000 ms default `testTimeout` — while lines 725, 769, 782, 792,
   888, 923 call `resolveImage(..., 5_000)`. **The driver's own timeout can never fire before
   vitest kills the test.** A race the test can only lose. These tests assert *classification*
   (`failure.kind === 'image-digest-foreign'`), not timing, so their budgets should be generous.
2. **Two tests: a budget smaller than a contended `spawn`.** `expected 'docker-unavailable' to be
   'timed-out'` at ~707 ms. Lines 818/852 pass `timeoutMs: 700`, line 870 passes `400`.
   `stubDocker` (:638) writes a `#!/bin/sh` to `tmpdir()` and the driver spawns it; under
   contention that spawn alone exceeds the whole 700 ms lift budget, so the driver never reaches
   the `run` it is meant to time out on. These two *are* about timing, so their budget must stay
   far below the stub's `exec sleep 30` while comfortably exceeding spawn latency.

**Proof it is not simple per-test load:** the single case `-t "does not mistake a registry port
for a tag"` **passes in 3.3 s at load average 37.88**, and fails when the whole file runs. The
file's own 48 spawns plus external load is what beats these budgets.

Docker itself is healthy — `docker info` returned in **0.078 s**.

**Before re-running the full suite: check `uptime` and `pgrep -f clang`.** A reading taken at
load 31 on 8 cores is not a reading. This cost two full-suite runs tonight (~11 min) and an hour
of the previous session.

# HARNESS LESSONS FROM THIS SESSION

- **A `pipeline()` stage returning `null` DROPS the item and skips its remaining stages.** A
  conditional "skip the design contest for uncontested items" silently killed 5 of 6 work items;
  only 5 of 21 agents ran. Never return `null` from a stage — return a sentinel object.
- **An agent can die on its structured output *after* doing the work.** B18's implementation was
  sitting in the tree with no report and no verification. **Always `git status` after a workflow
  and account for every changed file**, including from agents that errored.
- **Cost control worked.** Giving the full-suite duty to the orchestrator instead of to every
  agent, and running one design contest instead of six, brought this round in at roughly 40 min
  of agent time against 4h28m for the previous one.
